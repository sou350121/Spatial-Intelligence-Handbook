## Executive Summary

1. **本週最高 ΔI 信號是 SURE-Map (2609.15795) —— 自校正串流幾何基礎模型。** 它把「用跨視角幾何一致性不確定性驅動多時間尺度回饋校正」寫成一條新方法軸，宣稱純預測式 feed-forward 串流重建能**線上消除長時序尺度漂移**（previously GFMs 做不到）。這正面撞上 §13.3「feed-forward 沒有取代 real-time SLAM with IMU + loop closure」與 §13.1「GFM 會漂移」兩條立場。
2. **第二梯隊是一整片 world-model 定義收斂訊號**：IMPLY (2609.12441, AUROC 0.70 vs 1.00, 52%→73%)、Modality-Autoregressive WAM (2609.17524, 預測 RGB 無一致增益)、CLAP (2608.27406, 跨具身影片 WM)、Ego-Dynamics WM (2607.13410) 合起來正在把 §13.6「一個什麼都指、什麼都不指的詞」逼出**功能分層**——但這是定義漂移，不是技術裁決。
3. **feed-forward 陣營本週補了兩塊磚**：DRS-VPT (2609.12557) 把 image-to-scan 註冊、相機-LiDAR 標定、室內重定位統一進單一跨模態 pointmap；G3AR (2609.16603) 用圖引導分塊把 VGGT/Pi3/DA3 擴到千張影像尺度。前者動 §13.3/§13.5，後者直接回應 FastVGGT 的記憶體批評，但**分塊 ≠ 全局注意力**，§13.1 的 rank-1 collapse 指控未被擊倒。
4. **一條容易被忽略的硬信號：Compliance for Free (2609.19976)** 讓 VLA 除位姿外再輸出剛度/順應性，用四通道雙邊遙操作取得可辨識的 per-timestep 方向相關剛度標籤——這是「接觸力/阻抗監督」新軸，也是對 §13.5「pose-only = borderline foundation」的側翼包抄。

## Adversarial Triad: SURE-Map「自校正串流 GFM」——feed-forward 終於能線上修漂移，這是真突破還是又一場 hybrid 化妝？

**背景**：SURE-Map (2609.15795, cs.CV) 自稱開出一條新方法軸——串流幾何基礎模型的自校正。機制核心是：**不靠單視角深度信心，而用跨視角幾何一致性不確定性**驅動多時間尺度回饋校正，使「純預測式 feed-forward 串流重建」能**線上消除長時序尺度漂移**——論文明確標榜這是「先前 GFMs 做不到」的能力。它的 ontology tag 是 `paradigm: hybrid · time: filter-streaming · problem: VSLAM · representation: pointmap · sensor: mono`。它同時挑動兩條 §13 立場：§13.3 的「feed-forward 取代了 offline SfM/MVS，但**沒取代** real-time SLAM with IMU + loop closure」，以及 §13.1 的「GFM 會漂移、global attention 退化成 rank-1、二次記憶體爆掉」。

### 🔴 Bull（這是真信號）

1. **它自我標記為 hybrid，正是 §13.3 預言的 3R-SLAM Hybrid 兌現。** 本 ontology 立場（§5.4）說實際 deployment 走「feed-forward backbone + 傳統/學習式後端」，而 SURE-Map 就是把 feed-forward 串流重建接上一條**回饋校正環**。它沒有宣稱取代傳統後端，而是證明 **correction 訊號可以來自學習式的跨視角一致性**，不必是古典 backend——這是 hybrid 這條軸第一次有了「非古典」的校正來源。
2. **它直接攻擊 §13.1/§13.3 的「GFM 必漂移」共識。** §13.3 說 feed-forward 沒做到 online drift 消除；SURE-Map 說它用多時間尺度回饋做到了。若成立，則「feed-forward 只配 offline」這個二分被打破。
3. **校正訊號的選擇是原則性的、不是拍腦袋。** 單視角深度信心本身 miscalibrated——§13.4 已記錄 Depth Anything v2 在邊緣 hallucinate、把反射當幾何、薄結構崩。改用**跨視角幾何一致性**當不確定性來源，恰好繞開了單視角信心的已知病灶。這是 mechanism-level 的正確性論據，不是行銷詞。
4. **streaming + mono 的組合把成本壓到最低。** `time: filter-streaming` + `sensor: mono` 意味著不需要 IMU、不需要 per-scene 重優化——這正是 §13.3 所說「feed-forward 應吞下的那塊」。若它能以此配置完成串流 VSLAM，等於把 VIO/VINS 的地盤切掉一角。

### 🔵 Bear（過早慶祝 / 反共識）

1. **「hybrid」標籤是 self-claimed，未必對得起 §13.3 具體缺口。** §13.3 指名的未填缺口是「real-time SLAM with **IMU + loop closure**」。一個靠幾何一致性回饋的 mono 模型，**既無 IMU 也無 loop closure**——回饋校正 ≠ 迴環偵測 + 位姿圖全局優化。Wu 2025（§13.1）明說 transformer 方法「cannot fully replace traditional SfM and MVS」，SURE-Map 並未提供反例。
2. **日報未報告任何量化。** 沒有 ATE/RPE、沒有 FPS、沒有序列數、沒有跟 ORB-SLAM 家族（日報中 HuMemSLAM 接 ORB-SLAM3、LapaTrack 用 ORB-SLAM2）的 head-to-head。「eliminates long-horizon scale drift」是 claim，不是 measured result。對照本週另一篇同軸工程文（2609.13675 對 FAST-LIO2/LIO-SAM 做 12 序列配對統計消融），SURE-Map 的證據強度明顯不足。
3. **mono、無慣性 = 公制尺度在原理上不可觀。** 本週 2603.26740 專門推導了「單目 VIO 尺度的可觀測性需要運動激勵」，DefVINS (2601.00702) 全篇靠 IMU 錨定把不可觀模態變可辨識——**共識是：沒有 IMU 錨，尺度漂移就是結構性問題**。SURE-Map 若真靠純幾何一致性消除尺度漂移，等於繞過可觀測性定理，須給出不平凡的證明或外部尺度來源，日報均未報告。
4. **GFM 的既有崩壞模式未被回應。** arXiv 2512.21691 的「global self-attention 隨長度退化成 rank-1」、FastVGGT 的二次記憶體、518 px 上限——SURE-Map 摘要完全未觸及輸入解析度與記憶體隨串流長度的伸縮。若它內部其實是分塊處理（如 G3AR），那 rank-1 collapse 依然存在於塊內，只是被回饋環蓋住。
5. **單實驗室原型 vs 部署現實。** §13.1 的 ontology 立場是「deployment 走 3R-SLAM Hybrid」，SURE-Map 是又一個 lab prototype；沒有真機、沒有感測器速率級即時性（§13.10 定義 ≥30 FPS at sensor rate including tracking+mapping）的證據，就無法升級為「feed-forward 接管 VSLAM」的證據。

### 🟢 Arbiter（裁決）

**1. 爭議立場更新**
- **§13.3（feed-forward 取代 per-scene）**：**維持，微調**。SURE-Map 沒有推翻「feed-forward 未取代含 IMU + loop closure 的 real-time SLAM」，因為它本質是**把 hybrid 內部的 correction 來源從古典後端換成學習式幾何一致性**。方向對 hybrid 有利，但不足以重寫「real-time SLAM 仍屬 VIO/VINS」這句。幅度：**微調（往 hybrid 靠攏半步）**。
- **§13.1（VGGT 是 paradigm shift）**：**維持**。SURE-Map 不主張取代 SfM/MVS，也不回應 rank-1/記憶體/解析度批評，只是新增一個「GFM 可被回饋包裝」的案例，與「重要範式信號、但不是 shift」一致。

**2. 軸移動**
- **paradigm 軸**：feed-forward → hybrid 的位移本週**持續**（SURE-Map、DRS-VPT、G3AR 都在 feed-forward backbone 外掛校正/分塊/對齊層）。但這週 paradigm 軸的**主要質量仍落在 world-model-as-policy 與 VLA**（見五軸熱度）。
- **time 軸**：streaming / filter-streaming 明顯升溫（SURE-Map、Anchor3R、4DStreamCtrl、Zing-0.5）。

**3. 關鍵代理指標 + kill condition**（以下門檻為**本分析自設判準**，非已知事實）
- **確認條件**（全部要滿足才把 §13.3 往「重寫」方向推）：(a) 在需迴環的長軌跡上公開 ATE/RPE，且**與 ORB-SLAM 家族在相同感測器速率下 head-to-head**；(b) 達到 **≥30 FPS at sensor rate 且含 mapping**（§13.10 定義）；(c) **不接 IMU** 情況下尺度漂移在 **>1 km / >10k frames** 內保持有界。三者缺一，即為 hybrid 化妝。
- **推翻條件（kill）**：若後續在**無 IMU、無外部尺度先驗**下，漂移在數千幀內復現，或需人工/標靶尺度輔助 → §13.3 原立場不動，SURE-Map 降級為「工程包裝」。

**4. 用戶行動建議**
- **現在該關注**：校正訊號是否**公制**——沒有 IMU 的尺度從哪來？這是全篇的命門，比「自校正」四個字重要得多。
- **該謹慎**：不要把「self-correcting GFM」當 SLAM 取代品宣傳；先看它與 ORB-SLAM 家族的 **head-to-head**，再看**真機**而非序列重放。
- **該追蹤**：若 SURE-Map 團隊下一步加入 IMU 融合或 loop closure 模組，那就回到 §13.3 的原始命題，屆時才是真測試點。
