## Executive Summary

1. **本週最高 ΔI 是 AnyVIO（2611.26625）**——它不是在 VIO 上加模組，而是把 §13.3 明文保留的「real-time SLAM with IMU 仍 VIO/VINS 主場」這個 carve-out 裡的**後端本身**（filter / factor-graph）換成單次前向融合頭（GFM+IFM 可靠性加權），並宣稱恆定時間、免調參、免軌跡增長、跨九個平台＋140 km/h 實車。**核心判斷：feed-forward 這週第一次侵入「IMU odometry」這塊領土；但它侵入的是 odometry，不是 loop closure / global consistency——§13.3 的邊界下移一層，不是崩塌。**

2. **world-model-as-policy 是本週最大群，但多數是範式內的工程化（低 ΔI）**：LaST / JEPA Dots / WEVO / MAWAM / Fast-JEPA / Verify2Act / PhysVAM 等清一色「既有 WAM 範式＋新場景或效率改良」。真帶新軸的只有兩條：**How Uncertain（2611.23620，反向執行凍結世界模型偵測位移）** 與 **2611.18562（reasoning-model-as-robot-agent，純模擬 RL 免示範 zero-shot 跨具身）**。

3. **表徵側冒出兩條真信號，都在把「接觸/觸覺」從輸入模態升為監督軸**：Ego2X（2611.24138，contact-as-first-class，X-VLA 40.5%→67.0%、接觸實現率 62.9% vs 27.9%）與 TacInno（2611.26405，tactile innovation 殘差監督、部署零額外模組）。兩者對 §13.4 的模態 caveat 是**補充而非推翻**。

4. **VGGT 工程集群（EcoVGGT / Deep BA / 多視角加速）本週齊發，但方向是「把 VGGT 做得更實用」= 確認 ontology「不是 shift、需 hybrid 工程」的立場，屬低 ΔI 記錄級。** 不因其數量多就升 ⚡。

## Adversarial Triad: AnyVIO——feed-forward 第一次把手伸進「IMU 後端」這塊領土

**背景**：AnyVIO（2611.26625，eess.IV）宣稱**首次**把 VIO 後端從濾波器／因子圖換成「GFM+IFM 可靠性加權的單次前向融合頭」，得到恆定時間、免調參、免軌跡增長的純 feed-forward VIO，並在**九個跨平台數據集**與 **140 km/h 實車**上驗證泛化。它精準挑戰 §13.3 那句「沒取代 real-time SLAM with IMU + loop closure（仍 VIO/VINS 主場）」，以及 ontology「實際 deployment 走 3R-SLAM Hybrid（feed-forward backbone + 傳統後端）」的核心立場。注意：**日報未報告任何 ATE/RPE 數字、FPS、或 loop-closure 消融**——所有「多好」的判斷都缺一手數據。

**🔴 Bull（這是真信號）**
1. **它打的是 §13.3 親自畫下的那條線**。ontology 說 feed-forward 取代了 offline SfM/MVS，但**沒取代 IMU 後端**。AnyVIO 把「後端」這個最古典、最被 ontology 保留的元件本身換掉——這不是擦邊，是正中靶心。
2. **恆定時間／免軌跡增長是漸進性質，不是增量改良**。古典 filter/factor-graph 後端的成本隨狀態與軌跡增長；AnyVIO 若真做到 bounded，是把 time 軸從 incremental/filter-streaming 推到 true feed-forward 的**不同漸近區間**。
3. **「免調參」直擊 VIO/VINS 的第一號實務痛點**。per-platform 噪聲/內參調校正是 §13.3 說 feed-forward 沒取代掉的「per-scene 成本」——它是用資料換掉人工調校。
4. **eess.IV 場地＋九個跨平台數據集＋實車**，暗示不是單一 benchmark 挑選，泛化敘事有工程底氣。

**🔵 Bear（過早慶祝 / 反共識）**
1. **VIO ≠ SLAM，這是最大破口**。§13.3 的 carve-out 原文是「real-time **SLAM** with IMU + **loop closure**」。AnyVIO 是 **odometry**——「免軌跡增長」是說狀態有界，**不是 loop closure、不是全域地圖一致性**。一個 feed-forward odometry 仍需要 pose-graph/map 層做全域一致，那正是 ontology 守的 hybrid 部分。它移動的是**子邊界**，不是邊界。
2. **GFM 若是 transformer 幾何模型，§13.1 的反對證據直接適用**：arXiv 2512.21691 顯示 VGGT 級全域 self-attention 在長序列下**塌成 rank-1**；FastVGGT(arXiv 2509.02560) 顯示**二次記憶體**在數百幀後爆掉。所謂「IFM 可靠性加權」很可能就是在 GFM 崩壞時把權重讓給慣性——**等於在困難段退化回 dead-reckoning**，而非真正 feed-forward。
3. **「first」在 VIO 是循環宣稱**；且 140 km/h 是 demo 條件不是 benchmark 結果——**日報未報告 ATE、FPS、失敗案例**。§13.10 定義的 real-time（≥30 FPS at sensor rate 含 tracking+mapping）完全未驗。
4. **「跨九個數據集」≠ 跨硬體退化**。照 §13.1 Wu 2025：VGGT 被 518px 輸入封頂、建築周邊有洞、高樓俯視失敗。跨資料集泛化不覆蓋**退化運動**（純旋轉、動態遮擋、低紋理），日報也未報告這類消融。

**🟢 Arbiter（裁決）**
1. **爭議立場更新：移動 §13.3，方向 = 「local odometry 可由 feed-forward 取代」，幅度 = 微調（boundary 下移一層），非重寫。** §13.3 措辭需改：「VIO/VINS 主場」改為「**global-consistent SLAM（loop closure + pose-graph）仍古典；local VIO odometry 已被 feed-forward 侵入**」。§13.1（VGGT 是信號非 shift）**不動**——AnyVIO 反而靠工程化在特定層落地，正好符合「是實作信號不是範式躍遷」的立場。
2. **軸移動**：time 軸本週朝 **feed-forward（恆定時間）** 再推一格；problem 的 VIO 節點從 geometric/filter-streaming 往 learned/feed-forward 移。整體 paradigm **維持「hybrid 為實際 deployment」**，但 hybrid 的組成從「backbone + 古典後端」變成「**feed-forward odometry + 薄 global 一致性層**」。
3. **關鍵代理指標 + kill condition**（閾值是我設的判準）：(a) **大尺度含 loop 序列的室外/城市 benchmark 上 head-to-head 對古典 VIO/VINS 一脈 SOTA**，≥10 條含 loop 序列、ATE 不劣於古典 SOTA 5% 內；(b) **真機而非僅數據集回放**；(c) 報告 FPS 且達 §13.10 定義（≥30 FPS at sensor rate）；(d) 退化運動（純旋轉/動態遮擋）不崩。**任一不滿足 → 降級為「local odometry 改良」，§13.3 整體不推翻。**
4. **用戶行動建議**：(a) 若在做 VIO 產品，開始把「feed-forward odometry + 薄 pose-graph」當一等公民評估，別再預設 filter/factor-graph；(b) 但**別拆掉 global layer**——loop closure 與地圖一致性仍是不可讓渡的 hybrid 核心；(c) 盯 AnyVIO 的 ATE 表與 loop-closure 消融，那是它從「odometry」升級為「SLAM 級宣稱」的分水嶺。
