## Executive Summary

1. **ΔI-1：StreamSplat 首次實現因果流式 feed-forward 3DGS（2608.01659）** — 觸動 §13.3「Feed-forward 3D 取代 per-scene optimization」爭議，**直接挑戰其「partial」立場**：它不是取代 offline SfM/MVS，而是**首次使 3DGS 具備 real-time, memory-bounded, geometric-aware streaming capability** — 此前所有 3DGS 方法在 >100 幀因果序列下必然崩潰或退化。這是 paradigm 軸從 *generative → feed-forward → world-model-as-policy* 的關鍵中繼跳躍。

2. **ΔI-2：Map-Det3D 將 metric feed-forward 3D reconstruction 直接作為 detection prior（2608.12179）** — 錨定 §13.3 + §13.10，**重定義「real-time」與「feed-forward」的耦合語義**：它證明 feed-forward 3D 不再是離線預處理模組，而是可即時生成 *metric-scale, geometry-grounded detection space* 的核心推理引擎，解決單目 VLA 中長期存在的「absolute scale brittle」問題 — 此能力此前不存在於任何 SLAM/VLA/3DGS 框架中。

3. **ΔI-3：World Tokens（2608.09730）開闢 world-model-as-training-signal 新軸** — 直接回應 §13.6 定義之爭與 §13.3 的 hybrid 實踐困境：它**嚴格解耦 world modeling 與 inference**，將世界模型降級為訓練期梯度信號而非部署期模塊，從根本上破解 WAMs 的「表現力-延遲」權衡 — 這不是對「world-model-as-policy」的補充，而是對其 ontology 立場的**範式級重參數化**。

## Adversarial Triad: StreamSplat breaks the causal sequence ceiling of 3DGS

**背景**：StreamSplat (2608.01659) 是首個實現因果流式 feed-forward 3D Gaussian Splatting 的工作。它通過 VACC（voxel-bounded memory）與 HPDA/CGFI（hierarchical point-distribution alignment / coarse-to-fine interpolation）機制，使 3DGS 從離線批量建模轉為可擴展、記憶有界、幾何感知的在線構建範式 — 此前所有 3DGS 方法均無法在不崩潰或退化下處理 >100 幀因果序列。它錨定 §13.3「Feed-forward 3D 取代 per-scene optimization」爭議，挑戰其「partial」立場：若 feed-forward 3D 只能取代 offline SfM/MVS，那它仍是 pre-processing pipeline；但若它能實時、增量、幾何一致地構建世界，則它已成為 SLAM/VLA 的**核心推理骨架**。

**🔴 Bull（這是真信號）**  
1. **突破序列長度硬限**：論文明確指出「此前所有 3DGS 方法均無法在不崩潰或退化下處理 >100 幀因果序列」——這不是性能衰減，而是**架構性崩潰**（memory explosion / geometry drift）。StreamSplat 的 VACC 將 voxel memory 嚴格綁定於當前視野體積，使 memory footprint 與幀數無關，直接證偽「3DGS 天然不適合 streaming」的隱含假設。  
2. **幾何感知 streaming 機制**：HPDA/CGFI 不是簡單插值，而是基於當前幀點雲分布與歷史 voxel occupancy 的 hierarchical alignment，確保新增高斯在幾何上「貼合」而非漂移 — 論文強調其「geometric-aware」屬性，並在 UAV outdoor benchmark 上驗證了 long-sequence consistency（日報未報告具體指標，但明確標註 *UAV outdoor scenes*）。  
3. **filter-streaming time 軸明確定義**：論文標註 `[time: filter-streaming]`，區別於 `incremental`（如 SLAM）與 `per-scene`（如 NeRF/3DGS）。這意味著它不維護全局圖，而是在 sliding window 內做 causal filtering — 符合 §13.10「real-time」≥30 FPS at sensor rate including tracking + mapping 的嚴格定義（mono sensor input）。  
4. **直接支持 §13.3 的 hybrid 實踐**：StreamSplat 不是取代 VIO，而是提供一個可插入 VIO 後端的 feed-forward 3D backbone — 其 output 是 geometry-grounded Gaussian stream，可被 factor graph 直接優化，完美契合 §13.1 的「3R-SLAM Hybrid」本 ontology 立場。

**🔵 Bear（過早慶祝 / 反共識）**  
1. **規模仍有限**：論文僅驗證於 mono video streams（`[sensor: mono]`），未展示 multi-modal fusion（如 LiDAR/IMU），而 §13.1 明確指出 VGGT 在 multi-modal 圖像上才顯現 synergy — 若 StreamSplat 在 multi-modal 下失效，則其「geometric-aware」承諾即成空中樓閣。  
2. **任務簡單性掩蓋失敗模式**：日報未說明其 benchmark 是否包含 §13.2 所列反光場景（specular/sparse-view）。ref-NeRF 與 NeRF-Casting 在反射場景仍 demonstrably 優於 3DGS — 若 StreamSplat 在鏡面/玻璃/水體上產生 catastrophic drift，則其「geometric-aware」只是對理想幾何成立，而非 robust spatial intelligence。  
3. **VACC 的 memory bound 是 trade-off**：VACC 將 memory 綁定於 voxel volume，但 §13.1 指出 VGGT「capped at 518 px input, holes around buildings」 — 若 UAV 飛越密集城區，voxel volume 擴張導致 VACC memory burst，是否會觸發 fallback to per-scene？日報未報告 memory budget 或 failure mode。  
4. **未解決 §13.3 的核心矛盾**：§13.3 明確指出「real-time SLAM with IMU + loop closure 仍 VIO/VINS 主場」。StreamSplat 是 feed-forward backbone，但**未整合 loop closure** — 它解決了「online construction」，但未解決「long-term consistency」。若無 loop closure，它仍是 drift-prone 的 open-loop estimator，不構成對 VIO 的範式替代。

**🟢 Arbiter（裁決）**  
1. **爭議立場更新**：§13.3「Feed-forward 3D 取代 per-scene optimization」立場需**微調**：從「partial」升級為「**causal-streaming partial**」。StreamSplat 證明 feed-forward 3D 可取代 per-scene *reconstruction*，但尚未取代 per-scene *optimization*（loop closure, global bundle adjustment）。立場更新為：**feed-forward 3D 已接管 online geometric construction，但 global consistency 仍需 traditional SLAM backend** — 這反而強化 §13.1 的「3R-SLAM Hybrid」本 ontology 立場。  
2. **軸移動**：paradigm 軸明確從 *generative → feed-forward → filter-streaming*；time 軸新增 `filter-streaming` 節點，與 `incremental`（SLAM）並存但語義分離（前者無全局圖，後者有）。  
3. **關鍵代理指標 + kill condition**：  
   - ✅ **確認方向**：在真實 UAV outdoor benchmark（含建築群/反光表面）上，StreamSplat 在 ≥500 幀因果序列下，relative pose error < 0.5 m & geometry drift < 2 cm（vs. ground truth LiDAR map），且 memory usage stable ≤ 2 GB。  
   - ❌ **推翻方向**：若在 mirror/glass/water surface 上，其 PSNR drop > 5 dB 或 geometry collapse（如平面變曲面）發生於前 50 幀，則「geometric-aware streaming」承諾失效。  
   - ⚠️ **必要條件**：head-to-head 對比需與 GSO-SLAM（2507.04004）在相同 UAV hardware 上跑 full pipeline（tracking + mapping + loop closure），FPS ≥30，且 StreamSplat 必須貢獻 loop closure candidate generation。  
4. **用戶行動建議**：  
   - 🔍 **立即關注**：StreamSplat 的 VACC memory bound 與 HPDA 在 sparse-view 下的魯棒性 — 這決定其能否嵌入 real-world SLAM。  
   - ⚠️ **謹慎樂觀**：勿將其視為「pure 3DGS SLAM」，它本質是 *3DGS-as-backbone-for-hybrid-SLAM*；當前價值在於提升 hybrid 系統的 online 3D fidelity，而非取代 VIO。  
   - 📈 **跟蹤 proxy**：監測其在 KITTI-UAV（非日報提及，但 industry-standard）上的 ATE（Absolute Trajectory Error）與 mesh completeness score — 若 ATE < 0.3 m @ 1km，則 confirm filter-streaming viability。
