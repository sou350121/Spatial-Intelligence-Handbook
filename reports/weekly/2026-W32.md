## Executive Summary

1. **ΔI 最高信號：`StreamSplat`（2608.01659）** — 觸動 **§13.3「Feed-forward 3D 取代 per-scene optimization」— PARTIAL**，並推動 paradigm 軸從 *feed-forward* 向 **causal streaming** 遷移。核心判斷：**3DGS 的範式主導地位已從「批量建模工具」升級為「可擴展空間操作系統」，其時間語義正從靜態（per-scene）轉為動態（filter-streaming），標誌著 feed-forward 3D 從 offline utility 正式邁入 online embodiment infrastructure。**

2. **ΔI 次高信號：`LiLa-WAM`（2608.03701）** — 直擊 **§13.6「World Model」定義之爭**，以「Visual Transition Token (VTT)」為錨，將模糊的「world model」從多義術語壓縮為可微分、可組合、幾何原生的 *task representation space*，實質重定義了 world-model-as-policy 的接口層——**不再問『它預測什麼？』，而問『它如何被幾何化地指令？』**

3. **ΔI 結構性信號：`CorrelationFlow`（2607.29237）** — 對抗 **§13.7「5 軸是 canonical」— UNVERIFIED**，以純 geometric、training-free、BEV-based LiDAR scene flow 方法，在 sparse/distant/fast 圖像失效區實現魯棒性碾壓，證明「paradigm」軸可獨立於「representation」或「sensor」軸存在，且 geometric 范式在特定 problem（scene flow）上仍具不可替代性與本體論優先性。

4. **ΔI 隱性轉折點：`DeepThinkVLA`（2511.15669）** — 挑戰 **§13.5「FoundationPose 是 foundation model」— disputed** 的延伸假設（即 VLA 中 CoT 是 epiphenomenal），首次給出 CoT 在 VLA 中生效的兩個可驗證必要條件（解碼對齊 + 因果對齊），將「推理」從 heuristic 插件升級為可失效歸因、可優化的 causal module，**為 VLA 奠定真正的 foundation-level reasoning ontology。**

## Adversarial Triad: [StreamSplat breaks the per-scene bottleneck — 3DGS becomes a streaming spatial OS]

**背景**：`StreamSplat`（2608.01659）首次實現因果流式 feed-forward 3DGS，透過 VACC（voxel-bounded causal memory）與 HPDA/CGFI 機制，使 3DGS 從離線批量建模轉為可擴展、記憶有界、幾何感知的在線構建範式；日報明確指出「此前所有 3DGS 方法均無法在不崩潰或退化下處理 >100 幀因果序列」。此工作直接錨定 §13.3 爭議：「Feed-forward 3D 取代 per-scene optimization」是否僅為 partial？本體論立場認為 feed-forward 已取代 offline SfM/MVS/few-view，但 real-time SLAM with IMU+loop closure 仍屬 VIO/VINS 主場。`StreamSplat` 挑戰此劃界——它不是 SLAM，卻比 SLAM 更適合 embodiment 的 continuous spatial construction。

**🔴 Bull（這是真信號）**  
1. **VACC 實現 memory-bounded causality**：日報明確寫「VACC（voxel-bounded causal memory）」，證明其記憶機制非 sliding window 或 full history，而是 voxel-grid 約束下的幾何局部性因果建模，符合 embodiment 的物理約束。  
2. **HPDA/CGFI 解決 incremental drift**：日報指出「HPDA/CGFI 兩項機制」使 3DGS 具備「無界場景增量建模能力」，直接回應 §13.3 中「real-time SLAM with IMU + loop closure 仍 VIO/VINS 主場」的反對理由——它不依賴 IMU，卻解決了 drift 根源。  
3. **>100 幀序列穩定性為硬門檻**：日報強調「此前所有 3DGS 方法均無法在不崩潰或退化下處理 >100 幀因果序列」，此為可驗證的規模躍遷，超越 `Stipple`（2608.00931）等 hybrid VIO+3DGS 的 incremental 改良。  
4. **time 軸明確跳躍至 `filter-streaming`**：日報標註 `[time: filter-streaming]`，而非 `incremental` 或 `per-scene`，這與 §10.2「≥30 FPS at sensor rate including tracking + mapping」的 real-time 定義一致，標誌其已跨入 embodiment runtime 時間尺度。

**🔵 Bear（過早慶祝 / 反共識）**  
1. **未解決 loop closure 或 global consistency**：§13.3 反對方核心論據是「real-time SLAM with IMU + loop closure 仍 VIO/VINS 主場」；`StreamSplat` 未提 loop closure、未驗證 long-term global map consistency（如 KITTI 10km 序列），僅是「無界場景」≠「全局一致」。  
2. **VACC 仍是 voxel-grid，非 truly unbounded**：日報寫「voxel-bounded」，即 memory 仍受 voxel resolution 與 grid size 限制；對比 `SLAMFormer-∞`（2608.03429）的「unbounded SLAM transformer」與 memory-conditioned 動態坐標系，`StreamSplat` 的「unbounded」屬工程修辭，非本體論突破。  
3. **缺乏 real-robot deployment 驗證**：所有 ⚡ 論文均未報告 real-robot 測試（日報未提），而 §13.3 立場基於「3R-SLAM Hybrid」實際 deployment 經驗；`StreamSplat` 若僅在 synthetic 或 short real-world video 上驗證，則不構成 paradigm 移動。  
4. **未觸及 specular/reflection 場景**：§13.2 明確指出「3DGS 反光場景例外」；日報未說明 `StreamSplat` 在 mirror/glass/water 等反光物體上的表現，若其流式建模加劇反光失真（如 `StructureGS`（2607.26889）需專門結構損失），則其「接管多數 NVS/SLAM use cases」的 claim 仍受 §13.2 限制。

**🟢 Arbiter（裁決）**  
1. **爭議立場更新**：**§13.3 立場需微調**。原「PARTIAL」立場正確，但 `StreamSplat` 證明 feed-forward 3D 的適用範圍已從「offline reconstruction」擴展至「online spatial construction」，其範疇應從 *reconstruction* 升級為 *spatial infrastructure*。立場更新為：「Feed-forward 3D 取代 per-scene optimization — now extends to online embodiment infrastructure, but still excludes global-consistency-critical SLAM and specular scenes.」  
2. **軸移動**：**paradigm 軸從 `feed-forward` 移至 `causal streaming`**；`time` 軸同步從 `per-scene` → `filter-streaming`；`problem` 軸從 `reconstruction` → `spatial infrastructure`。  
3. **關鍵代理指標 + kill condition**：  
   - ✅ **代理指標**：在真實長時序（>500 幀）、動態場景（moving camera + moving objects）、含反光物體（mirror/glass）的 benchmark 上，`StreamSplat` 的 PSNR/SSIM/CD（Chamfer Distance）衰減率 ≤ 0.1%/100 幀，且 latency 波動 < ±5%（vs. sensor rate）。  
   - ❌ **kill condition**：若在真實 UAV flight sequence（>10km, 30 FPS）中，其重建 map 出現不可逆 drift（relative pose error > 2m after 1km），或在 mirror scene 中 PSNR 下降 >5 dB vs. ref-NeRF，則 `causal streaming` 範式尚未成熟，仍屬 engineering increment。  
4. **用戶行動建議**：  
   - 🔍 **立即關注**：`StreamSplat` 的 VACC 記憶機制與 HPDA/CGFI 的開源實現，評估其在 your robot’s sensor rate（e.g., 10–60 FPS）下的 memory footprint 與 latency profile。  
   - ⚠️ **謹慎採用**：勿假設其可直接替代 VIO；應視其為「前端 spatial builder」，後端仍需傳統 SLAM 或 world model 進行 loop closure / global optimization。  
   - 🧩 **戰略佈局**：將 `StreamSplat` 與 `Track4Action`（2608.03727）耦合——用 world-centric 3D tracker 提供 privileged supervision，訓練 VLA policy 對 `StreamSplat` 流式 output 的 action grounding。
