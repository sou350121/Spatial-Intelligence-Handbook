# 把纳米无人机的 DNN 部署自动化：从手工调到端到端编译（Improving Autonomous Nano-drones Performance via Automated End-to-End Optimization and Deployment of DNNs）

> **发布时间**：2026-07-14（arXiv:2607.12593v1 [eess.IV]）
> **论文 / 模型名**：PULP-Dronet **V2**（NN 拓扑两条：`PULP-DronetV2 GAP flow` / `PULP-DronetV2 NEMO/DORY`）
> **核心定位**：不是新网络，而是**部署方法论论文**——把「训练 → 量化 → 硬件感知 tiling → 片上执行 → 飞控闭环」整条链路从手工迭代变成工具链自动化；在 Crazyflie 2.1 + GAP8 上以 8-bit 达成 **2× 内存缩减、1.6× 推理加速、精度不变**，闭环自由飞行平均速度从 baseline 的 0.5 m/s 提到 1.96 m/s。

10 cm 级纳米无人机的算力预算只有整机几瓦中的 5–15%，跑 SLAM 完全不现实，所以路线是「轻量 CNN 直接从单目灰度图回归控制量」。但把多 MMAC 的 CNN 塞进 MCU 级 SoC 需要误差大、靠人肉反复试的调优——本文的答案是：用两套自动化 flow（厂商的 GAP flow vs 开源的 NEMO/DORY）接管这一切，并证明**飞行性能的真正跃升来自控制律改造，不是来自网络本身**。

---

## X-Ray 开场

**问题**：在只有 512 kB L2 + 64 kB L1 的 GAP8 上部署 CNN，必须同时满足内存、功耗、无 FPU、吞吐四个约束，传统做法是手工改拓扑 + 手工调 tiling，一轮一轮试。
**做法**：把流程拆成两级自动化——① 8-bit 后训练量化（PTQ，**不重训、不需要训练集**），② 由 AutoTiler / DORY 自动求解 L2↔L1 的 tile 划分与 DMA 双缓冲；再在飞控侧加一个积分项 + 二次速度映射的轻量控制律。
**对 spatial AI 研究者的意义**：这是一份「端侧 DNN 落地 cost model」的实证样本——**量化位宽减半只换来 1.5–1.6× 加速而非 2×**（非 MAC 操作 + 负载不均），而 **8-bit 的精度代价是拓扑相关的**（NEMO 必须把 ResBlock 的 ReLU 推到 residual branch 才可量化）。这类「自动化不等于无代价」的细节，是判断任何 edge-deployment 论文可信度的关键。

## 1 · 核心架构 / 方法总览

### 1.1 系统组件对比表

### 1.2 关键机制

网络侧的唯一结构改动来自**量化器约束**，而不是精度考量：

```
V1（原始）:      ResBlock = Conv → BN → ReLU → (+residual) → ReLU
V2 NEMO/DORY:   ResBlock = Conv → BN → ReLU → (+residual) → ReLU 被推到 residual branch
                ← 因为 NEMO 基线"不支持量化非 ReLU 输出的数据"
V2 GAP flow:    ResBlock 拓扑基本同 V1（NNTOOL 能 fold BN）
```

**⚡ Eureka Moment 1（部署侧）**：**16-bit QAT → 8-bit PTQ** 这一步之所以成立，不是因为精度更鲁棒，而是因为 **PTQ 不需要训练集、不需要重训**——只需一次轻量校准。这让「换一个 SoC / 换一套 flow」的边际成本从「重跑训练」降到「跑一遍校准」。代价是精度对拓扑敏感（见 §8）。

**⚡ Eureka Moment 2（闭环侧，最容易被误读的一点）**：**飞行性能的 4× 提升不是网络变强了，是控制律变强了**。原文明确写：V1 用 `p_col → 速度` 的**线性**映射，本文改成**二次**映射 `v ∝ (1 − p_col)²`，并在 `p_col` 上加了一个**积分项**对抗 CNN 输出的高频抖动（原文观察：面对某些正面障碍时 `p_col` 在 >0.8 与 &lt;0.3 之间来回振荡）。二次项让「接近障碍时减速更狠」，从而留出转向时间——这才是 1.96 m/s vs 0.5 m/s 的来源。

## 2 · 数学核心

📌 **Napkin Formula**

```
v_set(k) = α₁·[ v_target·(1 − (p_col + w·clip₍₀,₃₎(I(k))))² ] + (1−α₁)·v_set(k−1)
I(k)     = clip₍₀,₃₎( I(k−1) + (p_col − 0.3) )              w = 0.2, α₁ = 0.6, α₂ = 0.7
```

一句话直觉：**把「碰撞概率」当成一个带迟滞的软开关——越靠近障碍，速度按平方掉；而积分项负责把 CNN 的单帧抖动"攒"成一个稳定的避障信念。**

### 2.1 量化（部署侧）

**目标**：把 float32 张量映射到 N-bit 纯整数，使 GAP8 能用 packed-SIMD 做 8×8-bit MAC。

**公式**（原文 Eq.1，uniform affine quantization）：

```
t = α_t + ε_t · t̂ ,      ε_t = (β_t − α_t) / (2^N − 1)
```

| 变量 | 含义 |
|---|---|
| `t` | 浮点张量（输入 `x` / 输出 `y` / 权重 `w`） |
| `[α_t, β_t)` | 该张量的已知取值范围 |
| `t̂` | N-bit 整数表示 |
| `ε_t` | scaling factor（把浮点域缩到整数域） |

**直觉**：量化不是"丢精度"，是"重标定坐标轴"。关键工程细节：Conv 输出用 **32-bit 累加**，但**从不物化整个 32-bit 张量**——每个元素产生后立刻被 ReLU（或 BN+ReLU）压回 8-bit。这就是为什么 `64 kB` 的 L1 还活得下去。

### 2.2 控制律（闭环侧）

| 步骤 | 公式 | 作用 |
|---|---|---|
| 反量化 | `p_col ← data[0]·c_scale0`, `ω_steer ← data[1]·c_scale1` | 8-bit → 物理量；常数**硬编码在飞控固件** |
| 积分 | `I(k) ← clip[0,3)( I(k−1) + (p_col − 0.3) )` | 迟滞：`p_col>0.3` 累积"确有障碍"，`<0.3` 缓慢释放 |
| 修正 | `p_col ← p_col + w·I(k)`，`w = 0.2` | 抑制单帧漏检 |
| 速度映射 | `v_unfilt ← v_target·(1 − p_col)²` | **二次**惩罚，接近障碍时减速远快于线性 |
| 低通 | `v_set ← α₁v_unfilt + (1−α₁)v_set(k−1)`，`α₁=0.6` | 去高频噪声，但引入相位滞后 |
| 转向低通 | `ω_set ← α₂ω_steer + (1−α₂)ω_set(k−1)`，`α₂=0.7` | 原文：更低的值 → 延迟增大 + 路径低频振荡 |

## 3 · 带数字走一遍（玩具设定）

**设定**（数值取自论文常数，帧序列为我构造的示意）：`v_target = 1.5 m/s`，`w = 0.2`，`α₁ = 0.6`，阈值 `0.3`，初始 `v_set(0) = 1.5`。模拟原文描述的「`p_col` 在 >0.8 与 &lt;0.3 之间振荡」：帧序列 `0.85, 0.20, 0.85, 0.20`。

| k | `p_col` | `I(k)` | `p_col' = p_col + 0.2I` | `(1−p_col')²` | `v_unfilt` | `v_set` |
|---|---|---|---|---|---|---|
| 1 | 0.85 | 0.55 | 0.96 | 0.0016 | 0.0024 | **0.601** |
| 2 | 0.20 | 0.45 | 0.29 | 0.504 | 0.756 | **0.695** |
| 3 | 0.85 | 1.00 | 1.05 | 0.0025 | 0.0038 | **0.280** |
| 4 | 0.20 | 0.90 | 0.38 | 0.384 | 0.577 | **0.458** |

**对照组（无积分项，`w = 0`）**：

| k | `p_col'` | `v_unfilt` | `v_set` |
|---|---|---|---|
| 1 | 0.85 | 0.034 | 0.620 |
| 2 | 0.20 | 0.960 | 0.816 |
| 3 | 0.85 | 0.034 | 0.347 |
| 4 | 0.20 | 0.960 | 0.620 |

**读出来的三件事**：

1. **积分是不对称的**：`p_col=0.85` 时每帧 `+0.55`，`p_col=0.20` 时每帧 `−0.10`——**建立"有障碍"的速度是释放的 5.5 倍**。这就是迟滞的本质，也正是「一次闪避后不会立刻加速冲回去」的保证。上限 3 是为了防 windup（负置信度无意义则下界 0）。
2. **`v_set` 追不上 `v_unfilt`**：k=1 时 `v_unfilt` 已掉到 0.0024，但 `v_set` 还有 0.601——这是 `α₁=0.6` 的一阶 IIR 带来的**刹停滞后**，约 2–3 帧才收敛。所以**帧率直接等于安全裕度**：8.7 fps（115 ms/帧）vs 12.8 fps（78 ms/帧），同样的控制律在快配置下少等约 37 ms。
3. **无积分项时速度在 0.35↔0.62 之间来回摆**，系统会"利用"网络的不确定性飞得更快但更抖——这解释了为什么 baseline V1（线性映射 + 无积分）在同一 110 m 走廊上只能跑 **0.5 m/s**。

> 该节数字为**玩具推演**（帧序列与初始条件由我构造），常数 `w=0.2 / α₁=0.6 / α₂=0.7 / 阈值 0.3 / clip[0,3)` 逐字来自原文 §IV-C。

原文单位在 HTML 抽取中被吞（如 "1.65 m" 实为 1.65 m/s），下表按物理量补全单位；凡原文未给者一律标「论文未报告」。

| 纯推理吞吐（FC@250/CL@175, VDD 1.2 V，"最高性能"） | **~17 frame/s @ ~119 mW** | **~19 frame/s @ ~102 mW** | §V-B1 |

| 单帧能量 | **~3–4 mJ** | ~3–4 mJ | Abstract |
| 闭环实测感知帧率 | **8.7 frame/s**（省能配置）/ **12.8 frame/s**（性能配置） | **论文未报告**（闭环实验只用 GAP flow 部署） | §V-C1 |
| 参数量 | **0.32 MB**（V1: 0.64 MB） | 同 | §V-B1 |
| 计算量 | **~41 M MAC**，但每 MAC 是 **8×8-bit**（V1 为 16×16-bit） | 同 | §V-B1 |

| 整机功耗占比（AI-deck / 整机） | **0.67%**（省能）/ **1.64%**（性能） | **0.63%** / **1.43%** | §V-B3 |

**部署约束与 trade-off（逐条落地）**

1. **内存是硬墙，不是软约束**：L1 TCDM 只有 64 kB，权重 0.32 MB 必须常驻 L2（512 kB，装得下但只剩 ~180 kB 给激活）。所以 tiling 求解器不是优化项，是**可行性条件**。8-bit 的 2× 缩减真正买到的是"权重全驻 L2、不用反复去 DRAM"。
2. **位宽减半 ≠ 速度翻倍**：实测只有 **1.5–1.6×**。原文归因：i) 非 MAC / 非可加速操作（反量化、激活、输入 range 归一化），ii) 非理想性——负载不均 + marshaling 开销。**这是所有 edge 部署估时的通用折扣，做 sizing 时按"位数比 × 0.75–0.8"估更稳。**
3. **两套 flow 的胜负是分层级的，不是全局的**：AutoTiler 赢在**空间大、channel 少**的层（第一层 Conv 5×5，且能融合 Conv+MaxPool 免掉一次 L2 中转）；DORY 赢在**channel 多**的层（HWC + im2col GEMM，且不需要 shuffle）。**结论：如果模型首层是大 kernel、小 channel（典型 tiny CNN），GAP flow 的结构性优势会更大。**
4. **闭环帧率 &lt; 纯推理帧率**：性能配置纯推理 19 fps（≈53 ms），闭环只有 12.8 fps（≈78 ms）→ 约 25 ms 花在采图 / UART / 控制循环 / DMA 调度上（**此为我的算术推算，标 UNVERIFIED**）。做端到端预算时，别拿 §V-B 的 fps 当控制环频率。
5. **通信不是瓶颈，但格式耦合是坑**：115200 baud 传 2 bytes ≈ 0.17 ms，传 8 bytes 也远小于帧周期——**带宽安全，但"发什么"完全决定飞控固件**（见 §8）。
6. **飞控侧开销可忽略**：主循环 5 ms 轮询一次 DMA 标志，相对 78–115 ms 的帧周期占 4%–6%。
7. **算力换安全是单调的**：省能配置 `v_brake = 1.41 m/s`，性能配置 `1.65 m/s`（+17%），代价是 AI-deck 功耗占比 0.67% → 1.64%。**整机 7.3 W 电机占了 94.8%–96.0%，所以"把 SoC 拉满"几乎是免费的——这是本文最实用的工程结论之一。**
8. **对比 CMSIS-NN / Cortex-M7**：原文给 STM32H723VE（单核 M7 @550 MHz）可达 **390 M @ 203 mW**；GAP8 @CL175 MHz 为 **1.44 G @ 102 mW**（NEMO/DORY）与 **1.14 G @ 119 mW**（GAP flow）→ **功耗优于 M7 方案 >1.7×，吞吐 >3×**。

| V1 | Original+Himax | Fixed16 | 0.110 | 0.977 | 0.891 |
| V2 GAP flow | Original | Float32 | 0.126 | 0.915 | 0.831 |
| V2 GAP flow | Original | **Fixed8** | **0.124** | **0.916** | **0.840** |
| V2 GAP flow | Original+Himax | Float32 | 0.136 | 0.925 | 0.881 |
| V2 GAP flow | Original+Himax | **Fixed8** | **0.135** | **0.925** | **0.886** |
| V2 NEMO/DORY | Original | Float32 | 0.146 | 0.902 | 0.841 |
| V2 NEMO/DORY | Original | **Fixed8** | **0.143** | **0.903** | **0.836** |
| V2 NEMO/DORY | Original+Himax | Float32 | 0.118 | 0.893 | 0.905 |
| V2 NEMO/DORY | Original+Himax | **Fixed8** | **0.120** | **0.892** | **0.900** |

**读法（讲条件，不只给结论）**：
- 8-bit 相对自身 float32 的变化在 **RMSE ≤0.003、Acc ≤0.1%** 内——**这才是"精度不掉"的严格表述**。
- 但**跨拓扑不比 V1 好**：GAP flow/NEMO 在 Original 上 float32 RMSE 0.126/0.146，均劣于 V1 的 0.105（原文归因：拓扑差异、8 vs 16 bit、以及分类/回归共享前端到最后一层导致的弱收敛）。所以「V2 = V1 同精度」成立的前提是**在 Himax 测试集上（~90%）**，不是所有指标。
- 加 Himax 数据的收益很实：所有模型 Himax Acc 从 **~83–84%** 提到 **~88–90%**。

## 6 · 能力与失败模式

**能做（具体到数）**
- 以 **1.65 m/s** 刹停于 1.5 m 外出现的动态障碍前；安全距离 **~0.25 m**（性能配置）。
- **45° 弯**以 **1.47 m/s** 平均速度通过；**90° 弯**降到 **0.59 m/s**——锐弯是硬约束。
- 110 m 走廊 **5/5 成功**直到 `v_avg = 1.72 m/s`，**1.96 m/s** 仍 4/5。
- **零样本场景迁移可用**：完全陌生的公共街道上 6/6、平均 **171 s**——这是全文最强的泛化证据。
- 整机功耗代价极小：AI-deck **≤1.64%**。

**不能做（具体到失效）**
- **窄隧道 + 静态障碍 = 0/6**：原文描述为「卡在障碍附近，缓慢漂移向它，最后突然撞上」——典型的**只有减速、没有绕行**。根因见 §5.1 的标签互斥。
- **高加速 → 相机看地板**：`v_avg = 2.29 m/s` 时成功率崩到 **1/5**，因为大俯仰角使相机主要拍到地面，反应时间被压到极小。这是**纯几何/机械耦合**，任何控制律调参都救不了。
- **无深度、无尺度**：单目灰度 + 分类头，输出只有「碰撞概率」这一标量，没有自由空间几何、没有障碍物距离。
- **默认场内有视觉车道线索**：街道场景原文指出训练/部署差异来自「街道上没有车道线标志」，靠的其实是语义化的通路感。
- **Udacity 数据的地理偏置**：45° 场景里部分轨迹「呈现右行驾驶策略 fostered by the dataset（Udacity 采集于美国）」→ 会增加 RMSE 但任务仍完成。

### 隐含假设 (Hidden Assumptions)

| # | 隐含假设 | 一旦不成立会怎样 | 证据位置 |
|---|---|---|---|
| 1 | **碰撞概率可解释为"正前方有障碍"**（与转向解耦） | 窄隧道里它只会减速不会转 → 0/6 | §V-C4 |
| 2 | **两个头的训练标签来自不同分布是可接受的** | 恒速/大角度弯下两任务冲突时无仲裁机制 | §III-B/§V-C4 |
| 3 | **8-bit PTQ 不损精度**是拓扑相关的，不是普适结论 | 换拓扑（如 V1 原样喂 NEMO）会量化失败或掉点 | §IV-A, Fig.2 |
| 4 | **控制律参数按"帧索引"积分，不按时间积分** | `I(k) ← I(k−1)+(p_col−0.3)` 无 `dt`；换帧率（8.7→12.8 fps）等价于把物理时间常数改了 1.5×，而原文未重调 `w/α` | §IV-C 伪代码 |
| 5 | **环境光照充足、纹理可用**（QVGA 灰度 ULP 相机） | 暗光/低纹理失效；原文未做光照实验 | 平台描述 |
| 6 | **状态估计由平台自身提供**（Flow-deck 光流 + ToF）；Vicon 仅用于后处理分析 | 若光流在无纹理地面失效，闭环会先崩在定位而非感知 | §III-A / §V-C1 |
| 7 | **"熟悉的 110 m 走廊"包含在训练分布内** | 该实验的成功率**不能**当作泛化证据；真正泛化靠 Table V 的 street/office | §V-C3 |
| 8 | **整机 7.3 W 电机功耗主导，AI 负载几乎免费** | 换成更小电池/更省电平台，1.64% 这个结论不再成立 | §V-B3 |

## 7 · 与相关工作对比

| 维度 | **本文 PULP-Dronet V2** | PULP-Dronet V1 [1] | 微小模型路线 [7][15][16][18][19] | 卸载到基站 [20][22] | ASIC 加速 [23][24][25] | CMSIS-NN / Cortex-M7 [40] |
|---|---|---|---|---|---|---|
| 部署方式 | **自动化（NNTOOL+AutoTiler / NEMO+DORY）** | 手工迭代 | 手工/极小模型 | 不适用 | 硬件定制 | 通用库 |
| 数值格式 | **8-bit PTQ** | 16-bit 定点 + QAT | 不定 | 浮点（远端） | 定点 | 8-bit |
| 感知输入 | 单目灰度 | 单目灰度 | 激光/极简特征/IMU | 图像流 | 部分（VIO/SLAM） | — |
| 功能范围 | **端到端飞行控制**（避障+循线） | 端到端 | 单功能（悬停/避撞/定位） | 端到端但有链路 | 仅子功能，仍需主控 MCU | 仅推理 |
| 吞吐 | **8.7–12.8 fps（闭环）** | 提升 40%–60% 前基线 | 200 Hz（但仅 2.7 k 运算）[7] | 受无线延迟 | — | 0.71 MAC/cycle [40] |
| 功耗 | AI-deck **≤1.64%** 整机 | 略高 | 极低 | 无线收发可能占主预算 | 数百 mW | M7 方案 203 mW |
| 主要短板 | 单目+标量输出；无绕障 | 慢（0.5 m/s）、精度对 QAT 敏感 | 只能处理粗大/同质障碍 | 距离受限、安全/延迟 | 不灵活、非端到端 | 吞吐低 3× |

**一句话定位**：本文的对手**不是**别的网络，而是「同一张网的手工部署流程」；它对 ASIC 路线的差异化优势是**可编程 + 端到端**，对微小模型路线的优势是**视觉通路的通用性**。

**🎤 面试 Tip（被问到"这篇到底新在哪"怎么答）**

> 「它没有提出新网络——网络就是 Dronet，改动只有一处：为了适配 NEMO 量化器，把 ResBlock 的最后一个 ReLU 推到 residual branch。它真正的贡献是**把部署当成编译问题**：8-bit 后训练量化（不需要训练集、不需要重训）+ AutoTiler/DORY 自动求 tile 划分，换来 **2× 内存、1.5–1.6× 吞吐、精度变化在 0.003 RMSE 内**。
> 但数据上最反直觉的一点是：**闭环从 0.5 m/s 提到 1.96 m/s 这个 4×，主要不归功于网络，而归功于控制律**——二次速度映射 `v ∝ (1−p_col)²` 加一个 clip 到 [0,3) 的积分项压住 CNN 的概率抖动。所以如果有人拿这篇当『8-bit 量化让无人机飞快 4 倍』的例子，那是误读。」

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-10-22)

**repo 状态**：原文在 Abstract 与 Conclusion 中明确给出开源地址 `https://github.com/pulp-platform/pulp-dronet`（以纯文本形式出现，未能确认为 PDF 内可点击超链接），并声明 "we open-source all the software design in a ready-to-run project compatible with the Crazyflie 2.1"。**截至 2026-10-22，本次解析所依据的全文文本中不含任何 issue 流信息**，因此以下 pitfall **全部由 §6 失败模式 + §IV 方法约束推导，未经 issue 验证**；不引用任何 issue 编号 / 标题 / 日期。

| # | Pitfall | 由上溯的失败模式 | 由上溯的方法约束 |
|---|---|---|---|
| **P1** | **把 V1 原拓扑直接喂给 NEMO，量化会失败或掉点** | §6「8-bit 精度代价是拓扑相关的」 | §IV-A 原文：NEMO 基线「不支持量化非 ReLU 输出的数据」→ 必须把 ResBlock 末 ReLU 推到 residual branch（Fig.2）。原样迁移 = 撞这条限制 |
| **P2** | **换 flow 必须同步改飞控固件，否则速度映射全错** | §6「碰撞概率到速度的映射是唯一闭环通路」 | §IV-C：GAP flow 输出 **2 bytes 8-bit 量化值**，NEMO/DORY 输出 **8 bytes 32-bit 累加器**；反量化常数 `c_scale0/c_scale1` 是**硬编码在 STM32 固件里**的 |
| **P3** | **换 SoC 主频后闭环行为会变，不是"只变帧率"** | §6 隐含假设 4：积分按帧索引、不乘 `dt` | §IV-C 伪代码 `I(k)←I(k+1)+(p_col−0.3)` 无时间因子；8.7 → 12.8 fps 等价于把积分/滤波的物理时间常数缩放 1.5×，而文中 `w=0.2, α₁=0.6, α₂=0.7` 在两个配置上是**同一套** |
| **P4** | **复现 GAP flow 结果受 SDK 版本强约束** | §6「AutoTiler 融合 Conv+MaxPool 是其相对 DORY 的结构优势」 | §IV-B 原文：AutoTiler 为 **partially closed-source** 的厂商工具；DORY 虽开源，但 L3→L2 用 known-good 启发式，非最优解，换拓扑可能退回次优 |
| **P5** | **"自动化 = 无损"是错的：跨 flow 会有 0.02–0.04 的 RMSE 回退** | §6「V2 并非在所有指标上追平 V1」 | §V-A1 原文：Original 集 float32 下 GAP flow / NEMO/DORY 的 RMSE **0.126 / 0.146**，而 V1 为 **0.105**；原文归因于拓扑差异与弱收敛 |
| **P6** | **在窄通道/静态障碍场景调参是死路** | §6「窄隧道 + 静态障碍 0/6，卡住后漂移再撞」 | §III-B：Udacity 只给 steering、Bicycle/Himax 只给 collision，**标签互斥** → 网络不具备"为避障而转向"的监督信号；只能靠换数据或加中间决策层（原文把这两条列为 future work） |
