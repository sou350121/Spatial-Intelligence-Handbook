# TRISTAR：三信号楼梯识别与纯视觉室内导航，面向搜救微型无人机 (TRISTAR: Triple-Signal Stair Recognition and Vision-Only Indoor Navigation for Search-and-Rescue Micro-UAVs)

> **发布时间**：2026-07-04（arXiv:2607.03818v1 [cs.CV]）
> **论文 / 模型名**：TRISTAR（TRI-Signal STair Ascent Recognition）
> **核心定位**：在一台 <150 EUR、无任何专用测距传感器的 DJI Tello（~80 g）上，用**纯单目视频**（Depth Anything V2 + 经典 CV）实现走廊自主探索、开门进房、OCR 读门牌、人员检测与楼梯自主攀爬——把原本需要 11,000 USD 级平台的室内自主能力下沉到软件层。
> **Ontology 5-axis**：problem=navigation · representation=n/a · sensor=mono · paradigm=hybrid（几何 CV + 神经语义）· time=filter-streaming（EMA + 死区 + 相位状态机）

导语：室内搜救（SAR）的痛点是 GNSS 失效、布局未知、能见度差，而现有自主方案要么靠 LiDAR/双目抬高成本与质量，要么只能做跟踪/避障这类"点任务"。本文结论：单目深度足以支撑一条完整的"探索走廊→进房→扫描→上楼"链条，且**结构几何交给经典 CV、语义理解交给神经模型**的分工是最优性价比。

---

## X-Ray 开场

一句话：**TRISTAR 用三个"虚拟传感器"（Sobel 结构梯度 + 多尺度 Gabor 纹理 + 单目深度 DA2 几何）各自算一个 0~1 置信分，取等权平均，超过 0.52 才允许无人机上楼**——因为每个模态单独都脆弱，融合才可靠。

对 spatial AI 研究者意味着什么：它质疑了"要自主就得加硬件"的默认路线，用**标定后的相对深度**（误差 27.4%→<10%）承担所有控制决策，并用一个可复现的消融证明"三路融合 > 任意两路 > 任意单路"（7 配置 × 4 飞行，仅全融合 4/4 成功）。它是"廉价平台 + 系统集成"范式的样板，而非新的网络结构贡献。

## 1 · 核心架构 / 方法总览

系统是本地服务器 + Web 前端架构：FastAPI 后端 + React 前端 + 两个可选微服务（OCR=EasyOCR、医疗=Gemini 2.5 Flash）+ DJI Tello（UDP）+ SQLite 任务库。所有感知在本地 GPU 上跑三个神经模型：DA2（ViT-S，深度）、YOLO11n-Pose（人 + 17 关键点）、YOLOv8（火/烟）。本地加载模型总大小 ≈ 200 MB。

### 1.1 系统 / 组件对比表

| 模块 | 输入 | 输出 | 训练/推理差异 |
|---|---|---|---|
| **深度管线** stream_pipeline | 720p 视频帧（30 FPS 目标，drop-oldest 队列） | 标定后的逐像素度量深度图 D | DA2 权重离线预训练；**标定查表为运行时经验拟合，不训练** |
| **深度标定层** | DA2 相对值（色图 blue-channel 0–255） | 米制距离（查表 + 线性插值） | 无训练；**房间/走廊两套 profile 可 REST 热切换** |
| **门检测** door_controller | 深度图 D | 门候选框 + 进入控制 | 无训练、无外观模型，纯几何（掩膜+形态学+三过滤器） |
| **走廊导航** navigation | 深度图 + 门框 | lr/fb/ud/yaw RC 指令 | 比例控制 + EMA + 死区状态机 |
| **TRISTAR 楼梯检测** stair_climber | 320×240 分析图 + 深度图 | 复合置信分 conf_stairs | 三路纯推理，**无需训练** |
| **语义分析** AI Analyzer | 视频帧 | 人体姿态 + 医疗状态 + 火/烟 | YOLO11n-Pose/ByteTrack/YOLOv8 推理 + Gemini 云端 |

### 1.2 关键机制

> ⚡ **Eureka Moment：把"楼梯"不当作一个物体去检测，而是当作三个物理模态同时成立才存在的几何事件——Sobel 提供"每一级台沿"的上升线索、Gabor 提供"贯穿整幅"的纹理鲁棒性、单目深度提供"拒绝欺骗场景 + 识别平台"的几何验证；正因为每个传感器单独都脆弱，三路融合才强。**

三个虚拟传感器的核心判据：

- **Sensor 1 — 水平 Sobel**（结构）：在 320×240 图上取垂直梯度模 |G_y|，梯形掩膜去掉扶手/侧墙，逐行均值成 1D 剖面，高斯平滑 + 非极大值抑制找峰；一个峰只有当其线覆盖 **≥55% 帧宽**才算一级台阶。分数 `S_sobel = 0.40U + 0.35C + 0.25D`（U=峰间距均匀性、C=垂直覆盖、D=峰密度）。
- **Sensor 2 — 多尺度 Gabor**（纹理）：θ=90° 的 5 个核，λ∈{14,22,32,45,65}px 覆盖 ~0.5m 到 ~4m；有深度时自适应选波长 `λ*(d)=0.20·f_y/d`。核心判据是**边到边覆盖**：每条强响应线必须从左右帧边贯穿（含透视容差），不满足的标"红"。`S_gabor = C_edge-to-edge·(1 − r_red^0.35)`。
- **Sensor 3 — 单目深度 DA2**（几何）：两个性质——① 全局 CoV 在台阶上大（>0.28）、平面上小（<0.12）；② **频带单调性**：把图分 5 条水平带，从下（近台阶）到上（远台阶）中位深度必须单调递增。一次逆序把因子 M 塌到 0.05，两次塌到 0。`S_da2 = min(1, normalize(CoV))·M`。

融合与阈值：`conf_stairs = (1/3)(S_sobel + S_gabor + S_da2)`，**越阈 0.52 才起飞**，且要求三路互相印证。

## 2 · 数学核心

📌 **Napkin Formula**：

```
conf_stairs = (1/3)·(S_sobel + S_gabor + S_da2)  ≥ 0.52   →  允许上楼
     门检测：R = Q0.9(|G_x|_margin) / Q0.9(|G_x|_center) ≥ 1.20  →  判定为门
```

**目标**：在没有任何测距硬件的条件下，用单目深度 + 经典滤波得到一个**抗欺骗、能识别平台（landing）**的楼梯置信度，以及一个**不依赖外观**的门检测判据。

**公式与变量**：

| 公式 | 变量说明 | 直觉 |
|---|---|---|
| `S_sobel=0.40U+0.35C+0.25D` | U=峰间距 CoV 低（均匀）、C=行覆盖、D=峰密度 | 楼梯 = 等间距水平峰；门/墙 = 垂直梯度占优，被惩罚 |
| `λ*(d)=0.20·f_y/d` | 0.20m 标准步高、d 估计距离、f_y 垂直焦距 | 远台阶在图上间距更小，波长应随距离自适应 |
| `S_gabor=C_ete·(1−r_red^0.35)` | C_ete=边到边线覆盖、r_red=不合格线比例 | 真台阶线横贯全幅；局部纹理（地毯/瓷砖）不横贯 |
| `S_da2=min(1,norm(CoV))·M` | CoV=σ(D)/μ(D)、M=单调性因子(1→0.05→0) | 台阶 → 深度有序递变；平墙 → 深度大但无序 |
| `CoV=σ(D)/μ(D)`, `r_blue=|{d_min≤D(p)≤d_max}|/|D|` | D=逐像素度量深度集合 | 台阶 CoV 大；平墙小。蓝比 = 场景"向远延伸"的程度 |
| `R=Q0.9(|G_x|_margin)/Q0.9(|G_x|_center)` | Q0.9=90 分位；margin/center=候选框左右边/中心 | 开门=被门套框住的远景 → 边缘垂直梯度远强于中心 |
| `v_fb(d)=v_max(d−d_min)/(d_tgt−d_min)` | d_min=0.7m、d_tgt=1.2m、v_max=30cm/s | 越靠近台阶越刹车 |

**直觉总结**：论文把"结构/纹理/几何"三种互补先验各自压成一个 0~1 分，靠**等权平均 + 三路印证**把单模态的假阳/假阴互相抵消。门检测同理：不认外形，只认"垂直深度边缘比值"。

## 3 · 带数字走一遍（玩具设定）

**A. 楼梯融合分**（数字为演示，非论文实测）

设一帧楼梯图，三路输出：

- Sobel：U=0.80、C=0.70、D=0.60 → `S_sobel = 0.40·0.8 + 0.35·0.7 + 0.25·0.6 = 0.320 + 0.245 + 0.150 = 0.715`
- Gabor：C_ete=1.00、r_red=0.20 → `0.20^0.35 = e^{0.35·ln0.2} = e^{-0.563} = 0.569` → `S_gabor = 1.00·(1 − 0.569) = 0.431`
- DA2：norm(CoV)=0.90、单调性完好 M=1.0 → `S_da2 = 0.90`

融合：`conf = (0.715 + 0.431 + 0.900)/3 = 2.046/3 = 0.682 ≥ 0.52` → **起飞**，且三路都高，互相印证。

对照一个**平面**：Sobel 峰稀疏 → S_sobel≈0.20；Gabor 无贯穿线 → C_ete=0 → S_gabor=0；DA2 CoV<0.12 且单调性丢失 → M 因数塌陷 → S_da2≈0。`conf ≈ 0.067 < 0.52` → **拒绝**。三路同时塌，正是 landing 判据。

**B. 门检测 R 比值**

- 真门（门上被门套框住）：margin 的 `Q0.9(|G_x|) = 12`，center = 8 → `R = 1.5 ≥ 1.20` → **接受**（论文 Fig.5a 部分可见门实测 R=52.75）。
- 衣柜（深但无门套）：margin ≈ 0.4，center ≈ 8 → `R = 0.05` → **拒绝**（论文镜面 R=0.38，衣柜 R=0.05）。
- 玻璃窗（有真实横向边缘）：`R = 6.97` → **误检**，单目无法与门区分（论文承认的固有失败）。

**C. 前进速度刹车**

d=1.0m（在 0.7~1.2m 区间内）：`v_fb = 30·(1.0−0.7)/(1.2−0.7) = 30·0.3/0.5 = 18 cm/s`。若 d<0.7m → v_fb=0（停下）。

## 4 · 工程视角

| 指标 | 论文报告值 |
|---|---|
| 后端硬件 | Intel Core i7 + NVIDIA RTX 3060 Mobile（6 GB VRAM）+ 16 GB RAM，Python 3.11 / PyTorch 2.4 / CUDA 12.1 |
| 原始视频流帧率 | ~30 FPS |
| 端到端（frame → RC 决策） | ~10–12 Hz |
| DA2 (ViT-S) 单帧推理 | ~45 ms / frame（GPU） |
| 端到端延迟 | ~85–100 ms（预算 <300 ms） |
| 本地模型总大小 | ≈ 200 MB |
| Tello 控制通道 | `send_rc_control(lr,fb,ud,yaw)`，UDP，仅 10–15 Hz |
| 视频解码延迟 | 80–150 ms（H.264） |
| DA2 度量深度帧间抖动 | 相邻帧可达 **±0.2 m**（同质表面尤甚） |
| 楼梯爬升环频率 | 固定 12 Hz，每 tick 三条并发 RC 指令 |
| 安全层 | 单次飞行 50 s 超时、20% 电量强制降落、操作员中止、全程录制（原始+debug 叠帧） |

**Trade-off 解读**：
- **无测距硬件**换来了成本（<150 EUR）与质量（~80 g），代价是精度全部由"经验标定查表"兜底——标定 profile 一旦换楼/换装修就需重标。
- **10–12 Hz 控制环**远低于 30 FPS，瓶颈在深度推理 + 端到端延迟，而非相机。因此所有派生量都走 **EMA（α=0.18）+ 死区（±0.05）+ stable_hits=3** 滤波，用**延迟**换**稳定**（论文 Fig.6 明确展示：EMA 吸收了 raw 信号的噪声尖峰，避免了一次不必要的方向反转）。
- **走廊与楼梯两个模块完全独立**（stair_climber 是独立包），可单独验证、单独触发，但也意味着**无法串成连续任务**（爬完楼不能接着上层走廊探索）。

> 论文未报告的项目：CPU/内存占用、峰值功耗、每模块单独耗时分解、DA2 之外的 YOLO 模型推理延迟。

**主要结果（逐字来自全文）**：

## 6 · 能力与失败模式

**能做**：
- 纯单目走廊自主梳理，无测距硬件；门检测用几何而非外观，能识别**只部分入画**的门、能拒绝衣柜/镜面这类"外观陷阱"。
- 无 GNSS 下自主上楼，且**能识别平台（landing）**并停下——这是三路融合里深度模态的核心贡献。
- 集成了 OCR 门牌、人员姿态 + 医疗分诊、火/烟检测，产出一份结构化 JSON 报告。

**不能做 / 失败模式（论文明确记录）**：
- **玻璃窗误检为门**：窗的深度剖面与开口完全一致，R=6.97，单目不可区分（论文承认这是"固有于单目深度"的失败）。运营中靠进门后 OCR 复核缓解。
- **极低光漏检真门**：深度图过平滑，门套边缘消失，R=0.10 < 1.20。
- **楼梯被遮挡 / 几何不可见时漏检**：台阶前有障碍或视野内台阶太少 → Sobel 与 DA2 同时归零，Gabor 单独达不到 0.52（Table VI：Stairs+obstacle 得分 0.25；Partial stairs(right) 0.25）。
- **DA2 单模态被窗台/门楣骗**：DA2 only 闭环 0/4，窗台模仿台阶深度剖面，且无法识别 landing。
- **缺深度时"看不见坡道尽头"**：Sobel/Gabor/Sobel+Gabor 会冲过头撞天花板/墙或过早落地。
- **缺 Sobel 时丢失"每级上升"线索**：Gabor+DA2 会径直冲过平台。
- **复杂扫描累积偏航漂移**：连续两次 90° 旋转后失败（Tello 已知限制，论文留待 IMU 重力向量补偿）。

### 隐含假设 (Hidden Assumptions)

1. **静态规则几何**：走廊为平直、双侧平行墙的长廊，门为墙上矩形开口；非平面/非规则建筑（如斜墙、开放大厅）未验证。
2. **深度标定场景绑定**：查表把 DA2 原始值映射到米制距离，仅对 room/corridor 两套 profile 的"目标几何"有效——换装修/换楼层需重标。
3. **单目深度被当作可信的距离传感器**：所有控制都建立在"标定后误差 <10% 足够"这一前提下；而论文自身也承认 ±0.2 m 帧间抖动需靠 EMA 掩盖。
4. **台阶从下往上看且可见**：S_da2 的单调性假设要求无人机位于楼梯底部、台阶几何可见。
5. **无全局地图也不影响安全**：每个任务几何独立，不做 SLAM、不做回环，靠超时/电量/中止三重守卫兜底。
6. **云端可用的医疗分诊**：Gemini 微服务虽可选关闭，但"人员状态判定"这一能力依赖网络。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-09-20)

论文正文**以纯文本给出**了官方仓库地址：`https://github.com/tavigingu/HawkOps-Indoor-Drone-Navigation-and-TRISTAR-Stair-Climbing`（非 PDF 内嵌可点击超链接，按本手册判定标准视为**弱 repo 信号**）。截至 **2026-09-20**，我无法核实该仓库的 issue 流活跃度，因此**不引用任何 issue 编号、commit hash 或社区复现记录**。以下 3 条 pitfall 由 §6 失败模式 + §1/§2 方法约束**机械推导**（未经 issue 验证）：

1. **标定查表是"场景硬编码"，跨楼即崩**
   - 来源：§6 隐含假设 2（标定场景绑定）+ §2 标定层是"查表 + 线性插值"。
   - 推导：`room`/`corridor` 两套 profile 的映射曲线由**24 张参考图**拟合。部署到不同反光/不同墙面材质的建筑时，同一条 `raw→meter` 曲线不再成立，而门检测掩膜（1.7–6.0 m）、进房距离（1.8 m）、刹车区（0.7–1.2 m）全部是**绝对值阈值**——曲线偏移会同时污染门检测、居中、爬升三层控制，表现为"门口距离控制振荡或直接撞门"。

2. **固定 CoV 阈值 0.28/0.12 在反光与玻璃面前失效**
   - 来源：§6 失败模式（玻璃窗 R=6.97 误检；低光 R=0.10 漏检）+ §1.2 Sensor3 硬阈值。
   - 推导：`CoV>0.28` 判"有台阶"、`<0.12` 判"平面"是标定到目标走廊/楼梯几何的常数。强反光地面或玻璃幕墙会产生既高 CoV 又非单调的深度场，`M` 因子与 CoV 判据互相矛盾，`conf_stairs` 可能落在 0.52 附近的**抖振区**，触发"起飞-回落"抖动。

3. **`M` 单调性因子对"台阶几何不可见"零容忍，且无 fallback**
   - 来源：§6 失败模式（Stairs+obstacle / Partial stairs(right) 均得 0.25）+ §1.2 `S_da2=min(1,norm(CoV))·M`。
   - 推导：`M` 在两次逆序时直接塌到 0，把整路 DA2 分归零。楼梯口有障碍、或无人机恰在楼梯中途仰角过大时，Sobel 与 DA2 同时归零，只剩 Gabor≤1.0，`conf=(0+1+0)/3=0.33<0.52` → **原地悬停或超时**（对照 §4 单次飞行 50 s 超时保护会强制降落）。修法需引入"部分可见"退化策略，但论文未提供。
