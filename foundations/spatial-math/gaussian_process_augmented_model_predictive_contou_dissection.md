# GP-MPCC：面向全驱动 AUV 六自由度轨迹跟踪的高斯过程增强模型预测轮廓控制 (Gaussian Process-Augmented Model Predictive Contouring Control for 6-DoF Trajectory Tracking with a Holonomic AUV)

> **发布时间**：2026-11-10（arXiv:2611.14373v1 [cs.RO]，CC BY 4.0）
> **论文 / 模型名**：GP-MPCC（Model Predictive Contouring Control + Gaussian Process residual + zoRO）
> **核心定位**：把"6-DoF 轮廓控制 + GP 残差动力学 + 零阶鲁棒不确定度收紧"三者拼成一条 25 Hz 的实时控制回路，第一次在**全驱动（holonomic）AUV 上实船跑通 6-DoF MPCC**，姿态跟踪误差比调好的 PID 降 47%。
> **Ontology 映射**：problem=`navigation` / representation=`n/a`（不学表征，只学动力学残差） / sensor=`n/a`（依赖外部 EKF 融合 IMU+压力+DVL，感知不在本文范围） / paradigm=`hybrid`（一阶原理标称模型 + GP 数据驱动残差） / time=`filter-streaming`（25 Hz 滚动时域，RTI 单步 SQP）

小型全驱动 AUV 做近距检测时，必须"一边绕着目标平移、一边把相机对准目标"——位置和姿态要能解耦跟踪；而 MPC 的性能天花板完全取决于水动力学模型精度，水下参数恰恰最难辨识。本文的答案是：**不追求把模型辨识准，而是只学标称模型真正缺的那一小块（角速率残差），再把 GP 的方差当成约束收紧量喂回优化器**。

---

## 🎯 X-Ray 开场

MPCC（轮廓控制）把"跟踪时间参数化参考"换成"跟踪几何路径 + 把沿路径进度当决策变量"，天然适配"绕目标飞/游"这类任务；但它在水下的落地一直卡在两件事：① 没人做过 6-DoF（多数工作砍到 3-DoF，丢掉深度/roll/pitch，而这三者恰恰是检测任务的核心）；② 标称水动力模型不准，误差直接进闭环。本文做了两件事：把 MPCC 扩到 6-DoF 并把姿态误差独立加进代价（利用 holonomic 特性，姿态与航向解耦）；用 6 个独立 GP 学体速度通道的残差，经 `zoRO` 把 GP 方差变成约束 back-off 项，保持 25 Hz 实时。

**对 spatial AI 研究者的意义**：这是一个"不确定度驱动的控制接口"样例——GP 的后验方差没有停在"诊断/可视化"层面，而是被翻译成一个**标量约束收紧量 β** 进入实时 SQP，与策略网络/表征学习完全解耦。它同时给了一个反直觉的实证结论：**残差"学什么"比"怎么学"更决定成败**——学全部 6 个通道反而让误差翻倍。

## 1 · 核心架构 / 方法总览

### 1.1 系统组件对比表

| 模块 | 输入 | 输出 | 训练 / 推理差异 |
|---|---|---|---|
| 参考轨迹生成（cubic spline + SLERP） | 位置 waypoint + 姿态 waypoint | 路径 `p(θ)`、单位切向 `t(θ)`、姿态参考 `q_ref(θ)`（同一弧长参数对齐） | 无训练；离线一次性生成 |
| 标称动力学 `f`（Eq. 4–5，marine craft 六自由度方程） | `x=[η;ν]`、`u=τ` | `x_{k+1}` | 参数**不辨识**：直接用已知重量 + BlueROV2 系数（引 [7]，如 [33] 所用）；对角阻尼 `D`、对称机体、`ν_c=0` |
| GP 残差模型（6 个独立 GP，SE + ARD 核，GPyTorch） | `z=[x;u]` | 均值 `μ^g(z)`、方差 `Σ^g(z)`、雅可比 `∂μ^g/∂x` | **离线**训练（开环激励采集，每 GP 子采样 100 点）；**在线**只做推理，仿真与真机**各训一套** |
| zoRO 不确定度传播（Eq. 12–14） | 上一次 SQP 解 `(μ̂_k, û_k)` | `Σ̂_k`、约束收紧量 `β̂_k` | 无训练；每采样周期在 SQP **之外**传播一次（避免把协方差当决策变量） |
| MPCC 优化器（acados + L4acados，SQP/RTI） | 当前状态、`θ`、`v_θ`、GP 均值与雅可比、`β̂_k` | 归一化体轴广义力 `τ` | 在线，**25 Hz**，`N=40`，每步只做 **1 次 SQP 迭代**，用上一解 warm start |
| 推力分配（机载） | `τ` | 各推进器指令 | 在线，运行在 AUV 上；MPCC 本身跑在**水面笔记本**，经 LCM 通信 |

### 1.2 关键机制

**⚡ Eureka Moment：不要"学模型"，要"学模型缺的那一维，并把它的方差变成一个约束收紧标量"。**

拆开看是两个半洞见：

1. **轮廓控制在 6-DoF 上的"半解耦"**：把位置误差 `e(θ_k)` 拆成沿切向的 lag 分量 `e^l` 与法平面的 contouring 分量 `e^c`（Eq. 6–7）。`e^c` 被惩罚，`e^l` 不做惩罚而是通过 `v_θ`（沿路径进度速度）**奖励前进**。于是"跟上没跟上"和"偏没偏"解耦成两个旋钮；再叠加上姿态误差 `e_q = q_ref ⊗ q^{-1}`，就让 holonomic AUV 能"横着走同时转头看目标"。
2. **GP 的价值不在均值，在方差**：GP 均值直接替换标称动力学（Eq. 11c），但真正让它"鲁棒"的是把预测协方差沿时域线性传播（Eq. 12），再按 `β_i = γ√(∇h_i^T Σ_k ∇h_i)` 收紧约束（Eq. 11e）。用 `zoRO` 把这步挪出 SQP 迭代（Eq. 14），代价是保守性略增，收益是**问题结构与标称 MPCC 完全同构**，可以复用同一套求解器机制。

而论文用消融实验给出的"反洞见"同样重要：**线性通道（surge/sway/heave）的残差被测量噪声主导，GP 学到的是噪声**，`gp-full` 把位置与姿态误差、控制能量全部大致翻倍。所以工程上正确的动作是"只学角速率 p/q/r"。

## 2 · 数学核心

📌 **Napkin Formula**

```
min_{u, Δv_θ}  Σ_k [ ‖e^c_k‖²_Qc + Q_l (e^l_k)² + ‖e_{q,k}‖²_Qq + ‖Δu_k‖²_R ]
s.t.  μ_{k+1} = f(μ_k, u_k) + B_d·μ^g(μ_k, u_k)          ← 均值动力学
      h(μ_k) + γ·√( ∇h^T Σ_k ∇h ) ≤ 0                    ← 方差变约束收紧
      Σ_{k+1} = A_k Σ_k A_k^T + B_d Σ^g B_d^T + Σ_w      ← 协方差在 SQP 外传播
```

一句话：**"沿着路径的偏差用轮廓误差惩罚，沿路径的进度用参考速度奖励，模型不确定的地方用 GP 方差把约束往里收一点。"**

### 2.1 目标：残差动力学的鲁棒最优控制

离散非线性系统（Eq. 1）：

```
x(t+1) = f(x(t), u(t)) + B_d g(x(t), u(t)) + w(t),   w ~ N(0, Σ_w)
```

- `f`：一阶原理标称模型（Eq. 4–5 的 marine craft 方程离散化），`x=[η^T, ν^T]^T`，`u=τ`
- `g`：未知残差（未建模效应 + 参数失配），`B_d` 选择残差作用的通道
- 残差样本由相邻状态测量反解（Eq. 3 / Eq. 9）：
  `y(t) = B_d^† · ( x(t+1) − f(x(t), u(t)) )`，`B_d^†` 为 Moore–Penrose 伪逆
- 回归输入 `z(t) = [x(t)^T, u(t)^T]^T`

### 2.2 公式：轮廓 / lag 误差分解（Eq. 6–7）

```
e(θ_k)  = p(θ_k) − p_k
e^l(θ_k) = ( t(θ_k)^T e(θ_k) ) · t(θ_k) = e^l(θ_k) · t(θ_k)     ← 切向（lag）
e^c(θ_k) = e(θ_k) − e^l(θ_k) · t(θ_k)                            ← 法平面（contouring）
```

**直觉**：`e^l` 是"落后/超前"，`e^c` 是"跑偏"。MPCC 只惩罚跑偏，落后用 `e_{v_θ} = v_{θ,ref} − v_θ` 与 `v_{θ,ref} ≫ v̄_θ` 来奖励进度（保持代价凸、改善 solver 行为）。

### 2.3 公式：GP 后验（Eq. 10）

```
μ^g(z*) = K_{z*,z} (K_{z,z} + σ_n² I)^{-1} y
Σ^g(z*) = K_{z*,z*} − K_{z*,z} (K_{z,z} + σ_n² I)^{-1} K_{z,z*}
```

核为 SE + ARD，超参由边际似然最大化确定；每个体速度通道一个独立 GP。

### 2.4 公式：不确定度传播与收紧（Eq. 12–14）

```
Ψ_k(μ_k,u_k,Σ_k) = A_k Σ_k A_k^T + B_d Σ^g(μ_k,u_k) B_d^T + Σ_w
A_k = ∂f/∂x + B_d ∂μ^g/∂x |_{x=μ_k}
β_i = γ √( ∇h_i^T Σ_k ∇h_i )     ← 每个约束一个标量 back-off，γ 控置信度
```

`zoRO` 的关键替换（Eq. 14）：把 `Σ_k` 从**决策变量**降级为**基于上一解 `(μ̂_k, û_k)` 的前馈量**，在 SQP 迭代之外传播。于是优化问题回到 Eq. 8 的同构形式（少一条协方差动力学、`β̂_k` 变常数），可复用同一 SQP 机制。

### 2.5 变量说明

| 符号 | 含义 |
|---|---|
| `η = [x,y,z,q^T]^T` | 世界系位姿；姿态用单位四元数（避免奇异），体轴为 FRD（深度 z 向下为正） |
| `ν = [u,v,w,p,q,r]^T` | 体轴速度：线速度 u/v/w，角速率 p/q/r |
| `τ` | 归一化体轴广义力（送机载做推力分配） |
| `θ, v_θ, Δv_θ` | 路径弧长、进度速度（虚拟状态）、进度加速度（决策变量） |
| `Q_c, Q_l, Q_v, Q_q, Q_Δq, R` | 轮廓 / lag / 进度 / 姿态 / 姿态变化率 / 输入变化率的权重 |
| `h(x)=‖e_c‖−r ≤ 0` | 走廊约束：偏离中心线的半径 `r` |
| `β_i, γ` | 约束收紧量、置信度系数 |

## 3 · 带数字走一遍（玩具设定，非论文数据）

**场景**：圆形路径半径 2 m，当前弧长处 `p(θ_k) = (2cos45°, 2sin45°) ≈ (1.414, 1.414)`，切向 `t(θ_k) = (−sin45°, cos45°) ≈ (−0.707, 0.707)`。AUV 实际位置 `p_k = (1.6, 1.3)`。

**Step 1 — 原始位置误差**
```
e = p(θ_k) − p_k = (1.414−1.600, 1.414−1.300) = (−0.186, +0.114)
‖e‖ = √(0.0346 + 0.0130) = 0.218 m
```

**Step 2 — 分解**
```
e^l = t^T e = (−0.707)(−0.186) + (0.707)(0.114) = 0.1315 + 0.0806 = 0.212 m
e^c = e − 0.212·t = (−0.186 + 0.150, 0.114 − 0.150) = (−0.036, −0.036)
‖e^c‖ = √(0.0013 + 0.0013) = 0.051 m
```

**解读（这就是 MPCC 的立场）**：0.218 m 的"误差"里有 0.212 m 是**沿路径落后**——这部分 MPCC 不罚，它会让 `v_θ` 涨上去追；真正被惩罚的只有 0.051 m 的横向偏差。对比一个跟踪时间参数化参考的 MPC：它会把 0.218 m 全罚，于是为了"追上时间戳"而猛推，反而在弯道处切内线、姿态抖。

**Step 3 — 约束收紧**

走廊约束 `h(μ_k) = ‖e^c‖ − r`，`r = 0.15 m`。取 `γ = 3`（约 3σ），设沿 `∇h` 方向的预测标准差为 `σ = 0.02 m`：
```
β̂ = γ·√(∇h^T Σ̂ ∇h) = 3 × 0.02 = 0.06 m
有效半径 = r − β̂ = 0.15 − 0.06 = 0.09 m
```
**解读**：GP 越不确定，可行走廊越窄，控制器越保守——这正是把"模型不知道"翻译成"行为更谨慎"的那一步。注意 `zoRO` 的代价：`Σ̂` 来自上一解，所以收紧量有一拍延迟。

**Step 4 — 实时预算（算术推导，UNVERIFIED）**
```
1 / 25 Hz = 40 ms 每次求解
40 ms / N=40 steps = 1 ms 每预测步
```
即：**每个 horizon 步平均只有 1 ms 完成"GP 均值 + 雅可比求值 + 一次 SQP 迭代"**。这就是为什么必须 RTI 单迭代 + 100 点稀疏 GP。

## 4 · 工程视角

| 维度 | 论文报告值 | 备注 |
|---|---|---|
| 控制频率 | **25 Hz** | 摘要明示 "keeps the controller real-time capable at 25 Hz" |
| 预测时域 | **N = 40** | 每采样周期 **1 次 SQP 迭代**（RTI），上一解 warm start |
| 求解器 | acados（标称 MPCC）+ **L4acados**（GP-MPCC 的 zoRO 实现） | GP 均值与雅可比在**求解器外部**求值后传入 |
| 计算平台 | Ubuntu 24.04 笔记本，**Intel i7 CPU，64 GB RAM** | MPCC 跑在**水面（topside）**，不在载体上 |
| 机载算力 | **NVIDIA Orin NX** | 只跑 EKF 状态估计（IMU + 压力 + DVL）；GP/MPCC 不在机上 |
| 通信 | LCM | 仿真与实船同一条管线，仅"vehicle interface"不同 |
| GP 规模 | 每 GP **100 个均匀子采样点**，6 个独立 GP（SE + ARD，GPyTorch） | 只取 100 点是为"保持在实时预算内" |
| 单次求解耗时 (ms) | **论文未报告** | 全文只给 25 Hz 的达成结论，未给 per-solve 时间 |
| GPU / VRAM | **论文未报告** | 全文未提及 GPU 参与推理 |
| 通信链路延迟 | **论文未报告** | 由于控制在水面、执行在载体，这是隐性风险（见 §8） |

**Trade-off 结构（这是本文真正的工程张力）**

1. **实时性 ↔ 不确定度严谨性**：Eq. 11 原式把 `Σ_k` 当决策变量，"computationally expensive"；zoRO 把它挪出去 → 回到同构问题、可复用求解器机制，但收紧量基于**上一解**，是前馈近似。
2. **覆盖率 ↔ 推理成本**：100 点子采样是硬预算下的选择。点少 → 后验方差在覆盖稀疏处变大 → `β̂` 变大 → 走廊更窄 → 跟踪更保守（这是一种"安全降级"，不是崩溃）。
3. **模型精度 ↔ 学习风险**：`gp-full` 的实验说明"多学"不是免费的——噪声被当成动力学学进去，闭环振荡。**加学习成分必须能证明它在信号层面有结构**（论文用 Fig. 4 直接给证据：线性残差在噪声底，角速率残差有结构）。
4. **机载 vs 水面**：控制器在水面笔记本上，意味着系统**不是完全自主的**，依赖通信链路。这对"检测脆弱水下结构"这类任务的失效后果很敏感（论文未量化链路中断行为）。
5. **6-DoF 的代价**：全状态 + 姿态四元数 + `Δq` 软角速率限制 + `Δu` 平滑项，都在同一个 NLP 里，是 3-DoF 方案算力的数倍——25 Hz 是"笔记本 + RTI 单迭代 + 稀疏 GP"三者共同换来的。

## 5 · 数据与评测

### 5.1 训练数据（残差学习）

- **采集方式**：**开环**激励。先对每个轴单独、逐步加大激励幅值，再做**耦合**激励。
- **标签构造**：`y(t) = B_d^† (x(t+1) − f(x(t), u(t)))`（Eq. 9），回归输入 `z=[x^T, u^T]^T`。
- **规模**：子采样到**每个 GP 100 个均匀分布数据点**。
- **模型**：6 个体速度通道各一个独立 GP，SE 核 + ARD，GPyTorch 实现；`B_d` 相应选择速度状态。
- **关键工程细节**：**仿真与真机各训一套模型**（"Separate models are trained on the same maneuvers for the simulation and for the real vehicle"）。
- **论文图 4 的定性发现**：线速度（surge）残差"dominated by measurement noise"；roll 角速率残差有清晰结构、GP 抓得住 → 决定了后续只用角速率残差。

### 5.2 评测设置

| 项 | 内容 |
|---|---|
| 仿真器 | **Stonefish** |
| 真机 | **MOLA AUV**（MBARI），外形近似 BlueROV2；无该机辨识水动力模型，标称模型参数取已知重量 + **BlueROV2 系数**（引 [7]，如 [33] 所用） |
| 传感与估计 | IMU + 压力传感器 + DVL，由 **EKF** 在机载 **NVIDIA Orin NX** 上融合 |
| 试验场地 | **13 × 9 × 10 m** 盐水试验池 |
| 场景 1 | 恒定航向 **lawnmower pattern**（测绘常用）；仿真 5 runs/控制器（`nom` / `gp-pqr` / `gp-full`）；实船 5 runs/控制器（`nom` / `gp-pqr` / PID） |
| 场景 2 | **向上 inspection spiral**（绕虚拟目标、持续增大俯仰、始终指向中心）；仿真 10 runs/控制器（`nom` / `gp-pqr`）；实船作为最终 deployability 测试 |
| 指标 1 | **位置 RMSE**：对每个记录状态求样条上最近点 `θ*_i = argmin_θ ‖p(θ) − p_i‖₂`，取 `‖e_{p,i}‖₂` 的 RMSE |
| 指标 2 | **姿态 RMSE**：误差四元数旋转角 `φ_i = 2 arccos|e_{q,i,w}|` 的 RMSE |
| 指标 3 | **控制能量**：`Σ_i ‖τ‖_i`（指令绝对量之和，作能耗 proxy） |
| 调参声明 | MPCC 权重经验调好后**仿真与实船保持一致** |

### 5.3 结果（逐字数值）

**仿真 · lawnmower（Fig. 5）**
- `gp-pqr`：姿态 RMSE `0.81°` → `0.55°`（**32%**）改善；位置 RMSE 保持 `0.06 m` 不变；控制能量不变。
- `gp-full`：位置误差、姿态误差、控制能量**大致翻倍**，轨迹明显在参考附近振荡。

**仿真 · inspection spiral（Fig. 6）**
- `nom`：姿态 RMSE 从 `8°` 到 `48°`，均值 `31°` —— 无法稳定保持指令姿态。
- `gp-pqr`：姿态 RMSE `4.5°`；位置 RMSE `0.048 m` → `0.043 m`；控制能量降低 **6%**。

**实船 · lawnmower（Fig. 7）**
- PID：位置 RMSE `0.033 m`；姿态 RMSE `4.5°`。
- `nom` MPCC：位置 RMSE 与 PID 相同 `0.033 m`；姿态 RMSE `4.5°` → `3.2°`；控制能量略低。
- `gp-pqr`：姿态 RMSE 进一步降到 `2.4°`（相对 PID **47%**，相对 `nom` **25%**）；代价是位置 RMSE 升到 `0.040 m`，控制能量比 `nom` 高 **28%**。论文归因于控制动作更激进，并指出"权重全程不变，加大输入变化率权重可缓解"。

**实船 · inspection spiral（Fig. 8）**：`nom` 与 `gp-pqr` 都紧贴螺旋参考；PID 逐 DoF 朝下一个 waypoint 规整，呈分段运动，不构成预期检测路径 → 论文明确"quantitative comparison is not meaningful"。

**结论段的两句总结性数字**：补偿角速率残差"halves the attitude error of a field-proven PID controller"（对应 4.5°→2.4°）；仿真的螺旋上"reduces the attitude error of the nominal MPCC by **85%**"（对应 31° → 4.5°）"at a lower control energy"。

## 6 · 能力与失败模式

### 能做（具体）

- **6-DoF 同时跟踪位置与姿态**，且姿态与行进方向解耦——这是 holonomic 推进的直接红利，torpedo 型 AUV 与多数 3-DoF MPC 都做不到。
- **几何路径跟踪而非时间戳跟踪**：`θ`、`v_θ` 作为决策变量，速度剖面由优化决定，弯道不变"切内线"。
- **硬约束处理**：状态约束 `h(x)=‖e_c‖−r ≤ 0`、输入上下界、`v_θ ≥ 0`、`Δv_θ` 界——PID 原理上做不到（论文明确点出）。
- **实时**：25 Hz、`N=40`、单步 SQP。
- **实船验证**：盐水池中 lawnmower 5 runs/控制器，加一次螺旋 inspection；相对**多次外场部署成熟**的 PID 仍拿到姿态优势。
- **工程投入对比**：论文指出 MPCC 系控制器的集成与调参耗时"considerably less"于 PID。

### 不能做 / 失败模式（具体）

1. **全通道残差学习会主动变差**：`gp-full` 在仿真 lawnmower 上把位置误差、姿态误差、控制能量**一起翻倍**，轨迹可见振荡。机制清楚：线性通道残差在噪声底（Fig. 4），GP 把噪声拟合成了"动力学"。
2. **收益强依赖机动复杂度**：lawnmower（恒定姿态）上收益"moderate"（0.81°→0.55°）；螺旋（连续变姿态）上收益"substantial"（31°→4.5°）。换句话说——**姿态通道的模型失配只有在姿态真被激励时才暴露**。
3. **位置精度可能被牺牲**：实船 `gp-pqr` 位置 RMSE `0.040 m` 劣于 `nom`/PID 的 `0.033 m`，控制能量高 28%。权重全程固定，没有为 GP 版本重调。
4. **时不变模型**：GP 离线训练、部署期间不更新。论文自己把 online learning / active learning 列为未来工作，并说"online learning becomes crucial during longer deployments"。
5. **无海流**：显式假设 `ν_c = 0`、`ν_r = ν`。任何恒定流都会被 GP"吸收"成状态相关偏置，条件一变即失配。
6. **状态估计误差不入环**：`Σ_w` 与 GP 方差之外，EKF 的位姿/速度不确定度没有进入 `Σ_k` 传播；论文把"incorporating this uncertainty"列为扩展方向。
7. **无避障 / 无海床约束**：走廊约束只有 `‖e_c‖ ≤ r`，论文将 obstacle avoidance 与 seafloor 列为 future capabilities。
8. **PID 在螺旋上无法定量对比**：不是"赢了没数字"，而是对比本身不成立（PID 不跟样条）。
9. **单载体单场地**：只有 MOLA、只有一个 13×9×10 m 水池；跨载体泛化未验证（且仿真与真机需各自训练）。

### 隐含假设 (Hidden Assumptions)

- **H1 · 标称模型"错得有限且结构性可学"**：直接沿用 BlueROV2 系数 + 已知重量来参数化 `f`。若换了推进器布局、加了机械臂或大载荷，残差的**结构**会变，不是"再训一次"就能解决（论文已说明参数随 payload 变化）。
- **H2 · 残差只作用在 6 个体速度通道**：`B_d` + 伪逆把一切未建模效应投影到 `ν̇`。若误差在**运动学/测量层**（DVL 安装偏角、时间同步、四元数约定 FRD vs FLU），GP 无法表达，只会把系统性偏差揉进速度残差。
- **H3 · 训练分布 ≈ 部署分布**：开环激励数据来自低速、无流、单池的机动；外推到强流、高速、近壁（壁面效应）未验证。
- **H4 · 状态测量≈真值**：训练标签由相邻状态差 `x(t+1) − f(...)` 得到，EKF 的任何偏差/延迟都会同时污染标签与在线输入。这是"自监督标签来自估计器"的经典循环。
- **H5 · 机体对称 + 对角阻尼 `D`**：交叉耦合阻尼项被结构性地丢掉；这些项被丢给了 GP 去补，但 GP 输入是 `[x;u]`，能否在 100 点预算内表达交叉耦合是未验证的。
- **H6 · 单次 RTI 迭代"够用"**：25 Hz 下每步只做一次 SQP 迭代，收敛性由 warm start 与问题光滑性兜底；`gp-pqr` 引入 GP 后雅可比更复杂，这个假设的压力更大。
- **H7 · 稀疏 GP 的方差是可信的**：`β̂` 完全由 `Σ^g` 决定。100 点 SE-ARD 在远离训练数据处的方差是**核的假设**，不是真实误差的界——收紧量的"物理意义"弱于其"经验效果"。
- **H8 · 时间预算可迁移**：25 Hz 是"水面 Intel i7 笔记本 + topside 执行"达成的，不等于机载 Orin NX 也能达成。
- **H9 · 通信链路可用**：控制回路跨"水面↔水下"闭合，链路质量未在指标中体现。

## 7 · 与相关工作对比

| 方法 | DoF | 参考类型 | 学习成分 | 不确定度处理 | 验证级别 |
|---|---|---|---|---|---|
| PID（本文基线） | 各 DoF 独立 | waypoint 序列（pose setpoint） | 无 | 无 | 多次外场部署成熟；本文池中 lawnmower 5 runs |
| 标称 MPCC（本文 `nom`） | **6** | 几何样条 + SLERP 姿态 | 无 | 无（仅 `Σ_w`） | 仿真 + 实船 |
| **GP-MPCC（本文 `gp-pqr`）** | **6** | 同上 | 3 个角速率通道 GP 残差 | **zoRO 方差→约束 back-off** | 仿真 + 实船（本文主张：首次 6-DoF MPCC 实船实时） |
| `gp-full`（本文消融） | 6 | 同上 | 6 个通道 GP 残差 | 同上 | 仿真（结论：性能翻倍恶化） |
| GP 预测 ROV 扰动 [1] | 4 | 时间参数化 | GP 扰动预测 | 有（GP） | 靠复原力矩降阶到 4-DoF |
| 残差方法对比 [2] | 降阶 | 时间参数化（**LTV-MPC**） | GP 残差最优，**只学 damping** | — | **纯仿真** |
| 全状态 MPC [37] | 6 | 时间参数化 | 无 | 无 | **纯仿真** |
| 3D MPCC（飞行）[17,25] | 位置 + 偏航 | 几何路径 | 无 | 无 | 无人机 |
| 全驱动 ROV 作业/对接 [9,33,35] | 位置（+heading） | waypoint / 时间参数化 | 无 | 无 | 实验/仿真 |

**相对 [2] 的三点增量**（本文明确"build upon [2]"）：① 残差**不限于** damping 项；② 从 LTV-MPC 升到**非线性 6-DoF MPCC**，并叠加姿态参考；③ 从纯仿真到**实船 25 Hz**。
**相对 [25] 的增量**：把 3D 飞行 MPCC 的“几何路径 + 进度变量”骨架搬到水下，并利用 holonomic 特性额外加姿态跟踪项 `e_q` 与 `Δq`。

### 🎤 面试 Tip

被问"这篇和已有的 GP-MPC / 学习增强 MPC 有什么本质不同"，三句话答完：

> "第一，它是 **contouring** 不是 tracking——优化的是到样条的横向偏差 + 沿路径进度，所以参考不需要时间参数化，速度剖面是优化出来的。第二，GP **只学角速率残差**，这不是调参技巧而是有实验支撑的设计决策：线速度残差在噪声底，学了反而让误差翻倍。第三，GP 的方差不是拿来看的，是通过 **zoRO** 变成一个标量约束收紧量 `β̂ = γ√(∇h^T Σ ∇h)` 进入实时 SQP——而且这步被挪出 SQP 迭代，所以问题结构与标称 MPCC 同构，25 Hz 跑得动。"

追问"局限在哪"就答：离线时不变 GP、假设无海流、状态估计不确定度不入传播、控制跑在水面笔记本上依赖通信——这几条论文自己都写在结论的未来工作里。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-11-11)

**诚实声明**：论文全文**未给出任何代码仓库链接**（正文出现的 "Report GitHub Issue" 属于 arXiv HTML 页面 chrome，非作者仓库）。因此本节**无 issue 流可验证**，以下 4 条 pitfall 全部由 §6 的失败模式 + §5/§1 的方法约束**机制性推导**得到，标注 `未验证`。论文本身为 CC BY 4.0，且作者按 IEEE AI 生成内容政策披露使用 Claude 做"coding assistance during the implementation"与语言润色——复现时不应假设存在可直接对齐的参考实现。

---

**P1 · 照直觉"每个 DoF 都学"，会得到更差的控制器，然后误判为 bug**
- 来自 §6 失败模式 1：`gp-full` 在仿真 lawnmower 上位置与姿态误差、控制能量**大致翻倍**，轨迹可见振荡。
- 来自方法约束：GP 训练标签 `y = B_d^†(x(t+1) − f(x,u))` 由相邻状态差构造，线速度通道的残差被测量噪声主导（论文 Fig. 4 明示"dominated by measurement noise and offers little structure"）。
- 落地后果：复现者按"6 个通道 = 6 个 GP，全都开"的对称直觉实现，闭环出现振荡，会去怀疑 GPyTorch 版本、核超参、`B_d` 定义，而真正的问题是残差通道选择。**验证动作**：先画每个通道的"预测 vs 目标"曲线，只保留有结构的通道。

**P2 · 仿真训的 GP 直接上真机，性能退化且无告警**
- 来自 §6 失败模式 4/隐含假设 H3：模型离线、时不变、训练分布≈部署分布。
- 来自方法约束：论文明确"Separate models are trained on the same maneuvers for the simulation and for the real vehicle"——即**官方流程就是两套模型**。
- 落地后果：跨域直接加载仿真 GP，`μ^g` 系统性偏移 + `Σ^g` 在真机状态空间处不可信 → `β̂` 错位（可能过紧导致跟踪迟缓，也可能过松失去鲁棒性）。这不是崩溃型 bug，是最难查的"性能不对但跑得动"。**验证动作**：在真机上先跑开环激励、重算残差标签、对比两套 GP 的均值差。

**P3 · 训练点数改动会通过 `β̂` 悄悄改变闭环可行域**
- 来自 §6 失败模式（隐含假设 H7）：`β̂ = γ√(∇h^T Σ ∇h)`，收紧量完全由 GP 后验方差决定。
- 来自方法约束：论文把每 GP 子采样到 **100 个均匀分布点**，理由是"keeps the inference cost within the real-time budget"。
- 落地后果：为了"更准"而用全量数据 → 单次求解超 40 ms 预算、掉出 25 Hz；为了"更快"而用 50 点 → 覆盖稀疏处方差虚高 → 走廊被过度收紧 → 位置误差上升、`v_θ` 上不去，表现为"控制器变胆小"。两个方向都不报错。**验证动作**：固定机动，扫 &#123;50, 100, 200&#125; 点，同时记录 `β̂` 分布与 per-solve 耗时——**注意 per-solve 耗时论文未报告，需要自己测**。

**P4 · 求解器版本耦合 + 外部雅可比，是最可能的复现墙**
- 来自 §6 失败模式（隐含假设 H6）：25 Hz 靠 RTI **单次 SQP 迭代** + warm start 达成，对问题光滑性与雅可比一致性极敏感。
- 来自方法约束：论文明确 GP 均值与雅可比在求解器**外部**求值后传入（"the GP mean and its Jacobian are evaluated externally and passed to the solver"），栈为 `acados` + **`L4acados`**，且 `L4acados` 是实现 zoRO 的关键组件。
- 落地后果：`acados` 与 `L4acados` 版本不匹配、或 GP 雅可比用数值差分（与外部求值的均值不自洽）时，单步 RTI 没有第二次迭代来纠错，表现为求解器返回次优/不可行、控制量抖动，而日志上看不出"是雅可比错了"。**验证动作**：对 `μ^g` 的解析雅可比做有限差分校验，并先用 `nom`（无 GP）路径确认 `acados` 基础回路 25 Hz 通得过，再接 `L4acados`。
- **附带约束**：控制回路跨"水面笔记本 ↔ 水下载体"（LCM），论文未报告链路延迟与丢包行为 → **不要在机载 Orin NX 上直接假设可复现 25 Hz**（`UNVERIFIED`）。
