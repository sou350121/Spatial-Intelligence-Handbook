# ERA：误差鲁棒的无深度传感器自主物体导航 (ERA: Error-Resistant Autonomous Object Navigation with Predicted Depth)

> **发布时间**：2026-11-13（arXiv:2611.17730v1 [cs.RO]）
> **论文 / 模型名**：ERA（Error-Resistant Autonomous Object Navigation with Predicted Depth），其方法论范式自称 **Move with Error**
> **核心定位**：把"深度传感器换成预测深度"从**精度问题**重新定义为**闭环控制问题**——用「可撤销占据栅格 + 可达视点探索」把 VLFM 在预测深度下的成功率从 10.8% 拉回 61.7%，并在无深度传感器的 training-free 方法中做到三个 benchmark 上的 SOTA。
>
> 深度基础模型（Depth Anything 3 / VGGT）能仅凭 RGB + 位姿给出 metric depth，看似让 ObjectNav 摆脱深度传感器；但论文实测发现：把预测深度**当作传感器深度来建图**，同表面的视角相关误差会累积成"变厚的障碍"，把通路封死、把 frontier 抹掉，于是 agent 在还没来得及获得纠错视角时就宣布搜索结束。ERA 的答案是让**移动本身成为纠错手段**。

---

## X-Ray 开场

这篇论文问了一个很朴素但此前没人正面处理的问题：**当 agent 赖以规划的三维几何注定不完美时，导航系统该怎么设计？** 它没有去卷更准的深度模型（DA3 全程冻结、不改一行），而是指出失败链条是「误差累积 → 障碍变厚 → frontier 消失 → 提前终止 → 再也拿不到能纠错的新视角」，这是一个**循环依赖**。ERA 用两个耦合机制打破它（可撤销占据 + 从可达自由空间选视点），使"移动"与"改图"互为因果。对 spatial AI 研究者的意义是：**在 learned geometry 时代，下游系统的鲁棒性可以来自"消费几何的方式"，而不是"几何本身的质量"**——同一份预测深度，仅换更新规则与探索目标定义，SR 提升 50 个百分点量级。

**本文的历史位置**：它是"RGB-only ObjectNav"这条线上第一个把**地图更新的可撤销性**当作一等公民来设计的系统，而不是把预测深度塞进旧管线再抱怨精度。局限也很清楚：真值位姿、training-free 但冻结模型巨大、以及"在已观测自由空间里兜圈"带来的路径效率代价。

## 1 · 核心架构 / 方法总览

### 1.1 系统组件对比表

| 模块 | 输入 | 输出 | 训练/推理差异 | 相对 VLFM/L3MVN 的关键改动 |
|---|---|---|---|---|
| 深度预测（冻结 DA3） | 当前 RGB、**近期关键帧**、内参 K、位姿 T | metric depth `D̂_t` + confidence `C_t` | 完全 off-the-shelf，无微调 | 无改动（本文刻意不动） |
| 感知（冻结 C-RADIOv4 + SigLIP2 adaptor + SAM 3 head） | RGB | goal-conditioned 图像-文本相似度、goal/相似类 mask | 冻结 | 无改动 |
| **可撤销占据（Revisable Occupancy, Move2Error）** | `D̂_t`、K、T、碰撞反馈、已走过的 footprint | 带符号证据 `e_m ∈ [-E, E]` 的 2D 栅格 | 解析更新，无学习 | ⚡ 与 VLFM/SemExp/SG-Nav 的"只增不减"不同；与 L3MVN"仅当前帧清空"、ApexNav"障碍权重压倒自由"不同 |
| **可达视点探索（Error2Move）** | 可通行空间 `F_t`、value map、未知区域可见量 | 下一个视点 `v*_t` | 解析打分，无学习 | ⚡ 候选集合**不要求**贴未知边界（非 frontier） |
| 目标校验（Target Verification） | 候选表面 `P_c`、观测历史 `H_c`、当前 view | Stop / 换位再观测 | 解析 + 冻结检测器 | 多视角一致性门槛，不只靠语义分 |
| 规划执行 | `F_t`、目标点 | 离散动作（前进 0.25 m / 左右转 30°） | 距离场规划器 | 复用经典做法 |

### 1.2 关键机制

**⚡ Eureka Moment：把占据栅格从"证据累加器"改成"有界可撤销状态"，于是"走到新视角"本身就成了一种地图修正操作——移动即纠错 (Move with Error)。**

拆开说是两条互相咬合的因果链：

- **Move2Error**：新观测若在旧障碍处看到自由空间，必须能**推翻**旧估计。所以证据必须**有界**（`E` 封顶），否则累积的障碍证据永远压不过自由证据；更新必须**非对称**（新障碍立刻转正，因为 `max(0, e_m)` 先把负证据夹到 0），保证"真障碍"仍能被快速记上。
- **Error2Move**：即使地图可撤销，论文实测**近一半帧**里可撤销地图仍然没有任何"可达 frontier"（Fig. 2a）。所以探索目标必须从「free/unknown 边界」放宽到「**所有可达已知自由空间**」，让 agent 能绕回已建图区域换个视角看——这正是能触发 Move2Error 的前提。

单独任何一个都不成立：地图可撤销但没目标 → 走不动；能继续走但地图不可撤销 → 走了也白走，误差继续叠。**这是一个必须成对出现的机制。**

```
        RGB I_t ──┬──────────────────────────────┐
```

## 2 · 数学核心

### 📌 Napkin Formula

```
e_m ← clip[-E, E]( e_m ± δ )      ← 证据有界，所以可被推翻
predicted occupied  ⟺  e_m > 0     ← 一个符号，不是概率累加
v* = argmax_{v ∈ 可达自由空间} G(v) - C(v)   ← 候选集合去掉 "必须贴未知" 这个约束
```

**一句话**：用**有界符号证据**替代无限累加，用**可达自由空间**替代 frontier。

---

**目标 1：让新证据能撤销旧障碍（式 1）**

```
        ⎧ min(E, max(0, e_m) + δ)    障碍观测
e_m  ←  ⎨ max(-E, e_m - δ)           自由观测
        ⎩ e_m                         否则
```

- `E > 0`：证据上界；`δ > 0`：单次更新幅度；`e_m ∈ [-E, E]`，初值 0。
- 另有 `observed` 标志位，用来区分"未知"与"自由"。
- **直觉/为什么长这样**：
  - `max(0, e_m)` 这一步是**非对称的核心**：不管此前多"自由"（`e_m` 多负），一次障碍观测都能立刻让 `e_m` 变正 → 新障碍立即生效。
  - `min(E, ·)` 是**可撤销的核心**：障碍证据不能无限涨，否则"错一次就永久封路"。
  - 取 `δ = E/2` 时有漂亮的手感：**1 次**自由观测可清掉由 **1 次**障碍观测支撑的格子；**2 次**连续自由观测可清掉**饱和**的障碍证据。

**目标 2：把"可达"写进规划空间（式 2）**

```
B_t = {m : e_m > 0} ∪ K_t                    （blocked：占据 + 接触障碍）
F_t = {m ∈ O_t : dist(m, B_t) > r}           （traversable：已观测且有余量 r）
```

`O_t` 为已观测格子，`K_t` 为前向动作失败时写入的 contact-obstacle 集合（沿用 Stubborn），`r` 为 agent 半径。要点：`F_t` 是**动态**的——撤销一个预测障碍就能让一条路线重新开通。

**目标 3：视点选择（式 3）**

```
V_t = { v ∈ F_t : ρ_min ≤ ρ_t(v) ≤ ρ_max },    ρ_t(v) = 沿 F_t 的最短路长度（不可达为 ∞）
v*_t = argmax_{v ∈ V_t} G(v) - C(v)
```

`G(v)` = 从 v 可见的未知空间 + value map 里的图像-文本相似度 + v 所在区域的未覆盖程度；`C(v)` = 路径长度 + 障碍余量太小 + 重复访问的惩罚。**关键限定**：可见未知空间**只参与排序，不参与候选资格**——这正是 Error2Move 与 frontier exploration 的分水岭。

**目标 4：候选语义分更新（式 4）**

```
b_c ← clip[-b_max, b_max]( b_c + w(ℓ_c⁺ - ℓ_c⁻) + a_c - m_c )
```

`ℓ⁺/ℓ⁻` 为目标类/相似类检测的有界强度，`a_c` 为候选与目标 vs 相似类的相似度对比项，`m_c` 惩罚"看得很清楚但没有目标检测"。表面估计 `P_c` 是**替换**而非融合（旧表面留在 `H_c` 里供多视角校验），因为论文 §C.3 的观察是：**近邻视角的深度误差是相关的，靠凑近才能降低绝对误差**。

## 3 · 带数字走一遍（玩具设定）

取 `E = 2`、`δ = E/2 = 1`。关注走廊里一个格子 `m`。

| 步 | 事件 | 计算 | `e_m` | 是否 predicted occupied (`e_m>0`) |
|---|---|---|---|---|
| 0 | 初始未知 | — | 0 | 否（但 `observed=False`） |
| 1 | 预测深度在此处投出一条"薄障碍" | `min(2, max(0,0)+1)` | **+1** | **是** → 通路被封 |
| 2 | 同表面另一视角把障碍投得略远，本格变成自由射线经过 | `max(-2, 1-1)` | **0** | 否 → **通路重新开通** |
| 3 | 再来一次自由观测（若第 1 步预测更"猛"，直接饱和） | `max(-2, 0-1)` | **-1** | 否 |
| 4 | 又一条错误障碍预测 | `min(2, max(0,-1)+1)` | **+1** | **是** ← 注意：非对称性让它**立刻转正** |
| 5-6 | 连续两次自由观测 | `+1 -1 → 0 -1 → -1` | -1 | 否 |

对比"只增不减"的 VLFM 风格更新：第 1 步之后 `e_m` 只增不减，第 4 步再叠加就变成"厚障碍"，即使后续 10 次自由观测也压不下去 → 这个格子永久封路 → 如果它恰好卡在唯一通路上，`F_t` 被割断 → `V_t` 里的候选全部 `ρ_t = ∞` → 探索终止。

**再看饱和清空的手感**：若第 1 步连续被 2 次障碍观测命中，`e_m = 2 = E`（饱和）。此时恢复需要 `2 → 1 → 0`，即 **2 次**连续自由观测——这就是为什么"走两步换个角度"在实验里比"原地多看一眼"更有用。

> 以上为玩具设定（`E=2` 是为算术清爽），论文未在正文给出 `E`、`δ`、`ρ_min`、`ρ_max`、`r` 的具体取值（附录 B 有 Occupancy update / Exploration score 细节，本笔记所用全文片段中未包含数值）。

## 4 · 工程视角

| 维度 | 论文所述 | 备注 |
|---|---|---|
| 观测规格 | `640×480` RGB，水平 FOV `79°` | 单目 |
| 动作原语 | 前进 `0.25 m`，转向 `30°`（离散） | 无 strafe / 无速度控制 |
| 单 episode 预算 | 最多 `500` 步 | 折算上界约 125 m 直线位移（本笔记算术，非论文数字） |
| 深度模型 | DA3 `DA3NESTED-GIANT-LARGE`（冻结，nested giant-large 变体）；对比实验替换为 VGGT | 每步喂"当前图 + 近期关键帧 + K + T"，**每步不止一次前向** |
| 感知模型 | C-RADIOv4 + SigLIP2 adaptor + SAM 3 head（冻结） | 三个大模型常驻显存 |
| 实验硬件 | **two NVIDIA A100 GPUs** | 这是**实验**配置，不是机器人本体配置 |
| 真机平台 | AgiBot Genie G1 轮式人形；仅用头部 RGB + 轮式里程计位姿，**不使用任何深度传感器** | 机载算力型号与功耗：论文未报告 |
| Latency / FPS / VRAM / 吞吐 | **论文正文未报告**（附录 D.2 有 Runtime 一节，本笔记所据片段未含数值） | 不做估算填空 |
| 主要计算瓶颈（结构性推断） | 每步一次多关键帧 DA3 前向 + 一次感知前向；栅格更新与视点打分是解析的、可忽略 | 需在真机上核实，`UNVERIFIED` |

**Trade-off 梳理**：

1. **鲁棒性 ↔ 路径效率**。论文明确承认："continuing the search from mapped space can lengthen the path to the goal"。数据侧也有呼应：HM3D v2 上 ERA 的 SR `70.1` 但 SPL `30.6` &lt; VLFM(传感器深度) 的 `34.5`；消融里"frontier goals only + 传感器深度"的 SPL `33.9` 反而高于 full 的 `33.7`。也就是说：**这份鲁棒性是用 SPL 买的**，而 SPL 在真机部署里直接等于能耗与时间。
2. **有界证据 ↔ 遗忘速度**。`E` 与 `δ = E/2` 的选择等价于"容忍多少次一致的错误预测"。`E` 太小 → 真障碍（玻璃、细腿椅、低矮踢脚）也会被自由射线抹掉；`E` 太大 → 退化成 VLFM 的只增不减。
3. **接触障碍 `K_t` 的粘性**。`K_t` 里的格子**不能被视觉证据清除，只能靠 agent 中心穿过**。这在工程上是双刃：防止"地图自己把墙删了然后撞墙"，但一旦碰撞反馈误报，就留下永久幽灵障碍。
4. **多视角校验 ↔ 步数**。校验不通过时要"移动到另一个可达位置再转回来"，这会消耗 500 步预算；论文用 verification budget 兜底，超了退回 exploration。

## 5 · 数据与评测

**仿真 benchmark（Habitat simulator）**，均使用 **validation split**：

| Benchmark | episode 数 | scene 数 | 目标类别数 |
|---|---|---|---|
| HM3D v1 | `2,000` | `20` | `six`（6） |
| HM3D v2 | `1,000` | `36` | `six`（6） |
| MP3D | `2,195` | `11` | `21` |

**指标**：SR（Stop 时距目标物体 `1 m` 内的 episode 比例）、SPL（成功且考虑路径效率），单位 %。协议"Following [1]"。

**主结果（Table 2，SR / SPL）**——ERA 在"training-free 且无深度传感器"组内三项全为最优：

| Method | Depth sensor | Training-free | HM3D v1 | HM3D v2 | MP3D |
|---|---|---|---|---|---|
| VLFM | ✓ | ✓ | 52.5 / 30.4 | 68.2† / 34.5† | 36.4 / 17.5 |
| L3MVN | ✓ | ✓ | 50.4 / 23.1 | 63.2† / 27.5† | 34.9 / 14.5 |
| SG-Nav | ✓ | ✓ | 54.0 / 24.9 | 49.6 / 25.5 | 40.2 / 16.0 |
| UniGoal | ✓ | ✓ | 54.5 / 25.1 | – | 41.0 / 16.4 |
| PanoNav | ✗ | ✓ | 43.5 / 23.7 | – | – |
| RANGER | ✗ | ✓ | – | 42.7 / 17.8 | – |
| MVP-Nav† | ✗ | ✓ | 49.6 / 24.3 | 59.4 / 25.6 | 38.6 / 17.6 |
| **ERA** | ✗ | ✓ | **55.2 / 27.4** | **70.1 / 30.6** | **46.4 / 21.2** |

论文原话的方向性结论：在同组内 ERA 的 SR 与 SPL 三个 benchmark 全最优；相对最强的 MVP-Nav，**HM3D v2 上 SR 高出 `10.7` 个点**，HM3D v1 与 MP3D 上"by smaller margins"（正文未给具体差值）。与使用深度传感器的 training-free 方法相比亦有竞争力：**两个 HM3D 上只有 VLFM 的 SPL 更高，MP3D 上没有**。

| With sensor depth: ERA (full) | 70.7 | 33.7 |
| With sensor depth: frontier goals only | 66.2 | 33.9 |

解读条件很重要：关键对比不是"掉多少"，而是**掉落在什么深度条件下**——"frontier goals only"在预测深度下从 `70.1` 掉到 `32.6`，但在**传感器深度**下只损失"不到五个点"（`70.7 → 66.2`）。这正是"可达视点在深度不可靠时才是必需品"的机制性证据。`w/o free-space clearing` 掉到 `13.9`，说明 Move2Error 是主承重墙，不是锦上添花。

**真机（Table 5，AgiBot Genie G1，大学走廊）**：三类物体（chair / trash can / plant），共 `12` 次运行，其中 `7` 次起始时目标不在视野内；`11 / 12` 次停止在 `1 m` 内（SR `91.7`）。同起点对照（两个垃圾桶摆放位置 × 三个起点）：Base `0 / 6`（SR `0`）、+revisable occupancy `1 / 6`（`16.7`）、+reachable viewpoints `6 / 6`（`100`）。Base 的失败原因被明确记为"每次都是因为没有任何可达 frontier 剩下"。

## 6 · 能力与失败模式

### 能做

- **在"只有 RGB + 位姿"的硬件上做 zero-shot ObjectNav**，模型全冻结、无导航训练、无 Goat/SoundSpaces 式微调。
- **系统级误差免疫**：不是让深度更准，而是让"深度错了也能继续搜"。机制在 DA3 与 VGGT 两种精度档位下都生效（Table 3）。
- **可迁移的组件**：把 revisable occupancy + reachable viewpoints 接到 VLFM / L3MVN 上，**不改其感知与控制器**，SR 从 `10.8` → `61.7`、`29.2` → `59.1`。
- **多视角 Stop 判定**：要求"另一个相机位置的早期观测与当前观测一致"才停，降低基于错误几何的误停。
- **真机闭环**：轮式人形 + 头部单目 + 轮式里程计，`11/12` 成功。

### 不能做 / 明确不覆盖

- **不做位姿估计**：结论段明写 "ERA relies on the poses provided by the platform"，并把 pose estimation 列为 future work。仿真里用的是 simulator 位姿。
- **不是"无几何"方法**：它坚持显式 metric 地图（对比 PixNav/PanoNav/Navi-Agent 的图像/拓扑空间），因此继承了地图的一切代价。
- **不保证路径效率**：在已观测自由空间里继续找视点会拉长路径，SPL 上有可见代价。
- **不做主动学习 / 不微调深度**：深度误差本身没有被减小，只被"消费方式"吸收。
- **迁移是半量的**：转移到 VLFM/L3MVN 时，"reachable-viewpoint selection only when their original exploration cannot supply an executable goal"——即只在原探索失效时兜底，不是完整替换。

### 隐含假设 (Hidden Assumptions)

1. **位姿基本正确**（含尺度）。整个 `F_t`、`ρ_t(v)`、footprint 重置都建立在 `T_t` 上；附录 D.1 只是"敏感性分析"，不是"在位姿漂移下的鲁棒性设计"。一旦漂移，`e_m = -E` 的 footprint 重置会**把自由证据写到错误的格子上**。
2. **metric 尺度可获得**。DA3 直接给 metric；VGGT 需要"已知相机高度"才能换算出 metric —— 隐含假设**相机高度已知且恒定**（对轮式人形成立，对腿式/手持不成立）。
3. **障碍位于"agent 身体高度带"内**。占据标记的规则是"反投影后落在身体高度范围内的点记为障碍"——越过这条带之上的悬空物、以及远低于它的低矮物，其可见性/可通行性判断都依赖这条带的设置。
4. **自由射线能终止在"已观测地面"上**。当画面中没有障碍时，free-space ray 以观测到的地面为终点；地面被遮挡/反光/纹理贫乏时，射线长度与"清空"范围会失真。
5. **同一区域"再走一次"能带来有效新信息**。Move with Error 的因果前提是"新视角会揭示错误障碍后面的自由空间"。若错误障碍恰好**围住**了一个区域（附录 A.2 专列了 Enclosure），换个视角也看不到里面，只能靠反复兜圈消耗预算。
6. **语义检测器足以支撑停止判定**。式 (4) 依赖 `ℓ⁺/ℓ⁻` 与相似类对比，`b_c` 的确认门槛直接决定误停/漏停；冻结的 SAM 3 head + SigLIP2 的类别覆盖范围就是系统的能力边界。
7. **碰撞反馈可信**。`K_t` 只能靠"agent 中心穿过"来解除——意味着一次误报的碰撞需要一次真实的穿越来偿还。

## 7 · 与相关工作对比

| 方法 | 几何表示 | 是否需要深度传感器 | 地图更新策略 | 探索目标 | 主要短板 |
|---|---|---|---|---|---|
| SemExp [6] | 语义地图 | 是 | 保留障碍 | frontier | 需深度；预测深度下未验证 |
| L3MVN [38] | 语义地图 + LLM 排序 | 是 | **仅当前帧清空** | frontier | 预测深度下 `29.2`；旧误差留存 |
| VLFM [37] | 2D 障碍图 + value map | 是 | **只增不减** | frontier | 预测深度下 `10.8`；障碍变厚封路 |
| ApexNav [40] | 概率占据 | 是 | 障碍权重大于自由 | frontier + 自适应 | 错误障碍清除过慢 |
| MVP-Nav [31] | 近期帧重建局部图 | 否 | 窗口内重建（丢弃旧几何） | frontier | 窗口内误差仍累积；旧几何丢失 |
| RANGER [39] | 关键帧重建融合占据 | 否 | 跨视角融合累积 | frontier | 跨视角误差累积 |
| PixNav [3] / PanoNav [10] | 图像空间 / 全景方向 | 否 | 无显式地图 | 像素/方向目标 | 不编码 metric 自由空间与长程可达性 |
| Navi-Agent [30] | 视觉地点拓扑 | 否 | 无占据图 | 拓扑节点 | 无 metric 可通行性 |
| **ERA** | **有界符号占据 + value map** | **否** | **可撤销（有界证据 + 非对称更新 + footprint 重置 + 接触障碍）** | **可达已知自由空间（非 frontier）** | **依赖平台位姿；路径变长（SPL 代价）** |

### 🎤 面试 Tip

被问"这篇和 VLFM 到底差在哪，为什么换个更新规则就能从 10.8% 到 61.7%？"，**不要答"因为它更鲁棒"**，要答出闭环：

> "VLFM 的失败不是单点误差，是一个正反馈死锁：预测深度的视角相关误差被当传感器深度累加，同一表面越看越厚，把通路和 frontier 一起抹掉；没有 frontier 就停，停就再也拿不到能纠错的新视角。ERA 的贡献不是把深度做准（DA3 全程冻结），而是同时松开这个死锁的两端——证据有界所以后来的自由观测能推翻旧障碍（Move2Error），探索候选放宽到所有可达已知自由空间所以没 frontier 也能继续走（Error2Move）。任何一端单独松开都不行，这是论文里'近一半帧没有可达 frontier'这个统计支撑的。而且这个结论可被证伪地检验过：把组件装进 L3MVN、把深度换成更差的 VGGT，增益依然成立。"

如果追问"代价是什么"，答：**SPL**。SR 上去但路径变长，且真机/大场景下每步要多帧深度前向，算力账要自己算——论文没报延迟。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-11-16)

**Repo 状态核查**：本笔记所据 arXiv 全文（含正文、附录标题、参考文献区）中**未出现任何 `github.com` 链接或项目主页地址**，arXiv 页面仅有 "Report GitHub Issue" 这类站点级 UI 元素，不构成论文给出的 repo 信号。因此按规则记为：**官方 repo 未在论文中给出，社区 issue 流不可核查**。以下 3 条 pitfall 由 §6 失败模式 + 本文方法的具体约束推导，**均未经 issue 验证**，标 `UNVERIFIED`。

### Pitfall 1 — 自由射线在无纹理/反光地面上的"过度清空"，会把真障碍擦掉
- **机制推导**：§6 假设 4 指出 free-space ray 在无预测障碍时"终止于观测到的地面"。式 (1) 中取 `δ = E/2` 时，**一次**自由观测即可清掉一次障碍观测，**两次连续**即可清掉饱和证据；且式 (1) 的帧内规则是"障碍观测优先于自由观测"，即**跨帧**没有任何不对称保护。因此在玻璃门、镜面、纯色瓷砖走廊这类深度预测系统性偏远的场景，`max(-E, e_m - δ)` 会反复把真实障碍推向 `e_m ≤ 0`，`F_t`（式 2）随之扩张到墙里。
- **后果形态**：不是"提前终止"，而是反向失败——agent 把可通行空间算到实墙内部，规划器给出穿墙路径，最终靠**碰撞反馈**写进 `K_t` 才停住（而 `K_t` 只能靠中心穿越解除）。
- **可自检**：统计每个 episode 中 `K_t` 新增次数 / `e_m ≤ 0` 但曾被标记为障碍的格子比例，异常高即为该模式。

### Pitfall 2 — 位姿漂移 × footprint 硬重置 `e_m = -E` 的"错误自由证据"污染
- **机制推导**：§3.1 规定"After every map update, cells previously swept by the agent's footprint are reset to `e_m = -E`"，这是一个**写满最强负证据**的操作，优先级高于视觉证据。§6 假设 1 指出系统依赖平台位姿；论文只提供附录 D.1 的敏感性分析，没有漂移下的保护机制。轮式里程计在长走廊累积航向漂移时，被写成 `-E` 的"踏过区域"会**偏离真实轨迹**，覆盖到旁边的真实障碍上。
- **后果形态**：真实障碍被强制置为自由 → 与 Pitfall 1 叠加；且因为 `-E` 是饱和值，需要**两次**连续障碍观测才能翻正，恢复比普通格子更慢。
- **可自检**：把 footprint 重置在调试可视化中单独着色，与真实轨迹对比偏移量。

### Pitfall 3 — `ρ_min / ρ_max` 窗口 + "三次整圈即判定耗尽"会在开阔区误判 exploration exhausted
- **机制推导**：式 (3) 的候选集 `V_t = {v ∈ F_t : ρ_min ≤ ρ_t(v) ≤ ρ_max}` 只接受**路径长度落在窗口内**的自由格。若一个错误障碍恰好卡在近处、把近区割断，同时其余可达自由空间都远于 `ρ_max`（大平层、厂房、长走廊），则 `V_t = ∅`。论文 §3.2 的终止规则是"If `V_t` is empty, the agent turns in place... exploration is declared exhausted only if no candidate becomes available over **three full rotations**"。原地旋转不改变位置，`ρ_t(v)` 也不变，所以**旋转无法让 `V_t` 从空变非空**——除非视角变化恰好让 free-space clearing 改写了某个格子。
- **后果形态**：在一次错误的"空候选"事件后 3 圈内宣告终止，而 §2.2 的核心论断"early termination 是主要失败模式"恰恰就是这个形态；论文 Fig. 2a 已量出"近一半帧无可达 frontier"，即该边界条件在预测深度下**并不罕见**。
- **可自检**：日志中记录每次 `V_t = ∅` 时的 `min_v ρ_t(v)`，若普遍大于 `ρ_max`，则窗口设置是瓶颈而非深度出了问题；调 `ρ_max` 或把"原地旋转"换成"走到最近可达自由格再评估"是直接补丁。
