# 更清晰的帧，更糟糕的房间：前馈三维重建中视角覆盖度主导图像质量 (Sharper Frames, Worse Rooms: Viewpoint Coverage Dominates Image Quality in Feed-Forward 3D Reconstruction)

> **发布时间**：2026-10-11（arXiv:2610.15854v1 [cs.CV]，CC BY 4.0；距今天 7 天）
> **论文 / 模型名**：Sharper Frames, Worse Rooms（作者 Alibek Dadajonov, Hikmatillo Umarhojiyev，Arbuz AI；骨干模型为 `MapAnything`）
> **核心定位**：在固定视图预算（K=16）下做前馈多视图重建，**"挑最清晰的帧"是所有策略里最差的一种**——因为它等价于按相机角速度挑帧、按角度冗余挑帧；coverage 的主效应约为 quality 的 3×。

一句话导语：手机扫一间房能出约 1,800 帧，而前馈重建模型只接收 16 帧，这 16 帧的挑法决定了所有下游任务继承的几何。论文用 9 段手持室内扫描 + 2×2 析因实验证明：把 SfM 时代"去模糊、留清晰"的启发式直接搬过来，在固定小预算下会产生系统性错几何，而且**推理期可得的两种置信度信号全都朝错误方向走**。

---

## X-Ray 开场

这篇论文问的是一个"上游、便宜、但没人系统测过"的问题：喂给前馈多视图重建模型的那 K 帧，应该按什么挑？它给出的答案是反直觉的——**视角覆盖 (viewpoint coverage) 的作用远大于单帧清晰度 (per-frame sharpness)**，选最清晰的 16 帧会把误差推到 48%（同一段里均匀时间采样只有 3%），机制是"清晰帧 ≈ 慢速运动帧 ≈ 角度冗余帧"。对 spatial AI 研究者的意义不在选择算法本身（coverage 选择是已有技术），而在于：**它揭示了一个无检测器的失效模式**——模型自带的多视图一致性分数随误差上升，VLM 的自信度与自身误差无关，也就是说管线悄悄丢了覆盖度时，栈里没有任何一个信号会报警。

## 1 · 核心架构 / 方法总览

这篇论文没有网络架构创新，它是一篇**受控实验 (controlled experiment) 论文**：把"帧选择"从重建管线里拆出来，当作一个独立变量去操纵。所以 1.1 的表格描述的是**实验装置的各模块**，而不是网络的各层。

### 1.1 系统 / 组件对比

| 模块 | 输入 → 输出 | 训练 vs 推理 |
|---|---|---|
| 候选池构建 | 1–2 min @30fps 手持视频 → **200 帧**（均匀时间采样） | 无训练；纯预处理 |
| 特征 1：sharpness | 单帧 → Laplacian 方差，**在 capture 内做百分位归一化** | 无训练；解析特征 |
| 特征 2：yaw | 光流 + 名义水平 FOV 积分 → 每帧偏航角 | 无训练；**系统性高估总旋转**（平移污染流场），只依赖相关性不依赖绝对尺度 |
| 选择策略（6 种） | 特征表 + 预算 K → K 个索引 | 全部推理期决策；模型权重固定 |
| 2×2 析因格子 | spread(greedy bin coverage) / clustered(连续一段) × high/low(中位清晰度上下) | 同上；每格 9 captures × 3 seeds × 3 view orderings = **81 次重建** |
| 重建 | 16（或 K）帧 → 点云 + 度量几何 | **`map-anything-apache`** checkpoint（Apache-2.0），mixed precision + edge masking；论文未做任何训练 |
| 度量提取 | 世界点 → 重力(相机 up 向量均值) → 最小面积矩形对齐 yaw → 两水平轴 5–95 百分位跨度 | 确定性管线，重跑可复现到小数点后三位 |
| 参考 | 全部 **200 帧**稠密重建作为 reference | 同上；无卷尺真值的替代方案 |
| 置信度信号 | 重叠区域逐视图深度预测的一致性 → multi-view consistency score | 模型自带，推理期可得 |
| VLM 探针 | 同一批帧 → 房间地面尺寸估计 + 自报置信度（`claude-sonnet-5`, 2026-08 查询，189 次） | 零样本，非训练组件 |

### 1.2 关键机制

**⚡ Eureka Moment：清晰度是相机角速度的反向代理——按 sharpness 排序，就是在按"角度冗余"排序；而固定小预算下，误差由覆盖度主导，不由单帧质量主导。**

论文把这个耦合讲得很直白：`sharp frames tend to occur during slow motion and therefore concentrate the selection in a narrow angular region`。手持扫描时人在转角处减速、在直墙前匀速平移，所以 Laplacian 方差高的帧天然堆在少数几个朝向上。示意图里选出的 16 帧只覆盖 0.194 的角度、最大未观测楔形 3.35 rad，即「192° 的房间从未被看见」——**没看过的房间不可能被重建**。

第二层洞见（部署向）：**丢失覆盖度的选择，同时也获得了冗余**。而 multi-view consistency 分数度量的正是"多视图之间有多一致"。于是「一致 ≠ 正确」在这里退化成「一致 ∝ 错误」，一致性分数随误差上升（9/9 captures，mean ρ = +0.529）。

### 1.3 信息流 / 实验装置图

```
手持视频 (9 段, 30fps, 1–2 min)
        │
        ├─► 均匀抽 200 帧 ──► [特征层] ──► sharpness = Var(Laplacian), 百分位归一化
        │                              └─► yaw = ∫光流 (名义水平 FOV)  ──► 36 个 10° bins
        │                                        └─ 校验: 与稠密重建相机朝向 Pearson r
        │
        ▼

        ├─ Uniform (时间均匀, 部署基线)
        ├─ Random (无放回)
        ├─ Sharpness (top-K Laplacian 方差)          ◄── 最差
        ├─ Coverage (36 bins 上 greedy 边缘增益, 依 [13])
        ├─ Coverage-FPS (yaw 上最远点采样)
        ├─ Coverage-q (greedy 池限制在 sharpness 第 q 百分位以上)

        │
        ▼

        │

        │        └─ relative dimension error: 两个主水平跨度的平均绝对相对误差
        │
        ├─► [置信度] multi-view consistency ──► 与误差正相关 (反直觉)
        │
        └─► [VLM] claude-sonnet-5 → 尺寸估计 + 自报置信度 ──► 与几何误差不相关
```

## 2 · 数学核心

📌 **Napkin Formula**

```
在固定预算 K ≪ B（B=36 个 10° yaw bin）时：
      error(S)  ≈  e₀ + α · (1 − cov(S)) + β · (1 − sharp̄(S))
      且  α_spread ≈ 3 × α_quality
  ⇒  argmax_{|S|=K} cov(S)   ≫   argmax_{|S|=K} sharp(S)
```

**目标**：在 |S| = K 的硬基数约束下，选 S 使重建的相对尺寸误差最小。这是一个**基数约束子模最大化**问题，覆盖函数有标准 (1−1/e) 贪心保证 [7]（论文自陈这是引用严谨性，不是贡献）。

**公式 1（覆盖目标）**：

$$f(S)=\left|\bigcup_{i\in S} B(\theta_i)\right|,\qquad B(\theta_i)=\left\lfloor \theta_i/10^{\circ}\right\rfloor \bmod 36$$

贪心边缘增益：$i^{*}=\arg\max_{i\notin S}\left|B(\theta_i)\setminus\bigcup_{j\in S}B(\theta_j)\right|$

变量：$\theta_i$ 为第 i 帧光流积分得到的偏航角；$B(\cdot)$ 把 360° 切成 36 个 10° 箱（沿用 Wang et al. [13] 的对比启发式）。

**公式 2（误差度量）**：

$$e(S)=\frac{1}{2}\sum_{d\in\{\text{long},\text{short}\}}\frac{|\hat d(S)-d_{\text{ref}}|}{d_{\text{ref}}}$$

关键点：**分母是 reference，不是卷尺真值**，且求和时**包含退化重建**（不条件化于成功——论文明确指出早期版本按成功条件化，把最差格子的惩罚低估了 8 个点）。

**公式 3（退化判据，先于任何重建固定）**：

$$\text{degenerate}(S)\iff \min(\hat L,\hat W)<1.2\,\text{m}\ \ \lor\ \ \frac{\max}{\min}>4{:}1$$

**公式 4（析因主效应）**：符号约定为「正值 = 聚集 / 低清晰度 使误差变大」

$$\Delta_{\text{spread}}=\overline{e}_{\text{clustered}}-\overline{e}_{\text{spread}},\qquad \Delta_{\text{quality}}=\overline{e}_{\text{low}}-\overline{e}_{\text{high}},\qquad \Delta_{\text{int}}=\Delta_{\text{quality}}^{(\text{clustered})}-\Delta_{\text{quality}}^{(\text{spread})}$$

**直觉**：把清晰度写成角速度的单调递减函数 $s_i \approx g(|\dot\theta_i|)$ 后，$\arg\max_S \sum_{i\in S} s_i$ 会落在 $|\dot\theta|$ 的极小值附近——在角度空间里就是一个**簇**。"挑清晰帧"和"挑同一面墙"在数学上是同一件事。

## 3 · 带数字走一遍

### 3.1 玩具设定（明确为合成，非论文数据）

设一段 24 帧扫描，8 个 10° 箱（每箱 3 帧），相机在箱 3、4 处减速停留，因此这两箱的 Laplacian 方差最高。预算 K = 4。

| 策略 | 选中箱 | 覆盖度 | 玩具误差模型 $e=0.05+0.45(1-\text{cov})$ |
|---|---|---|---|
| Sharpness top-4 | &#123;3,3,4,4&#125;（簇） | 2/8 = 0.25 | 0.05 + 0.45×0.75 = **0.3875** |
| Greedy coverage | &#123;1,4,6,8&#125; | 4/8 = 0.50 | 0.05 + 0.45×0.50 = **0.2750** |

差距约 1.4×——玩具里的系数是任意设的，**不能用它去复述论文的"3 倍"**；它只演示机制方向：预算固定时，第二、三个清晰帧带来的信息增量几乎为零，而换一个朝向上的模糊帧带来的是整数个 bin。

### 3.2 用论文真数验一遍析因代数

取 Table 2 的四个格子均值（相对误差）：

| | high quality | low quality | 行均值 |
|---|---|---|---|
| **spread** | 0.110 | 0.154 | 0.132 |
| **clustered** | 0.324 | 0.435 | 0.3795 |

- spread 主效应 = 0.3795 − 0.132 = **+0.247** ✓（论文报告的 +0.247，95% CI [+0.155, +0.340]，p = 0.0003，9/9 captures 同向）
- quality 主效应 = (0.154+0.435)/2 − (0.110+0.324)/2 = 0.2945 − 0.217 = **+0.077** ✓（95% CI [+0.018, +0.136]，p = 0.017，8/9）
- 交互项 = (0.435 − 0.324) − (0.154 − 0.110) = 0.111 − 0.044 = **+0.067** ✓（95% CI [−0.064, +0.199]，p = 0.27 → **不显著，论文只作"暗示性模式"报告**）

**直接格子对比**（不依赖上述比值）：spread-low 0.154 打败 clustered-high 0.324，正好 2 倍，8/9 captures（配对差 +0.170，配对 t 检验 p = 0.009；Wilcoxon p = 0.012）。

**退化率的算术**：clustered-low 格 0.435 误差 / 39.5% 退化率，典型失败返回"0.59 到 0.89 m 宽"的房间，未观测楔形 4.2 到 5.7 rad——一块板而不是一间房。检查判据：若长边取 2.8 m 而短边收缩到 0.7 m，则 2.8/0.7 = 4:1，恰好命中阈值。

**预算上限的算术（可直接验证 Table 3）**：36 个 bin、K = 16 ⇒ 最多只能占 16 个 bin ⇒ 覆盖度上限 16/36 = **0.444**，与 Table 3 中 K = 16 行 "coverage achieved (spread) = 0.444" 完全吻合。也就是说 **K ≥ 36 才可能 coverage = 1.000**，论文在 K = 48 时才首次达到 1.000——这正是 §4.3 "机制自己预测自己的边界"的含义。

## 4 · 工程视角

| 维度 | 论文报告值 | 备注 |
|---|---|---|
| 硬件 | 单张 **NVIDIA GB10**（unified memory） | 唯一给出的硬件型号 |
| 单次重建延迟 | K = 16 约 **2 s**；K = 32 约 **5 s** | 原文 "about 2 s at K=16 and 5 s at K=32" |
| 全部实验总量 | 约 **4 GPU-hours** | 含全部 captures × 策略 × seeds × orderings |
| 数值精度 | mixed precision inference + edge masking | 推理配置 |
| 确定性 | 完整重跑可复现每个误差与失败率到小数点后三位 | 对论文可信度很关键 |
| VRAM / 显存峰值 | **论文未报告** | GB10 unified memory，未给占用 |
| 端侧 / 手机部署 | **论文未报告** | 只在单卡服务器上跑 |
| 选择器本身耗时 | **论文未报告** | 未给特征提取或 greedy 选择的计时 |
| 部署实现差异 | ONNX 导出**固定 16 视图**，更短输入靠**重复最后一帧 pad** | 因此预算扫描被迫用 PyTorch reference 实现 |
| 部署 vs 离线一致性 | 一段上部署服务返回 3.63 × 3.60 m，稠密参考 3.94 × 3.63 m，约 **8%** 差 | 绝对数值不可当作部署系统读数 |
| 骨干数量 | **1 个**（MapAnything） | 是否迁移到置换等变骨干（π³ 类）未测 |

**Trade-off 读法（工程意义）**：

1. **预算是架构常数，不是超参**。部署系统服务的重建图被导出为固定 16 个视图，"选择"因而是硬基数约束。这意味着你不能靠"多喂几帧"来补救——K = 16 相对 B = 36 个 bin 只有 0.444 上限，是硬上限。
2. **延迟随 K 超线性上升的幅度未知**：2 s → 5 s 是 K 翻倍（16→32），但论文没报告 K = 48 的延迟，也没有给显存/吞吐。做容量规划时只能拿"单张 GB10、秒级"作数量级参考，**不能外推 8–48 全区间**。
3. **ONNX 的 pad 语义会污染实验**：重复最后一帧等价于人为放大最后一帧所在的角度 bin，短输入时既提高表面覆盖度又提高冗余度——这就是论文拒绝用部署实现做预算扫描的原因。任何在自家管线上复现这个权衡的人，第一步必须先确认 pad 策略。
4. **选择器的开销相对重建可忽略还是不可忽略，论文没给数**（`UNVERIFIED`：Laplacian 方差 + 光流积分在 200 帧上是毫秒到百毫秒量级，greedy 在 36 bin 上是 O(K·N) 的纯整数运算——但这是推断，不是论文数据）。

## 5 · 数据与评测

**数据组成**（逐字来自全文）：

- **9 段**手持手机视频，每段**单个房间**，住宅或办公室内，**30 fps**，时长**1 到 2 分钟**。
- 每段抽出 **200 帧**候选池（均匀时间间隔）。
- 未使用任何公开 benchmark；数据是作者自采。**其中 3 段**可以实地测量（bedroom / work_office / home_office），其余 6 段无法进场测量。
- 光流 yaw 展开（unwrapped）跨度：8 段完整扫描为 **386° 到 1083°**，且**非单调**——这正是"时间均匀 ≠ 角度覆盖"的物理原因。第 9 段是窄扫，展开仅 **80°**。

**特征校验**：

| 校验项 | 数值 |
|---|---|
| yaw vs 稠密重建相机朝向（Pearson r） | 8/9 段 **r ≥ 0.70**；中位 **0.87**；4 段 **r ≥ 0.98** |
| 失败段 | 1 段 **r = 0.154**（窄扫），全篇单独处理 |
| 重力估计 vs 独立 layeredness 估计 | 差 **6.9°** |
| 重建层高范围 | **2.24 到 2.47 m**（住宅室内合理区间） |

**Reference 及其噪声底**（这是全文最诚实的部分）：

| 量 | 数值 |
|---|---|
| 半池分治一致性（even/odd 各 100 帧稠密重建之差） | 均值 **3.3%**（9 段）；排除失败段后 **1.6%**；范围 **0.3 到 5.2%** |
| 卷尺实测 vs 稠密参考 | **11.8%**（bedroom）、**8.1%**（work_office）、**11.4%**（home_office）；平均绝对误差 **10%**，无一致方向 |
| 注意 | 这 3 段恰好是自一致性最好的（0.3 到 1.1%），却仍有 8–12% 精度误差 ⇒ **自一致不预测真值一致** |
| 房间形状 | 方形房间重建成方形 |

Table 1 逐字：bedroom 实测 3.39 × 3.39 m / 参考 3.94 × 3.63 m / 11.8%；work_office 3.90 × 2.62 / 4.22 × 2.83 / 8.1%；home_office 4.72 × 3.72 / 4.04 × 3.41 / 11.4%。

**评测设置（条件，不只结论）**：

- 主策略比较与析因：**K = 16**，9 captures × 3 seeds × 3 view orderings，每格 **81 次重建**；统计单元是 **capture（n = 9）**，因为 seed 和 ordering 是 capture 内的重复测量。
- 预算扫描：**K ∈ &#123;8, 16, 32, 48&#125;**（K = 12、24 因篇幅省略，据称平滑插值），只用**当时可用的 4 段完整扫描**，3 seeds ⇒ 每格 **12 次重建**。
- VLM 探针：9 captures × 7 strategies × 3 seeds = **189 次查询**（2026-08 查询，`claude-sonnet-5`，仅图像输入）。
- 跨模态相关：**63 个**匹配的 capture-strategy 单元（9 × 7）。
- 排序敏感性：同一 16 帧重排使长边变化 **1.5 到 13.7%**（中位 ≈ 9%），但策略间误差差在 9 段上全部超过 ordering 方差 ⇒ 策略比较固定时间序，析因额外对 3 个随机 ordering 边缘化。

**主要结果数字（逐字）**：

|---|---|

| uniform / random | **0.063** / **0.114** |
| sharpness 选择的角度覆盖 / 最大未观测楔形 | **0.194** / **3.35 rad**（≈192° 未观测） |

## 6 能力与失败模式

**能做**：

- 在 9 段手持室内扫描上给出**策略排序**：sharpness 排序显著最差（0.278），且在预算扫描的每个 K 上都覆盖最少；uniform 0.063 最好，但论文明确声明 **uniform 有结构性优势**（它是 200 帧中"最像 reference"的 K 帧子样本），因此**不宣称 uniform 最优**。
- 用 2×2 析因**独立操纵** spread 与 quality，把"覆盖 vs 质量"从混杂中拆开，得到 spread 主效应 +0.247、quality +0.077。
- **预测并验证机制边界**：B = 36 ⇒ K ≥ 36 才饱和；实测在 K = 48 时 spread 选择首次达到 coverage 1.000，gap 从 0.212（K=16）降到 0.105，clustered-low 退化率 0.500 → 0.000。这是先做预测再跑的实验（§4.3），方法论上比前两节（自陈 confirmatory）更强。
- 给出**推理期无检测器**的证据：一致性分数随误差上升；VLM 误差与几何误差不相关、自报置信度几乎不变化（131/189 都是 0.30）。

**不能做**：

- **不能给绝对精度**。最好格子的误差（11.0%、15.4%）与 reference 自身误差（10% MAE vs 卷尺）同量级，作者直接写"我们不做绝对准确的声明"。只有 clustered 格子（32.4%、43.5%）是 reference 不确定度的 2–3 倍，加上 degeneracy rate 依赖物理上不可能的房间尺寸，才撑起"选择比较"的结论。
- **不能外推到非单房间/非矩形**：度量提取用最小面积矩形 + 5–95 百分位跨度；L 形、开放式空间、多房间没有测。
- **不能外推到窄角扫描**：那段 80° 展开的 capture 是 r = 0.154、reference 分歧 16.4%（别处均值 1.6%）、VLM 误差 0.541（别处 0.122–0.334）、ordering 方差 18.7%，并且是**唯一一段 spread-low 输给 clustered-high** 的。论文选择"把它报进汇总但不下边界结论"。
- **不能外推到其他骨干**：只测了 MapAnything。置换等变模型（π³ 类）是否还敏感于 ordering / 选择，未测。
- **不能宣称"几何毒化了 VLM"**：§5 给 VLM 的是**同一批帧，不是重建结果**。所以它测的是"图像型 VLM 是否也有相同选择敏感性"，不是"错几何是否污染下游推理"——论文自己把这列为未测项。
- **不能宣称 quality 不重要**：quality 主效应 +0.077 是显著的（p = 0.017），且交互项方向一致（8/9）只是不显著。正确表述是"spread 比 quality 更重要"，不是"quality 无关"。

### 隐含假设 (Hidden Assumptions)

1. **假设"清晰 ↔ 慢速运动"这个耦合在采集策略里成立**。它由"30fps 恒帧率 + 手持转角减速"产生。若换成三脚架定点变焦巡检、或云台匀速环绕，耦合会弱化甚至反向。
2. **假设覆盖度可以用 1-D 偏航角刻画**。36 个 yaw bin 对"绕光心旋转 + 小平移"的手持房间扫描合理；对走廊直推、穿门过渡这类**平移主导**的轨迹，yaw 覆盖 = 1.000 仍可能完全没看到某个房间。
3. **假设场景是静态的**。有人的房间里，人站定时帧也会"清晰"，sharpness 选择器会连带选中同一站立姿态的多帧。
4. **假设房间是单一矩形盒**。重力取相机 up 向量均值、yaw 用最小面积矩形对齐、跨度取 5–95 百分位——这套提取对非凸户型没有定义良好的"两个主水平跨度"。
5. **假设 reference 是有效代理**。而论文自己测出：自一致 1.6%、对卷尺 10% MAE，且"两个稠密重建彼此接近，同时以相同方式出错"。**所有误差数字都是"与稠密重建的分歧"，不是 metric accuracy。**
6. **假设 Laplacian 方差是有效的清晰度代理**。它同时是**纹理**代理：一面空白墙即使对焦完美方差也低。这使 top-K sharpness 在纹理不均的房间里实际是一个"纹理选择器"（详见 §8 Pitfall A）。
7. **假设 K 是硬约束**。整个结论的前提是"不能多喂帧"；若能喂 200 帧，覆盖度问题自然消失。
8. **假设 multi-view consistency 被从业者读作可靠性**。论文的批评落在这个**用法错配**上，而不是分数本身实现有缺陷——"一致性不是正确性"。
9. **假设单一 VLM 单次查询能代表"VLM 类系统"**。只测了 `claude-sonnet-5`，单一 prompt（要求输出"估计落在真值 15% 内的概率"），未测注意力/依据。

## 7 与相关工作对比

| 工作 | 场景/采集 | 选择准则 | 固定基数？ | 把 coverage 与 quality 对撞？ | 结论/主张 |
|---|---|---|---|---|---|
| Ahmed et al. [1]（+ Torr GRIC [12]） | SfM 关键帧 | correspondence ratio 作 baseline 代理 + GRIC 选模型 + 点到极线代价 | 否（阈值/准则驱动） | 否 | 最大化三角化 baseline；显式淘汰"绕光心旋转"与"共面结构"——**正是本文的采集配置** |
| Koschel et al. [5] | 惯性 + 随机森林 | 拒运动模糊 + 拒冗余帧，Meshroom 重投影 RMSE 验证 | 否 | 否（Figure 1 提了这个问题，但把答案判给 quality） | 自陈"discards frames carrying real information"；用 360° 相机架，覆盖由构造保证 |
| Zhang et al. [14] | 无人机航拍 | Crete blur metric [2] + 由高度/FOV 导出的成对重叠率 | 否 | 部分（先定几何间距，blur 只做局部精修） | 云台稳定 nadir 匀速飞行，角度覆盖由构造保证 |
| Rashidi et al. [9] | 验证序列专门拍平面墙、纯旋转 | 在既有方法上加模糊约束 | 否 | 否 | 构造序列**就是为了证明选择器会剔除这类帧** |
| Jha et al. [3] | Spann3r / CUT3R（同族） | 光度 + SSIM 变化信号，阈值式自适应 | 否（阈值而非基数） | 否（无 coverage 基线） | 需 RGB-D 输入，Chamfer 距离评测 |
| Wang et al. [13] | 多贡献者环绕地标 | 36 个 10° bin，每 bin 取最佳帧 / 全局视角覆盖目标（transductive experimental design） | **是** | 否（完全不含图像质量） | 报告覆盖感知选择接近均匀采样 |
| UfM [23] | 不确定性 | 多视图分歧 > 单图不确定性 | — | — | 本文**限定而非反驳**它：多视图一致对多数误差源有效，但对"帧选择引入的误差"是**反信息**的 |
| π³ [19] | 架构 | 置换等变以去掉参考视图偏置 | — | — | 本文引用它说明 ordering 敏感性存在（实测长边变化 1.5–13.7%，中位 ≈ 9%） |
| **本文** | **9 段手持单房间室内扫描** | **6 种策略 + 2×2 析因 + 预算扫描** | **是（K = 16，部署硬约束）** | **是（首次）** | **spread 主效应 ≈ 3× quality；sharpness 排序最差；两种置信度信号均失效** |

⚠️ **关于"3 倍"的一个必须转述的限定**：论文自陈 *"our spread manipulation is extreme while quality is a median split, so the factor of three reflects the contrast widths we chose rather than an intrinsic property of the factors"*。也就是**这个比值不是因子的内在常数**，不依赖它的直接格子对比（spread-low 0.154 vs clustered-high 0.324）才是稳健主张。

**🎤 面试 Tip**：被问"为什么不用最清晰的帧做 keyframe / frame selection？"——不要答"因为模糊有害"，要答三层：(1) **机制**：在手持续扫 + 恒帧率下，清晰度是相机角速度的反向代理，于是 argmax sharpness ≈ argmax 角度冗余，论文实测 sharpness 选择只覆盖 0.194 的角度、最大未观测楔形 3.35 rad；(2) **边界**：这个结论只在 K ≪ B 时成立，B = 36 个 10° bin 时 K ≥ 36 覆盖才能饱和，论文实测 gap 从 K=16 的 0.212 掉到 K=48 的 0.105，而部署预算恰是 K=16、正处在效应最大处；(3) **诚实**：主动说出"3 倍"是操纵对比宽度的产物、uniform 有结构性优势、reference 自身有 10% MAE，并补一句最狠的部署含义——**一致性分数随误差上升，所以没有检测器可以报警**。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-10-18)

**诚实前置声明**：论文正文（含摘要、正文、参考文献、附录 A）**没有出现任何 `github.com` 超链接**。arXiv HTML 头部的 "Report GitHub Issue" 是 arXiv 页面控件，不是作者代码库；文中提到的 MapAnything 权重是 **Apache-2.0 的 `map-anything-apache` checkpoint**，但**未给出 URL**。因此**本文无社区 issue 流可引用**，以下 3 条 pitfall 全部由 §6 失败模式 + 具体方法约束**推导**，未经 issue 验证。论文发表仅 7 天（2026-10-11 → 2026-10-18），即便存在 repo 也尚属 early-release。

### Pitfall A：Laplacian 方差在纹理不均的房间里会退化成"纹理选择器"

- **来自 §6 失败模式**：单一 sharpness 度量被明确列在 Limitations 中（对比工作用 Crete 感知模糊 [2] 或 DFT 幅值 [5]）；隐含假设 6 指出 Laplacian 方差同时是纹理代理。
- **来自方法约束**：`Sharpness = variance of the Laplacian, percentile normalised within a capture`，用于 top-K 排序。
- **机械后果**：一幅对焦完美但内容为空白平墙的帧，Laplacian 方差低于一幅轻微失焦但满墙书架纹理的帧。于是 top-K 在"blank wall + textured corner"的房间里会**系统性偏向同一纹理密集角落**，把论文的"角度冗余"效应进一步放大到"角度 + 纹理"双重聚集。此时你观察到的误差溃败**不能**归因于"模糊真的有害"，因为排序信号根本不是模糊。
- **工程动作**：若要在自家管线复现或反驳这篇，先做 §6 那条未做的消融——换方向性/感知模糊度量重跑 top-K，并在纹理方差层做一次归一化，看 gap 是否只剩一部分。

### Pitfall B：把 36-bin coverage 贪心直接套到 K = 16，覆盖率被硬顶在 0.444，调参调不动

- **来自 §6 失败模式**：K = 16 相对覆盖需求是稀缺的；部署预算是架构常数。
- **来自方法约束**：`36 yaw bins of 10°` 的 greedy 边缘增益（依 Wang et al. [13]），每 bin 只能被计一次。
- **机械后果**：|S| = K 时覆盖度 ≤ K/36。K = 16 ⇒ 上限 0.444（与 Table 3 中 K=16 行实测 0.444 完全一致）。此时你再怎么改贪心的 tie-break、稀疏先验、或换 FPS 变体，**都不可能超过 0.444**；但"覆盖度"这类指标的绝对值会让人误以为还有 55% 的提升空间，于是在错误维度上做优化。
- **工程动作**：先决定 B。若预算固定 16，就把 bin 数降到 B ≈ 8–12（每 bin 22–45°），让 K/B 落在 ≈ 1–2 区间；否则覆盖率指标本身失去分辨力（这一点在论文的 K 扫描里也能看到：K = 32 时 0.889、K = 48 才 1.000，"spread error 在最后两个预算上持平 0.078 / 0.087"，正是饱和态）。

### Pitfall C：用 ONNX 部署实现做预算扫描，pad 语义会让 coverage 指标虚高且可复现地错

- **来自 §6 失败模式**：实现差异被明确列出——部署 ONNX 固定 16 视图且对更短输入**重复最后一帧**；论文因此全程用 PyTorch reference 实现做扫描。
- **来自方法约束**：选择器输出 K 个索引后直接喂模型；覆盖度按被选帧的 yaw bin 计算。
- **机械后果**：K &lt; 16 时，重复的最后一帧在角度统计里贡献"额外一帧"却只占同一个 bin ⇒ 你上报的 coverage / degeneracy 曲线在 K &lt; 16 区间被错误地抬高，且因为 pad 是确定性的，**重跑会稳定复现同一个错**（作者自己强调管线"重跑到小数点后三位"——确定性是优点，但它掩盖了语义错误）。K > 16 则根本无法通过导出图，只能改图或改实现。
- **工程动作**：任何"挑帧策略"的对比，先用一次 K = 16 的 A/B 确认离线实现与部署服务在同一段上的差异量级（论文给出的单点例子：部署 3.63 × 3.60 m vs 稠密参考 3.94 × 3.63 m，约 8%），再决定是否允许用部署实现跑扫描。8% 已经和论文最好格子（11.0%）与 reference 误差（10%）同量级，跨实现比较会把这些差异全部吃掉。

### Pitfall D（附加）：把 multi-view consistency 当质量闸门，会**专门放行**退化重建

- **来自 §6 失败模式**：一致性分数随误差上升（9/9，mean ρ = +0.529），退化重建的一致性 **0.710** vs 有效 **0.505**（+41%，p = 0.003，7/8）。
- **来自方法约束**：该分数定义为"重叠区域逐视图深度预测的一致程度"，而丢失覆盖度的选择恰恰是"视图彼此高度冗余"的选择——两个量在机制上被同一个变量驱动。
- **机械后果**：任何形如 `if consistency < τ: reject/retry` 的守门逻辑，在 τ ≈ 0.5–0.7 区间会**优先拒绝有效重建、保留退化成"0.59–0.89 m 宽的板"的重建**。这不是阈值调错，是符号错了。
- **工程动作**：闸门换成与选择无关的量——论文自己给了两个不依赖 reference 的：**物理不可能判据**（短边 &lt; 1.2 m 或长宽比 > 4:1 的 degeneracy 检测）和**角度覆盖度本身**（选择后立即算 cov(S)，K=16 时 &lt; 0.3 就该告警）。也就是说，**把闸门放在选择器之后、重建之前**，而不是放在重建输出上。
