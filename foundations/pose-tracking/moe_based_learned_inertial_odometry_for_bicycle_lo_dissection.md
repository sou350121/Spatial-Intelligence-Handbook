# 基于 MoE 学习的自行车惯性里程计 (MoE-Based Learned Inertial Odometry for Bicycle Localization)

> **发布时间**：2026-07-26（arXiv:2510.17604v2 [cs.RO]；v1 由 arXiv ID 推断为 2025-10，未在正文核对）
> **论文 / 模型名**：MoE-based learned inertial odometry for bicycle localization（代表配置 **MoE-8-2-128**）
> **核心定位**：把"自学步/自车"的 learned inertial odometry 第一次搬到自行车上，并用**稀疏门控 MoE** 把 ResMLP/ResNet 主干的计算量压到 1/7 与 1/9，精度持平或更好。
> **Ontology 定位**：problem=VO（此处为自行车三维速度/位姿回归）· representation=n/a（无稠密几何表征）· sensor=IMU · paradigm=learned · time=filter-streaming

城市峡谷里 GNSS 多路径让共享单车定位不可靠；手工的 cycling dead reckoning (CDR)、非完整约束 (NHC) 换骑手、换姿势、换路面就失效。本文的结论很干脆：把自行车运动模型换成**多骑手/多车/多路面 IMU 数据训练出的速度预测网络 + 误差状态 EKF 紧耦合**，通用性显著优于 NHC，且用 MoE 把推理算力降到移动端可接受的水平。

## X-Ray 开场

自行车惯性定位此前只有两条手工路线：CDR（用踏频线性映射前进速度）和 NHC（强行令横向/垂向速度为零），两者都要求物理建模精确、安装位姿固定、路面理想。本文提出**首个数据驱动的自行车惯性定位方案**：网络吃一段 IMU+姿态序列，直接输出机体系三维速度及其协方差，再塞进 ESKF 做 3D 位姿估计。对 spatial AI 研究者而言，它的价值不在"又一个 TLIO"，而在于给出一个**"小算力 + 专家分工"在流式滤波框架里可行的工程范式**：28.76 M FLOPs 的门控专家网络，能在 120 s 纯惯性外推中拿到 ATE 9.49 m、RTE 2.58 m，并且在**未见过的自行车**上退化远小于单主干网络。

## 1 · 核心架构 / 方法总览

### 1.1 系统组件对比表

| 模块 | 输入 | 输出 | 训练期 | 推理期 |
|---|---|---|---|---|
| 数据采集 App | 手机内置 IMU / GNSS / 磁力计 / Wi-Fi | 多模态原始流 | —（离线） | 不参与 |
| 数据预处理 | 原始多模态流 | 时间对齐样本 + 平滑轨迹与逐历元真值速度 | GNSS/INS **位姿图优化**（IMU 预积分因子 + GNSS 位置因子） | — |
| 门控网络 | 单个样本特征 | N 个专家的权重 → softmax → **top-K 稀疏 one-hot** | 交替冻结：epoch K 冻结门控 | 逐样本路由 |
| 专家网络（ResMLP 主干） | 9×L 输入切 patch 后的 embedding | Top-K 专家的加权特征 | epoch K+1 冻结全部专家 | 仅激活 K 个 |
| 回归头 | 融合特征 | 3 维机体系速度 `v̂^b` + 协方差对角 `Σ̂` | MSE 阶段 → NLL 阶段 | 每 0.1 s 输出一次 |
| ESKF | 原始 IMU（机械编排）+ `v̂^b, Σ̂`（量测） | R, v^n, p^n, b_g, b_a | — | 全速率传播 + 10 Hz 量测更新 |

关键差异：**同一份 IMU 被用了两次但角色不同**——一次驱动 EKF 机械编排产生先验，一次（连同滤波器给出的姿态）作为"运动索引"喂给网络。论文明确把这一点当作设计要点（避免"同一信号的冗余使用"）。

### 1.2 关键机制

- **稀疏门控**：`conv → ReLU → global average pooling → linear → softmax → top-K → 重新归一化 → 稀疏 one-hot 门控矩阵`。只有 top-K 专家参与计算。
- **容量约束**：`Capacity_i = ⌈ c·B / N ⌉`，超额的样本按权重降序**顺延**给下一个专家，防止少数专家吃掉整个 batch。
- **交替参数冻结**：偶数 epoch 冻结门控、奇数 epoch 冻结全部专家，"解耦路由优化与专家特化"。
- **两段式损失**：先 `L_MSE + λ·L_aux` 收敛，再 `L_NLL + λ·L_aux` 收敛（协方差在后半段才被监督）。
- **机体系速度作为量测**：`h(X) = R̂^T v^n = v̂^b`，因此 EKF 不需要维护历史状态做位移对齐，滤波器结构比 TLIO 更简单。

**⚡ Eureka Moment：稀疏 top-K 不只是省算力的手段，而是一种有用的归纳偏置**——Table IV 里稠密 `K=N=8` 花掉 108.46 M FLOPs（K=2 的 3.8×）却拿到**最差**精度（ATE 10.99 m vs 9.49 m），因为"强制每个专家对每个样本都发言"会把学到的特化平均掉，退化成过平滑的单网络。稀疏路由 = 条件依赖的专家分工。

## 2 · 数学核心

📌 **Napkin Formula**：
> `v̂^b_t = Σ_{i∈TopK} 归一化(g_i(x)) · f_i(x)`，然后 `R̂^T v^n = v̂^b + N(0, Σ̂)` 进 EKF —— **"学出来的机体系速度 = 滤波器的一个三维量测"**。

**(a) 门控 + 容量（决定"谁来算"）**
- 目标：每样本只激活 K 个专家，且 batch 内负载均衡。
- 公式：`Capacity_i = ⌈ c·B/N ⌉`（式 2）；超额样本按权重降序顺延分配。
- 变量：`c` 容量系数、`B` batch 大小、`N` 专家池大小。直觉：`c·B/N` 是"平均每人该分到多少个"，`c>1` 留缓冲。**注意：论文未报告 `c` 的具体取值**。

**(b) 回归损失（决定"算什么"）**
- `L_MSE = (1/n) Σ ‖v − v̂‖²`（式 3）——只监督均值。
- `L_NLL = (1/n) Σ ( ½ log det Σ̂ + ½ ‖v−v̂‖²_Σ̂ )`（式 4–5）——同时监督均值与协方差，Mahalanobis 项写为 `(v−v̂)^T Σ̂ (v−v̂)`。
- 直觉：EKF 的卡尔曼增益 `K = P Hᵀ (H P Hᵀ + Σ̂)^{-1}` 直接吃 `Σ̂`，所以**协方差标定质量等于滤波器对网络的信任度**。

**(c) 均衡损失（决定"别塌缩"）**
- 重要性 `I_i = Σ_{t=1}^{B} g_i(x_t)`（式 6），负载 `L_i = Σ_t 1(i ∈ S(x_t))`（式 8）。
- `L_importance = Σ_i (I_i/Σ_j I_j − 1/N)²`，`L_load = Σ_i (L_i/Σ_j L_j − 1/N)²`，`L_aux = L_importance + L_load`（式 10–11）。

**(d) 滤波（决定"怎么融合"）**
- 误差状态 `δX = (φ, δv^n, δp^n, δb_g, δb_a)`（式 13），`φ = log_SO(3)(R R̂^{-1})`。
- 传播：`P_{t+1} = A_t P_t A_tᵀ + B_t Q_t B_tᵀ`（式 17）。
- 量测雅可比只有两块非零：`H(φ̂) = R̂ᵀ (v̂^n)_×`，`H(δv̂^n) = R̂ᵀ`（式 19）——3×15 的极稀疏雅可比，这是"机体系速度做量测"带来的结构红利。
- Joseph 形式协方差更新：`P = (I−KH)P(I−KH)ᵀ + K Σ̂ Kᵀ`。

## 3 · 带数字走一遍（玩具设定，数字为演示自造）

设 `N=8`，`K=2`，某样本门控 softmax 输出
`g = [0.40, 0.30, 0.10, 0.10, 0.05, 0.05, 0.00, 0.00]`。

1. **top-2 选择**：选 E0、E1；丢弃其余 6 个（这 6 个的 forward 完全不算 → 这正是 K=2 相对 K=8 省 3.8× 的来源）。
2. **重新归一化**：`0.40/(0.40+0.30)=0.571`，`0.30/0.70=0.429`。
3. **加权融合**：`f = 0.571·f_{E0} + 0.429·f_{E1}` → 回归头 → `v̂^b = [4.2, 0.05, −0.02] m/s`，`Σ̂ = diag(0.04, 0.01, 0.01)`。
4. **容量检查**（训练期）：`B=1024, N=8`，取 `c=1.25`（演示值）→ `Capacity = ⌈1.25×1024/8⌉ = 160`。若 E0 在本 batch 被 200 个样本选中，则后 40 个按权重降序改派给 E1；E1 也满则继续下推。
5. **EKF 量测更新**：设上一时刻 `R̂ = I`、`v̂^n = [4.0, 0.2, 0.0]`，则预测量测 `h = R̂ᵀv̂^n = [4.0, 0.2, 0.0]`；新息 `h − v̂^b = [−0.2, 0.15, 0.02]`。由于 `Σ̂` 的横向分量只有 0.01（比传播先验小），卡尔曼增益会**主要修正横向速度**——即"网络告诉滤波器：这段路的侧滑比 NHC 假设的大"。
6. **对比 K=8 稠密**：同一 batch 8 个专家全部参与，融合权重被摊平为 `1/8` 附近，输出趋向训练集均值，ATE 从 9.49 m 恶化到 10.99 m（论文 Table IV 真值）。

Trade-off 解读（基于论文报告的量，不外推数字）：

- **算力 vs 精度不是单调曲线**。Table IV：`K=1` 15.48 M FLOPs、ATE 9.48 m；`K=2` 28.76 M、9.49 m；`K=3` 42.04 M、**9.28 m（最优 ATE）但 RTE 恶化到 2.69 m**；`K=8` 108.46 M、10.99 m（最差）。也就是说 `K=1` 已经"够用"，`K=2` 买到的是路由多样性（`N_act` 从 4 升到 5），`K=3` 只买到 ATE 边际收益。
- **参数量与算力解耦**。Table V：`N` 从 4 涨到 12，per-sample 算力几乎不变（≈28.76 M），参数从 3.68 M 涨到 10.67 M，但 `N_act` 在 `N≥6` 后饱和于 **5**——`N=12` 白白浪费约 3.5 M 参数。对嵌入式部署的含义：**模型体积按 N 增长，延迟按 K 增长**，两者可独立调。
- **滤波器侧开销是常数项**：ESKF 传播跑在 IMU 原始速率上（采样率**论文未报告**），网络只在 10 Hz 触发。真正的实时瓶颈通常在传播步的矩阵运算（15×15）而非网络，这一点论文未给分解。
- **部署约束**：稀疏路由意味着 batch=1、逐样本 gather，实际墙钟时间与 FLOPs 不成正比（见 §8）。

## 5 · 数据与评测

**数据**（全部逐字来自 V-A 节）：
- 自研手机 App，手机用支架**固定在自行车车把**上（Fig. 1），采集内置 IMU、GNSS、磁力计、Wi-Fi。
- 规模：**超过 25 小时**骑行记录；**8 名参与者**；多种型号自行车；覆盖 paved / unpaved 路面。
- 真值：多模态插值到统一时基后，做 **GNSS/INS 位姿图优化**（IMU 预积分因子 + GNSS 位置因子），得到平滑轨迹与**逐历元真值速度**作为监督。
- 划分：**70% 训练 / 10% 验证 / 20% 测试**。

**评测设置**（讲条件）：
- 指标：**ATE**（RMSE，米）、**RTE**（局部重力对齐系下的相对平移误差，`Δt = 1 minute`）、**IE**（推理误差，m/s，定义为 `(1/n)√Σ‖v−v̂‖²`，论文明确说明它与标准 RMSE 略有不同）。
- **标准断 GNSS 协议**：每段测试序列循环执行"10 s 提供参考位置更新做初始化 → 120 s 切断位置修正模拟 GNSS 失锁"；**指标只在 120 s 失锁区间上计算**，所以数字反映纯惯性外推。
- 鲁棒性切分：沿 rider / bicycle / road surface 三个正交维度切成 **People seen/unseen、Bicycle seen/unseen、Paved/Unpaved road** 六个 split；unseen 指训练中未出现的参与者或自行车。

**关键结果（原文数字）**：
- vs 模型基线 NHC（Table I）：Overall NHC ATE **10.82** / RTE **4.01** vs MoE-8-2-128 **9.49** / **2.58**；**Paved 路面上 NHC 反而更优**（8.54 vs 9.86，RTE 3.36 vs 2.44）；Unpaved 上 NHC 崩坏到 **13.86** / **4.44**，MoE 为 **8.76** / **2.86**。这是全文最诚实的"双峰"结论。
- vs 学习基线（Table II）：MoE-8-2-128 IE **0.333 m/s**、ATE **9.49 m**、RTE **2.58 m**、28.76 M FLOPs；ResMLP-512 IE 0.349 / ATE 9.91 / RTE 2.56 / 195.64 M；ResNet-512 IE 0.352 / ATE 10.38 / RTE 2.76 / 267.26 M。
- 泛化（Table III）：论文称 MoE 变体在**所有六个 split 上 ATE 与 RTE 均排第一**；最大差距出现在 **Bicycle unseen**（MoE 保持在 **8.15–8.53 m**，而 ResMLP-128 恶化到 **12.16 m**、ResNet-128 到 **10.37 m**）；bicycle 维度是泛化差距最大的维度，rider 维度最温和（多数模型在 People unseen 上 RTE 甚至下降）。
- 专家行为（Fig. 8）：**8 个专家中 3 个从未被激活**（故只画 E0/E1/E2/E5/E6）；**E5 与 E6 合计约占 85%** 的激活；unpaved 路面上 E6 占比从 **34.28%** 升到 **47.04%**，E1/E2 几乎被完全抑制；山地车上路由更分散，E1+E2 合计 **26.57%**。

## 6 · 能力与失败模式

**能做**：
- 纯惯性、120 s 无 GNSS 外推下的三维位姿估计，机体系速度误差 0.333 m/s 量级。
- 跨骑手、跨车、跨路面**不重训**的泛化；在未见自行车上退化明显小于 ResMLP/ResNet 单主干。
- 在**非铺装路面**上显著优于 NHC（NHC 的零侧滑/零垂向速度假设被微振动与不规则轮地作用破坏）。
- 用 ~1/7、~1/9 的 FLOPs 达到或超过 LLIO/TLIO 主干精度（同数据集内比较）。

**不能做 / 已暴露的失败模式**：
1. **铺装路面上打不过 NHC**（Table I：8.54 vs 9.86 ATE）。当物理假设恰好成立时，数据驱动没有优势。
2. **专家塌缩**：3/8 专家从未激活，实际只有 5 个专家在工作，`N_act` 在 `N≥6` 后饱和为 5。论文在结论里把"更完善的负载均衡"列为未来工作。
3. **稠密激活反而退化**（K=8 时 ATE 10.99 m）：路由稀疏性是精度的必要条件，不是纯粹的算力旋钮。
4. **bicycle 维度的分布迁移最致命**：unseen 自行车上所有模型都退化，MoE 只是退化得少。
5. **无位置/姿态直接量测**：滤波器只吃机体系速度，航向靠速度方向间接约束，长时间外推仍会累积漂移（ATE 9.49 m / 120 s 本身就是一个仍然很大的残差）。
6. **协方差误标定的后果被放大**：`Σ̂` 直接进卡尔曼增益，若 NLL 阶段拟合出的协方差过自信，滤波器会过度信任网络输出。

### 隐含假设 (Hidden Assumptions)

1. **安装刚性且时不变**：数据全部来自"手机支架固定在车把"（Fig. 1）；换到车架、口袋、大腿，输入分布直接越出训练集。论文在批评 CDR 时强调 CDR 需要"trunk/thigh/lower leg 等规定安装位置"，但本文自己的安装条件同样是单一的。
2. **每次评测都有 10 s GNSS 可用做初始化**：这是评测协议的一部分；真实 GNSS 全程失锁场景下滤波器初值与初始协方差如何设定，论文未讨论。
3. **真值质量依赖 GNSS**：监督信号来自 GNSS/INS 位姿图优化，因此训练数据的可信度在 GNSS 良好的时段最高；GNSS 长期劣化的区域反而是最需要学习、却最缺可靠真值的地方。
4. **8 骑手 + 多车型足以覆盖运动多样性**：所有"泛化"结论都在这个内部数据集内测得，论文未报告任何外部数据集（如其他城市的共享单车数据）结果。
5. **机体系三维速度是可学习且物理有意义的量**：网络被当作"把 IMU 序列映射为速度"的黑箱，隐含"速度由当前窗口 IMU + 姿态唯一决定"，未建模载荷、胎压、风等外因。
6. **门控与专家可以逐 epoch 解耦优化**：交替冻结假设两者优化目标近似可分；`L_aux` 的均衡压力与 top-K 的稀疏压力之间存在张力，论文未给超参敏感性（`λ`、`c` 的具体值均未报告）。
7. **batch 内负载均衡 = 全局负载均衡**：容量约束与 `L_aux` 都是 batch 统计量，batch 组成改变会改变路由。

**面试 Tip**：被问"这篇和 TLIO/LLIO 的本质区别"，标准答法是三层——① **域**：首次把 learned IO 用到自行车，用数据替代 CDR 的踏频线性模型与 NHC 的零侧滑约束；② **架构**：稀疏 top-K 同构 MoE 而非单主干，FLOPs 降到 1/7~1/9；③ **最强的论据是反直觉那条**：稠密 `K=N=8` 花 3.8× 算力却最差（ATE 10.99 vs 9.49），说明稀疏路由是**归纳偏置**而非省算力技巧；配套证据是 Fig. 8 的条件依赖激活漂移（unpaved 上 E6 从 34.28%→47.04%）。若被追问弱点，直接承认"铺装路面上 NHC 仍更准"和"3/8 专家死掉"，这两个是论文自己写的。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-11-10)

**Repo 状态核查**：全文（含标题页、致谢、参考文献、图注）**未出现任何 `github.com` 链接，也未给出项目主页或代码发布声明**。因此本节**不做 issue 级验证**——以下 3 条 pitfall 全部由 §6 的失败模式与 §4 的方法约束**推导**，未经社区 issue 证实。

1. **【稀疏路由 → 导出与端侧延迟双失配】**
   - 失败模式来源（§6-2/§6-3）：路由是**逐样本数据依赖**的 top-K 选择，`K=2` 且只有 5 个专家真正工作。
   - 方法约束来源：门控实现为 `softmax → top-K → 重新归一化 → 稀疏 one-hot 门控矩阵`，融合端是"拼接 Top-K 专家特征"。
   - 机制链条：data-dependent gather/scatter + 变长专家集合 → 静态图导出（ONNX/TFLite）需要把 `N` 个专家全部展开成条件分支，甚至退化为稠密计算 → **论文报告的 28.76 M FLOPs 是"理论稀疏算力"，端侧墙钟延迟可能接近稠密配置**（108.46 M，3.8×）。论文只报告 FLOPs 与参数量，**未报告任何设备上的延迟/FPS**，所以这个 gap 无法从论文内部排除。

2. **【容量约束是 batch 依赖的训练期算子 → 实验难复现】**
   - 失败模式来源（§6-7）：`L_aux` 与 `Capacity` 都是 batch 统计量，"batch 内均衡"被当成"全局均衡"。
   - 方法约束来源：`Capacity_i = ⌈c·B/N⌉`，超额样本按权重降序**顺延**给下一个专家（一个带顺序的、不可微的重分配过程）。
   - 机制链条：换 `B` → 换每个专家的容量 → 换顺延的样本集合 → 换专家看到的数据分布 → 换 `N_act` 与最终 ATE。而论文**未报告 `c` 的取值、`λ` 的取值、训练 batch 大小与优化器细节**，想复现 Table IV/V 的 `N_act = 5` 饱和现象，几乎必须靠猜这几个超参。

3. **【速度-only 量测 + 学习协方差 → 过自信即发散】**
   - 失败模式来源（§6-5/§6-6）：量测只有 `h(X)=R̂ᵀv^n=v̂^b`，航向仅靠速度方向间接约束；`Σ̂` 直接进卡尔曼增益。
   - 方法约束来源：`L_NLL = ½ log det Σ̂ + ½‖v−v̂‖²_Σ̂` 且**只在 MSE 阶段收敛之后**才联合训练协方差；回归头输出的是协方差**对角**（两个 3 维向量头，非完整 3×3 参数化）。
   - 机制链条：对角近似丢掉速度分量间的相关性 → 在急弯/侧倾（横向与垂向速度强相关）时 `H P Hᵀ + Σ̂` 被低估 → 增益过大 → 滤波器跟随网络的瞬时误差 → 一旦网络进入训练分布外（未见车型、非车把安装），误差被正反馈放大。这条在 120 s 外推协议下最危险，因为没有任何位置观测可以把它拉回来。
