# 并发抓持与非抓持操作：面向多阶段灵巧任务的实用方法 (Concurrent Prehensile and Nonprehensile Manipulation: A Practical Approach to Multi-Stage Dexterous Tasks)

> **发布时间**：2026-08-03（arXiv:2603.11655v4 [cs.RO]）
> **论文 / 模型名**：**DexMulti**（USC，Hao Jiang / Yue Wu / Yue Wang / Gaurav S. Sukhatme / Daniel Seita）
> **核心定位**：用「物体中心技能库 + retrieve-align-execute」替代端到端策略，在**每个物体仅 3–4 条真机示教**下完成「一只手握住 A 的同时操作 B」的多阶段灵巧任务，成功率比 diffusion policy baseline 高 2–3×。

灵巧手真正区别于夹爪的能力不是"抓得稳"，而是**握着一个物体同时去动另一个物体**（握着钥匙转门把手、扶着盒子开盖）。这类长程、接触密集、多物体的任务在示教昂贵 + 端到端策略数据饥渴的双重挤压下几乎无人做真机。本文的结论很干脆：**不要学整条轨迹，学"物体中心的技能片段"，然后在部署时检索、对齐、回放。**

## X-Ray 开场

它解决的问题：多阶段灵巧操作里，"手-物体精细对齐"这一最脆弱的环节被端到端策略和整条轨迹一起学，导致少样本就崩、换个摆放位置就崩。它提出的做法：把每条示教按**接触信号**切成若干 object-centric skill，存进**以物体质心 + yaw 为原点的规范化坐标系**；部署时按当前点云做 Chamfer 检索、用 EKF 跟踪的 (质心, yaw) 把技能变换到世界系做闭环对齐、对齐收敛后**冻结位姿开环回放**。对 spatial AI 研究者的意义：这是一篇"**显式几何状态估计 + 技能检索**打败"隐式端到端表征"的强证据——消融显示把 yaw 拿掉（只留质心）成功率从 22/34 掉到 6/34，而换成完整 6D 位姿估计器 FoundationPose 也只有 12/34。

## 1 · 核心架构 / 方法总览

### 1.1 系统组件对比

| 模块 | 输入 | 输出 | 训练 / 推理差异 |
|---|---|---|---|
| **感知**（§IV-A） | V 路 RGB-D `{I,D}` + 语言指令 ℓ | 每物体点云 `P_k ⊂ R³`（FPS 降采样到 **512** 点，机器人 base 系） | 无自训练；Grounding DINO [35] 检测 + SAM2 [36] 实例分割跟踪 + 反投影/去噪/聚类。整条流水线约 **20 Hz**，离线在线共用 |
| **技能分段**（§IV-B） | 示教关节序列 + 物体点云 | 每个子任务 `σ_{i,k}` 的起始 keyframe | **仅离线**。手用 FK 建成点云，算手-物体几何邻近的**软接触信号**，取首次持续接触时刻为 keyframe |
| **规范化表示**（Eq.1） | keyframe 处物体点云 + 该段末端位姿/手关节指令 | 规范化技能 `σ^canon`，入技能库 | **离线**建库（PCA 求质心 c 与 canonical yaw）；检索时对观测点云同样处理 |
| **状态估计**（§IV-C） | 实时分割点云 | `(c_t, ψ_t, I^obs_t)` | **仅在线**。匀速动力学 EKF；yaw 由水平投影 PCA 观测，几何各向异性 + 卡尔曼不确定性 → 连续可观测性分数 → **迟滞阈值**得二值 flag |
| **检索**（Eq.2） | 观测点云 + 技能库 | 示教索引 `i*`（整条任务共用一个 i*） | 在线一次。yaw 可观测时 1 次 Chamfer；不可观测时在离散 yaw 假设集 Θ 上取 min |
| **对齐**（Eq.3） | `i*` 的首个 canonical 动作 + 实时 `(c_t,ψ_t)` | 世界系 TCP 目标位姿 | 在线**闭环**。Pyroki [39] 滚动时域运动规划，含避障（用感知障碍物表示）、关节限位、轨迹平滑 |
| **执行** | 对齐收敛时的 `(c_fixed, ψ_fixed)` + 剩余 canonical 轨迹 | 机械臂位姿 + 手关节指令 | 在线**开环**。位姿插值过渡后整段回放；**10 Hz** 下发 |

**关键点：本文没有任何需要训练的神经网络策略。**"学习"全部发生在示教库这一层；Grounding DINO / SAM2 / Pyroki 都是现成组件。这使它与三个 diffusion baseline 的数据需求曲线结构性地不同。

### 1.2 关键机制

⚡ **Eureka Moment：接触密集的灵巧操作不需要 6D 位姿，只需要"任务相关的那部分状态"——桌面上的物体被重力钉死在平面里，姿态自由度只剩一个 yaw；把 yaw 的可观测性显式判出来（不可观测就冻结不更新），比上 FoundationPose 求全 6D 位姿更稳。**

三条支撑：
1. **按接触切技能**：用软接触信号而非人工标注/固定时长切示教，使每个技能片段都能在"手已对好位"的前提下被可靠回放——把最脆弱的接触阶段压缩成短段。
2. **规范化到物体坐标系**：技能存的是物体系下的动作，因此对平移天然不变、对 yaw 在可观测时不变。
3. **对齐闭环、执行开环**：接触发生前用实时状态闭环修正；一旦开始接触就冻结位姿，避免接触期间位姿估计抖动引起的正反馈失稳。

### 1.3 信息流

```
离线（一次性）                          在线（每个 episode）
─────────────────────────              ──────────────────────────────────────
示教 ξ_i (DexCap 遥操作)                ℓ ──► 子任务序列 (s_1..s_K), 物体 (o_1..o_K)
   │                                      │
   ├─ 手 FK 点云 + 软接触信号            2×L515 RGB-D
   │      └─► keyframe 切分 σ_{i,k}       │

          └─► P^canon = R_z(-ψ^canon)(p-c) │
                + 末端位姿/手指令           ├─ EKF ─► (c_t, ψ_t, I^obs)
                     └─► 技能库 {σ^canon} ─┼─► 检索 i* = argmin Σ_k Chamfer(P_k^obs, P_{i,k}^canon)
```

## 2 · 数学核心

📌 **Napkin Formula**：
**`a^world = T(c_t, ψ_t) · a^canon`，其中 `(c_t, ψ_t)` 来自 EKF；`i* = argmin_i min_θ Chamfer(R_z(θ)P^obs, P_i^canon)。**
一句话：**用物体的一小块位姿（质心 + yaw）把"示教过的动作"搬到"现在这个物体"上。**

### 2.1 规范化（Eq.1）

目标：让技能与物体的绝对位置/朝向解耦。

```
P^canon = { R_z(−ψ^canon)(p_i − c) }                    (1)
```

- `c ∈ R³`：keyframe 处物体点云质心
- `ψ^canon`：水平投影点云 PCA 主方向给出的 canonical yaw
- 效果：所有末端位姿与手关节指令同变换，得平移不变、yaw 可观测时旋转不变的技能库

直觉：把物体"扶正、摆到原点"，示教就变成一段与场景无关的相对运动。

### 2.2 检索（Eq.2）

```
i* = argmin_i min_{θ∈Θ} d_Chamfer( R_z(θ) P^obs_centered , P_i^canon )      (2)
```

- `Θ`：离散 yaw 假设集
- `I^obs_t = 1`（yaw 可观测）：`θ` 固定为任务级 yaw `ψ^task_t`，只算 1 次 Chamfer
- `I^obs_t = 0`：在 `Θ` 上最小化，同时恢复 `i*` 与相对对齐 yaw `θ*`
- 多阶段：用**跨所有物体的联合分数**选出**同一个** `i*`（Alg.1 line 4），保证各子任务来自同一条示教、技能配对自洽

直觉：Chamfer 是"点集形状像不像"的弱度量，正好只需要形状相似、不需要精确位姿。

### 2.3 对齐（Eq.3）与执行

```
p^world = c_t + R_z(ψ_t) p^canon ,   R^world = R_z(ψ_t) R^canon        (3)
```

- `ψ_t` 由"检索时 yaw 可观测性 + 实时 yaw 可观测性"共同决定（附录给出完整选择规则）
- 目标是**滚动时域规划**问题：跟踪 `(p^world, R^world)` + 避障 + 关节限位 + 平滑
- **收敛后冻结** `(c_fixed, ψ_fixed)`，剩余轨迹开环回放

### 2.4 yaw 可观测性（本文真正的技术核心）

- 观测：水平投影 PCA 的方向（仅在点云**各向异性足够**时有意义）
- 连续可观测性分数 = f(几何各向异性, EKF 不确定性)
- 二值化：**迟滞阈值**（hysteresis）→ `I^obs_t`
- `I^obs_t = 0` 时：抑制朝向更新，任务级 yaw 保持常数 → 防止圆/无纹理物体诱发伪旋转

直觉：对圆柱杯子，"yaw 是多少"这个问题本身没有答案；强行估会得到一个随机游走的噪声通道，把 Eq.3 的整个世界系目标位姿搅乱。

## 3 · 带数字走一遍

> ⚠️ 本节是**玩具设定**，数字为我为演示 Eq.1–Eq.3 而构造，非论文实验结果。

**设定**：桌面系，物体质心 `c = (0.40, −0.10, 0.02) m`，yaw `ψ = 30°`。检索到的技能在 canonical 系里第一个动作（预抓取 TCP 偏移）是 `p^canon = (0.05, 0.00, 0.10) m`，即"沿着物体局部 x 轴前伸 5 cm、抬高 10 cm"。

**Step 1 — 对齐（Eq.3）**：
```
R_z(30°)·p^canon = (0.05·cos30 − 0·sin30,  0.05·sin30 + 0·cos30,  0.10)
                 = (0.0433, 0.0250, 0.10)
p^world = c + 上述 = (0.4433, −0.0750, 0.1200)
```

**Step 2 — 如果 yaw 被当 0（消融里"Centroid-only"的情形）**：
```
p^world(ψ=0) = (0.4500, −0.1000, 0.1200)
误差 = (−0.0067, +0.0250, 0)  →  |误差| = 0.0259 m ≈ 2.6 cm
```
仅 5 cm 的力臂、30° 的 yaw 错，就已经 2.6 cm 横向偏差。换成**抽屉把手**（力臂 10 cm）：
```
|Δ| = 2·r·sin(Δψ/2) = 2 × 0.10 × sin15° = 0.0518 m ≈ 5.2 cm
```
——这正好解释 §V-B 里那类失败："the hand does not contact the drawer handle at the correct location"。也解释了 Table II 里 Centroid-only 掉到 6/34、8/34。

**Step 3 — 检索代价（Eq.2 的 Θ 分支）**：
yaw **可观测**：1 次 Chamfer/物体 → 2 物体 × N 条示教。
yaw **不可观测**：`|Θ|` 次 / 物体。取 `Θ` = 12 个 30° 分箱、库中 40 条示教、2 个物体：
```
12 × 40 × 2 = 960 次 Chamfer（在 512 点集上）
```
纯 CPU 级别的量级；这正是"可观测时只算 1 次"这一优化的价值所在。

**Step 4 — 状态估计**：EKF 匀速模型下，`c_t` 与 `ψ_t` 每帧更新；当物体被拉出时 `c_t` 沿拉动方向漂移，但一旦进入开环执行，`(c_fixed, ψ_fixed)` 被冻结 —— **模型不再看它**。

**可从方法结构推导的工程特性**（非原文数字）：

- **算力画像与 diffusion policy 相反**：对齐阶段靠感知（20 Hz）+ MPC 吃算力，**回放阶段零神经网络前向**；而 DP/DP3 需要高频策略推理。这意味着 DexMulti 的瓶颈在"接触前那段"，DP 族的瓶颈在"整段"。
- **控制频率 10 Hz 与感知 20 Hz 的 2:1 关系**：对齐闭环的每次决策粒度是 100 ms；对齐收敛的判据与时序未在正文给出，属实现细节（附录称有额外控制频率/速度限位说明）。
- **开环回放 = 零反馈**：`(c_fixed, ψ_fixed)` 冻结后，物体滑移、示教-执行动力学的偏差都无法纠正。这是用"稳定性"换"鲁棒性"的显式取舍。若要做视觉伺服，就必须把 `dChamfer` 或位姿残差接回控制器——本文没有。
- **技能库存储**：每条技能只存点云（512 点）+ 位姿序列 + 手关节序列，无网络权重。真正稀缺的是**示教采集工时**：DexCap 遥操作、13 个物体、每物体 3–4 条、每任务约 40 条（§V-A）。
- **部署约束**：需要多视角标定（base 系表达）；需要 Grounding DINO 的语言提示能命中物体类别；Pyroki 需要感知障碍物表示才能避障。

## 5 · 数据与评测

### 5.1 数据组成（逐字）

- **示教采集**：**DexCap** 遥操作系统 [18]。
- **规模**：每任务每个物体 **3-4** 条示教，**13** 个不同物体，总计 **approximately 40** 条示教/任务。
- **采样效率补充采集**：对选定的 物体-任务 组合额外采集至多 **50** 条示教。
- **所有示教**均使用随机化物体摆放。
- **物体集**（Fig. 4）：左侧为训练物体（用于采集示教），右侧为 **held-out test objects**，训练期间完全未见。
- **摆放随机化范围**：**± 25 cm** 工作区区域。

### 5.2 任务集（3 个，每个 2 个子任务）

| 任务 | 子任务 1 | 子任务 2（并发） |
|---|---|---|
| **Grasp+Pull** | 从桌上抓取物体 | 握持状态下拉开抽屉把手，把物体放进抽屉 |
| **Grasp+Open** | 抓取物体 | 推/开容器盖，把物体放进去 |
| **Grasp+Grasp** | 抓取物体 1 | 不释放物体 1 的前提下抓取物体 2（类似 [30]） |

判定：**两个子任务按序全部完成且无外部干预**才算成功（抓取 + 关节物体操作 + 放置）。

### 5.3 Baseline

| Baseline | 说明 |
|---|---|
| **Image-based DP** [5] | RGB 输入的 diffusion policy |
| **DP3（raw point cloud）** [6] | 原始场景点云条件的 diffusion policy |
| **Object-centric point cloud diffusion** | 最强的对照：DP3 + 逐物体分割点云（思路近 CordViP [4]），每点接触图作为额外通道，PointNet [41] 编码 + 本体状态融合，与其它 baseline 共享 diffusion backbone |

### 5.4 主结果（Table I，LEAP Hand，原文 `successes / total trials`）

| Method | Train G+Pull | Train G+Open | Train G+Grasp | Test G+Pull | Test G+Open | Test G+Grasp |
|---|---|---|---|---|---|---|
| Image-based DP | **3 / 34** | **3 / 34** | **0 / 27** | **3 / 31** | **2 / 31** | **0 / 15** |
| DP3 (raw point cloud) | **3 / 34** | **2 / 34** | **0 / 27** | **3 / 31** | **1 / 31** | **0 / 15** |
| Object-centric DP3 | **7 / 34** | **12 / 34** | **8 / 27** | **8 / 31** | **12 / 31** | **7 / 15** |
| **Ours (retrieval-based)** | **22 / 34** | **23 / 34** | **12 / 27** | **24 / 31** | **22 / 31** | **3 / 15** |

⚠️ 值得在面试里主动点出的**反例**：Ours 在 **Test G+Grasp = 3 / 15**，低于 object-centric DP3 的 7 / 15。论文正文没有解释这一反转，只笼统说"consistently outperforms"。

### 5.5 采样效率（§V-C，Fig. 6，任务 = Grasp+Open）

- 数量维度：示教条数 ∈ **{5, 10, 20, 50}**，固定单个物体。**Ours 在 5 条时即成功、并 across all data budgets 保持 100%**；object-centric DP3 **在 5 与 10 条时失败**，**20–50 条时仅达 30-40%**。
- 多样性维度：训练物体数 ∈ **{4, 7, 11}**，总计 **44 条**示教。性能随多样性先升后**plateau**；本方法在各多样性档位均优于 baseline。
- 注意：100% / 30-40% 这些是正文叙述里的数值，其**对应的 trial 数与分母未在正文给出**。

| Centroid-only（去掉 yaw 规范化） | **6 / 34** | **8 / 34** |
| **Ours（uncertainty-aware）** | **22 / 34** | **23 / 34** |

三条可复述结论：(i) **完整 6D 位姿不是必需的**，小/对称/弱纹理物体上 FoundationPose 反而更差；(ii) **时序滤波 + 不确定性建模是必需的**（Raw PCA → Ours 翻倍）；(iii) **yaw 本身是必需的**（Centroid-only 6/34，长条物体如香蕉、抽屉把手系统性错位）。

### 5.7 具身泛化（Table III，`successes / total trials`）

| Method | Allegro G+Pull | Allegro G+Open | LEAP G+Pull | LEAP G+Open |
|---|---|---|---|---|
| Object-centric DP3 | **17 / 34** | **2 / 34** | **7 / 34** | **12 / 34** |
| **Ours** | **30 / 34** | **20 / 34** | **22 / 34** | **23 / 34** |

⚠️ 必读细节："For each embodiment, we collect the same amount of demonstration data"。**这是"同一套 pipeline 换手重采集示教"，不是零样本跨具身迁移**。

### 5.8 与 no-demo 方法的对比

§V-F **未给任何定量结果**，仅论证 RL [14,17] 与抓取合成 [3,9,11] 依赖手工设计的 reward/energy 与良好初始化，在多阶段任务上愈发困难，并把示例放在项目网站。

## 6 · 能力与失败模式

### 能做（具体）

- **并发抓持 + 非抓持**：握持物体 A 的同时拉抽屉 / 开盖 / 抓取 B（Fig. 1）。这是相对 parallel-jaw 与"only-grasping"工作的核心增量。
- **少样本**：每物体 3–4 条示教即训练；采样效率曲线上 5 条即达 100%（Grasp+Open 单物体设定）。
- **空间泛化**：随机摆放 **± 25 cm**；Table I 的 test 列在 held-out 物体上仍维持 24/31、22/31。
- **跨具身**：Allegro（G+Pull 30/34）与 LEAP（22/34、23/34）均超越最强 baseline，且观察到 Allegro 在小/薄物体上更强（硬件上限影响任务上限）。
- **失败可预测**：无好匹配时"抓不住/对不准"的受控失败，而非 diffusion 那样对分布外大/高物体**撞上去触发急停**。

### 不能做 / 会失败（具体）

| 失败模式 | 论文中的证据 | 机理 |
|---|---|---|
| **测试集上顺序抓两个新物体** | Test G+Grasp = **3 / 15**（低于 object-centric DP3 的 7 / 15） | 第二个物体无示教几何近似时，检索无匹配；且第一抓已占用手指，容错余量为零 |
| **接触密集的力平衡** | Fig. 5 左下：香蕉第一阶段抓取失败 | 开环回放无法调力；`(c_fixed, ψ_fixed)` 冻结后无反馈 |
| **细长/关节物体的接触点定位** | Fig. 5 右下：手没在正确位置接触抽屉把手 | yaw 误差经力臂放大（§3 算出 ≈5.2 cm） |
| **薄物体** | 结论节明说：笨重手指难以操作 credit cards / thin fabric | 硬件限制，非算法 |
| **极端构型 / 训练分布外几何** | 结论节："performance degrading under extreme configurations" | 检索式方法的固有边界——没有匹配就没有行为 |
| **单视角 / 无标定 / 无 RGB-D** | 结论节："dependent on ... multi-view RGB-D sensing" | 感知前提 |

### 隐含假设 (Hidden Assumptions)

1. **平面桌面 + 重力约束** → 物体状态可降维为 `(c ∈ R³, ψ ∈ (−π,π])`。任何倾斜、堆叠、被抓离桌面的物体，这 4 维表示立即失效（§IV-C "Design Rationale" 明写此假设）。
2. **物体是刚体、且关节物体（抽屉/盖子）的几何与动力学在示教与测试间一致**。技能是开环回放的位姿序列，抽屉阻力变化不在模型内。
3. **子任务分解是给定的，不是学出来的**：`ℓ` 直接决定物体类别与顺序（Alg.1 line 1）。语言理解失败 → 整条流水线失败，且无重规划/回退分支。
4. **"存在一个 Chamfer 近邻的示教"**：检索式方法的核心前提。Test G+Grasp = 3/15 就是这条假设被打破的直接读数。
5. **yaw 可观测性可由几何各向异性 + EKF 不确定性可靠判定**。对称/近圆形物体被判不可观测后，世界系目标位姿的旋转分量被固定为任务级常数——若真实物体其实转过了一个角度，对齐将系统性错位。
6. **开环执行期间物体位姿不变（或变化不影响任务成功）**。`(c_fixed, ψ_fixed)` 冻结意味着滑移/外扰不可纠正；Fig. 5 上排的"moderate external perturbations"鲁棒性来自抓持本身的柔顺性与任务容差，不来自闭环。
7. **感知的点云足以支撑检索**：分割无身份交换、无严重遮挡。已握持的物体会被手大幅遮挡——本文未讨论该情形下的点云质量（此条为**由 §IV-A 流水线推导**，论文未明说，标 `UNVERIFIED`）。
8. **多视角相机已标定、外参固定，物体点云在 base 系表达**（§IV-A 明写）。
9. **技能库只需"每物体 3–4 条"就够**，隐含假设示教者的放置/朝向覆盖了测试分布的主要模态。

**与最接近工作的差异一句话**：相对 [30] 的 sequential multi-object grasping，本文要求**在整个第二阶段维持对第一物体的握持**（不只是"抓完再抓"）；相对 [31]，本文显式混合了 prehensile 与 nonprehensile；相对 object-centric DP3，本文用**检索-对齐-回放**替掉策略网络，从而在 5 条示教的量级上工作。

🎤 **面试 Tip**：如果被问"这不就是把示教轨迹回放一遍吗？创新点在哪？"，标准答法是三段——(1) **不是回放**：回放需要精确位姿，本文只估 4 维 `(c, ψ)` 并**显式建模 yaw 可观测性**，不可观测时冻结而非硬估；(2) **技能是物体系规范化的**，Eq.1 让同一段示教对平移不变、对 yaw 不变，检索在 canonical 空间用 Chamfer 完成，Eq.2 的 Θ 分支让 yaw 不可观测时也能对齐；(3) **闭环只用在接触前**（Eq.3 + Pyroki），接触开始就冻结——这个"闭环对齐 / 开环执行"的切分是关键工程决策，消融里 Centroid-only 6/34 和 FoundationPose 12/34 就是它存在的证据。

## 8 · GitHub-validated pitfalls (atlas 联动, 2026-11-10)

**Repo 状态核查（诚实声明）**：论文全文**未给出任何 `github.com` 链接**，也未出现 issue 编号、commit hash 或 release tag。正文/摘要仅提到 "More videos and code are available on our project website **https://dexmulti.github.io/**"，这是一个 `github.io` **项目主页**，不是仓库，且全文没有可点击的代码仓超链接。因此：**以下 pitfall 全部由 §6 失败模式 + §IV 方法约束推导，未经任何 issue 流验证。**

| # | Pitfall（机制性推导） | 由哪条失败模式 / 方法约束推出 | 落地时的典型症状 |
|---|---|---|---|
| 1 | **PCA canonical yaw 的符号与主轴交换歧义**：Eq.1 的 `ψ^canon` 来自水平投影 PCA。特征向量的**正负号不定**，且近似对称物体上**两个主轴的特征值接近 → 主轴会跳变**，导致 `ψ^canon` 在 ±90° 间翻转，规范化整个错掉 | 约束：Eq.1 依赖 PCA 单一定义；失败模式：§6 "Centroid-only 6/34" 与 Fig.5 右下"手没在正确位置接触把手"同源（yaw 错 → 力臂放大）。论文为 yaw 可观测性专门引入**迟滞阈值**，说明这个量本身就抖 | 重采集后同一物体成功率骤降；不同次运行间 yaw 相差 ~90°/180°；抽屉把手永远对不上 |
| 2 | **两个物体的分割身份必须全程稳定**：Alg.1 line 2–3 一次性检测并跟踪 `(o_1..o_K)`，line 4 用**跨物体联合 Chamfer 分数**选**同一个** `i*`。SAM2 跟踪一旦在两手/物体交叉时交换 ID，联合分数的最小值就落到一条"物体配对错位"的示教上，且**无法在后续阶段自愈**（i* 全程共用） | 约束：Alg.1 line 4 的 joint score 设计；失败模式：Test G+Grasp = 3/15（第二物体无匹配/错配）。语义提示依赖 Grounding DINO 的文本 prompt | 第一段正常、第二段完全错位；换 prompt 措辞后行为改变；日志里两个物体的点云数量在若干帧后互换 |
| 3 | **开环执行段对外扰/滑移完全无响应，且对齐收敛判据未公开**：§IV-D 明确 `(c_fixed, ψ_fixed)` 在 alignment 结束时冻结。因此任何"抓起来之后物体在指间转了 10°"的情形，后续子任务用的仍是错的物体系；同时正文未给出 alignment 收敛阈值与最大迭代数，复现时该超参只能自行拍定 | 约束：§IV-D "frozen at the end of alignment ... avoids instability from continuous pose re-estimation"；失败模式：Fig.5 左下香蕉力平衡失败（回放不能调力） | 轻/软物体被压扁或滑落；把收敛阈值调紧 → 对齐阶段反复抖动超时，调松 → 接触点偏几厘米 |
| 4 | **`10 Hz` 指令 / `20 Hz` 感知 / Pyroki 求解预算三者耦合**：控制回路每 100 ms 一个 tick，而每个 tick 内要做 EKF 更新 + 目标变换 + 滚动时域规划（含用感知障碍物点云做避障）。感知端延迟或障碍物点云变大都会吃掉规划预算 | 约束：§V-A 的 10 Hz 指令、§IV-A 的 20 Hz 流水线、§IV-D 的 Pyroki + 感知障碍物表示；失败模式：§6 "受控失败"依赖于对齐真的收敛，若来不及收敛就进入回放则等价于开环盲走 | 换了相机/加了物体后对齐"永远收敛不了"；规划器偶尔超时导致指令卡顿；本文未报告单次求解耗时，需自行 profile |

> ⚠️ 若后续拿到官方仓库，**第一件要验证的是 pitfall #1**：检查 `ψ^canon` 是否有符号消歧与主轴一致性处理（例如用带符号的包围盒 / 最长轴定向），而不是裸 PCA eigenvector。
